### 2.6 存储层需求（3.0 新增）

上表暴露 5 个问题。**它们不是 UI 缺陷，是数据层缺陷**，会直接导致「刷新后丢状态」「用久了变慢」类线上问题，因此在此立需求。

| # | 问题 | 3.0 需求 |
|---:|---|---|
| **E1** | `clingo-onboard-profile-v1` **只写不读**：`onboardingStorage.ts` 没有 `readProfile()`，`hskLevel` / `nickname` / `dob` / `gender` / `avatar` 写进去后无人消费 | 提供 `readProfile()`，并让 `/profile`、`/profile/edit`、首页问候语、HSK 默认等级**全部从它取值**。详见 `01` 与 `05` |
| **E2** | **键命名有 4 套前缀（`clingo-` / `c-lingo-` / `apps-` / 无前缀）、3 种分隔符（`-` / `.` / `_`）、版本后缀时有时无** | 统一为 `clingo.<域>.<名>.v<N>`；提供一次性迁移函数读旧键写新键后删旧键；新增键必须带版本后缀 |

| **E4** | `clingo-user-token` 存在，但一期**无账号体系**（`AGENTS.md`：不做学员注册登录） | 若确认一期不用，**删除该键与 `/api/auth/*` 调用**，避免留下看似有鉴权的假象；若保留，须说明用途 `[待确认]` |
| **E5** | 无统一读写封装：多处直接 `localStorage.getItem` + 各自 `try/catch`，`syntax-snap-points` 甚至不走 JSON | 提供统一 `storage` 模块（命名空间、JSON 序列化、schema 校验、失败兜底、配额超限处理）。**`QuotaExceededError` 当前无任何处理** |

### GWT · 存储层

- **Given** 设备已完成开机向导且个人资料已填写，**When** 用户进入 `/profile`，**Then** 页面展示的昵称、生日、性别、头像与 `clingo-onboard-profile-v1` 中的值一致。
- **Given** 存储中存在旧版键 `camera_translation_history`，**When** 应用升级到 3.0 后首次启动，**Then** 数据被迁移到新命名空间键，旧键被删除，且历史记录条数不变。
- **Given** 用户已作答 5000 道题，**When** 打开 `/mistakes-review`，**Then** 首屏渲染在 2 秒内完成，且 `localStorage` 中学习记录相关键的总数不超过 10 个。
- **Given** `localStorage` 已达浏览器配额上限，**When** 用户完成一次作答触发写入，**Then** 应用不崩溃、不白屏，提示「存储空间不足，请清理学习记录」，并提供跳转清理入口。
- **Given** 同一设备打开了两个标签页、分别在 `paperId` 为 P1 和 P2 的试卷上作答，**When** 关闭 P1 的标签页，**Then** 仅 `clingo-hsk-active-attempt:P1` 被清除，P2 的作答指针与 `hsk-attempt-<attemptId>` 缓存完好。

## 三、后端接口清单

C-LingoAIOS 客户端**只调两组 HTTP 接口**，分属两个不同后端。这是实测结果，不是设计意图——两组接口的归属与存废需要业务方裁决（见第五节）。

### 3.1 考试 API（Java 平板端，端口 `8082`）

- 基址环境变量：`VITE_CLINGO_EXAM_API_BASE_URL`，代码 fallback `http://localhost:8082`（`src/services/hskExamService.ts`）
- 请求头：**`X-Clingo-Device-Id`（必带）**，值为 `clingo-hsk-device-id` 中的匿名 UUID
- 归属：外包交付，**3.0 冻结，不改契约**

| 方法 | 路径 | 用途 | 关键返回 |
|---|---|---|---|
| GET | `/api/papers{query}` | 试卷列表 | 可用试卷。3.0 只应返回 HSK1、HSK2 |
| POST | `/api/papers/{paperId}/attempts` | **开始考试** | `attemptId`、`startedAt`、`expiresAt`、**公开题目快照**、听力规则 |
| GET | `/api/attempts/{attemptId}` | 恢复作答 | 作答状态与快照 |
| POST | `/api/attempts/{attemptId}/submit` | 提交判卷 | 判卷结果 |
| GET | `/api/attempts/{attemptId}/result/detail` | 成绩详情 | 逐题结果 |

**契约约束（不得违反）**

1. 同一 `deviceId + paperId` 同时只能有一个 `in_progress` 作答。
2. 判卷只用**作答开始时冻结的**计分模式、总分和答案快照，**不读当前题库默认分值**。
3. 不从前端题型代码推导答案，答案只来自后端快照。
4. delivery 题量要**递归展开复合题**（`L02_group` / `R03_group` 内嵌 `questions`，每组 5 小题）并排除 `isExample` 才能对上。60 题的卷子 delivery 只返回 28 条**是正常的**。
5. 官方模板（`equal_ratio`）下每题 `score` 均为 0、`moduleScores` 内得分为 null，**这是设计如此，不是丢数据**。
6. 不为绕过报错而修改接口契约、数据库结构或一期业务规则。

### 3.2 旧 Node 后端接口（`src/services/apiClient.ts`）

- 基址环境变量：`VITE_API_BASE_URL`
- 请求头：`clingo-user-token` 注入

| 方法 | 路径 | 现状判读 |
|---|---|---|
| POST | `/api/auth/login` | **一期无账号体系**，与 `AGENTS.md`「不做学员注册登录」冲突。见 E4 |
| POST | `/api/auth/register` | 同上 |
| POST | `/api/feedback` | 反馈上报。`feedbackTypes.ts` 含 `parental_controls` 等分类 |
| GET | `/api/products/{code}/config` | 产品配置下发 |

> **重要事实**：`api.clingoaios.com` 指向的是**旧 Node 后端**（`c-lingo-cms-backend`），**没有任何 HSK 接口**。因此这一组接口和 3.2 表的能力，与考试 API 不在同一后端、不共享身份体系。

### 3.4 不由客户端调用的接口

管理端 API（端口 `8081`）由 `NSK-BackEnd` 管理台调用，**C-LingoAIOS 不碰**。记录一条排查经验以免误判：

> `GET /admin/papers`、`GET /admin/exams` **不支持 GET**，会返回 500 `INTERNAL_SERVER_ERROR`。列表必须用 `/admin/papers/page`、`/admin/exams/page`、`/admin/questions/page`、`/admin/question-types/page`。**这类 500 不是数据库问题。**

## 四、环境与端口

### 4.1 客户端环境变量

| 变量 | 作用 | 默认 / 注意 |
|---|---|---|
| `VITE_SCREEN_SIZE` | 决定 `figmaPx()` 缩放基准 | 形如 `2000x1200`。**未传时回落 `2000x1200`**（`APP_SCREEN_SIZE` 的默认值），与 `MainLayout` / 底栏 / AI 练习模式页的 fallback 一致——**两边必须同一套字符串**。注意 `figmaScale` 对**未声明**的字符串才按 `1024/1920` 兜底，这与「未传」是两种不同情形，容易混（见 4.3 更正说明） |

### 4.3 多分辨率调试脚本

| 命令 | 实际生效的 `VITE_SCREEN_SIZE` | 端口 |
|---|---|---:|
| `npm run dev` | **`2000x1200`（回落值，不是 1024×768）** | 3001 |
| `npm run dev:960` | `960x540` | 3002 |
| `npm run dev:1920` | `1920x1125` | 3003 |
| `npm run dev:1920-1080` | `1920x1080` | **3002（与 `dev:960` 冲突）** |
| `npm run dev:2000` | `2000x1200` | 3004 |
| `npm run dev:all` | 并行三档（`dev` / `dev:960` / `dev:1920`） | — |

> **本表已按实测更正（`06` 评审发现，`01` 第十三章同步）。** `package.json` 里 `"dev": "vite"` **不设 `VITE_SCREEN_SIZE`**，而 `figmaScale.ts` 写的是 `APP_SCREEN_SIZE = import.meta.env.VITE_SCREEN_SIZE || '2000x1200'`，源码注释也明确「**未设 `VITE_SCREEN_SIZE` 时不要回落到 1024**」。所以 `npm run dev` 跑的是 **2000×1200**（scale ≈ 1.042），不是 1024×768。
>
> **`AGENTS.md`「多分辨率调试」小节同样写错**（记为 `npm run dev # 1024×768`），需一并更正。这条错误的实际危害是：开发以为自己在最小分辨率下自测，其实在最大分辨率下——**1024 档从来没被日常覆盖过**。
>
> 另注 `figmaScale` 只有三个显式分支（`960x540`、`2000x1200`、`1920x1125`），**缺 `1920x1080` 与 `1920x1200`**，后者恰是设计稿自身尺寸、本应为 1.0。见 `01` 第十三章 D8。
>
> 仓库里几个旧 shell 脚本（`open-all-resolutions.sh`、`start-and-open-all.sh`）注释说各分辨率都用 3001，**已与 `package.json` 不一致，按 `package.json` 为准**。

### 4.5 本机环境已知坑（排查时先看这里）

| 现象 | 根因 |
|---|---|
| 数据库连不上，`Communications link failure` / `EOFException` | 代理软件（小火箭）TUN + fake-ip 模式劫持了 MySQL 的 TCP 连接。查 `route -n get default` 是否走 `utun`、`nslookup` 是否返回 `198.18.x.x` |
| 自有域名 `*.clingoaios.com` 全部连不上、TLS 握手失败 | **同一个代理劫持自有域名**。在这台机器上验证自有域名会**误判成「线上服务挂了」**。改用 `*.vercel.app` 验证，或给域名加直连规则 |
| 端口明明在监听却被判成空闲 | Agent 沙箱拦截裸 TCP，`/dev/tcp` 探测不可靠。查端口用 `lsof -nP -iTCP -sTCP:LISTEN`，查服务用 `curl` |
| `/admin/health`、`/api/health` 通了但库没连上 | 这两个**不查数据库**。验证库是否真通要用业务接口 `curl -s -H "X-Clingo-Device-Id: local-dev-test" http://127.0.0.1:8082/api/papers`，`"data"` 里有内容才算通 |
| `198.18.x.x` 被当成局域网 IP | 那是小火箭 fake-ip 的虚拟接口，不是局域网地址 |
| Java 命令找不到 | Homebrew 装在 `/opt/homebrew/opt/openjdk@17`，未软链到系统路径，需先 `export PATH`/`JAVA_HOME` |
| 后台服务被回收 | Cursor/Agent 后台终端结束时回收子进程，`nohup` 也挡不住。需常驻的服务用挂住主进程的脚本；macOS 的 `sleep` 不支持 `infinity`，用 `while true; do sleep 3600; done` |

| **Q34** | **C-LingoAIOS 与已有 `com.nsk.launcher` 谁是 Home？** `PRODUCT_APPS` 里同时有 `com.nsk.launcher`（NSK Launcher 2.4.0）和 `com.nsk.parental`（Parental Service）两个独立 APK 包。三种可能：① C-LingoAIOS 自己做 launcher；② NSK Launcher 是 Home、C-LingoAIOS 只是其中一个 App；③ **NSK Launcher 是原生壳、C-LingoAIOS 的 H5 跑在它的 WebView 里**（`05` 认为③最符合现有架构）。若③成立，则 Q20 的全部桥接口是**向 NSK Launcher 提的需求**，归属方不是「我们的安卓开发」 | 需先向硬件/产线方确认现有 NSK Launcher 的角色，再定 C-LingoAIOS 的定位 | **阻塞开工 + 不可逆**（见下方说明） |

> **Q34 为什么标「事实不可逆」**（措辞已按第七节评审纠正 1 修订）：家长控制要真正生效必须拿 **Device Owner** 权限——没有它，屏幕时间只是一条建议，孩子可以退出去玩别的、清除应用数据、改系统时间。Device Owner 只能在设备**未 provision 且无账号**的状态下设置。
>
> **但「出厂后永远无法补设」是错的**：抹机后设备回到未 provision 态，可用产线 ADB / NFC / QR 补设（`05` 9.5.3 自己写的「恢复出厂 + 重新配置」售后路径就是这个）。真实约束是——**不能不抹数据地静默补设**。对已售出设备而言，唯一补救手段是抹掉用户全部数据，商业上几乎等于做不到，所以性质上可逆、事实上不可逆。它依然必须在产线定型前拍板。
>
> **另有一条比 DO 更该先问的路径（新增 Q74）**：DO **拿不到** `signature|privileged` 权限，因此系统级夜览真实色温这类需要 `WRITE_SECURE_SETTINGS` 的能力**在 DO 身份下同样做不到**（`05` 2.6.2 写的「Path A 原生层默认可用」不成立）。反过来，若我们掌握 ROM，把壳做成**平台签名的 priv-app**，能力比 DO 更强**且可随 OTA 补装**。**Q34 与 Q74 必须在同一次产线会上一并问**——若 Q74 答案是「能」，Q34 的紧迫性会显著下降。
>
> 连带后果：若最终选了「不拿 Device Owner、也拿不到平台签名」的路线，`00-总纲` 第一节「开机即接管整台设备的学习操作系统外壳」这句定位**必须下调**，隐私政策里关于家长管控能力的表述也要跟着改。定位不是文案问题，写了做不到就是虚假宣传。

| 5 | **Q29** | HSK 冻结要不要为埋点开例外 | 埋点排在 S1，第一个 sprint 就撞上 |

### 7.2 对 PRD 的事实性纠正（评审推翻的判断）

以下五条是 PRD 里**写错了的事实**，不是意见分歧。已在正文中修订。

#### 纠正 1 · Device Owner「出厂后无法补设」写得过硬（影响 Q34、R10）

| 项 | PRD 原文 | 评审纠正 |
|---|---|---|
| 事实 | 「Device Owner 只能在设备无账号的全新状态下设置，**出厂后无法补设**」「家长控制这辈子能不能做」 | **抹机后设备回到未 provision 态，可用产线 ADB / NFC / QR 补设。** 真实约束是「**不能不抹数据地静默补设**」 |
| 内部矛盾 | `05` 9.5.3 自己写了「恢复出厂 + 重新配置」的售后路径 | 与 `07` Q34 的「这辈子做不了」互相矛盾，**PRD 内部就不自洽** |

**结论修订**：Q34 仍是最高优先级，但**理由要改**。它不是「错过就永远做不了」，而是「错过后唯一的补救手段是抹掉用户全部数据」——对已售出设备而言这在商业上几乎等于做不到，但性质上是可逆的。R10 的「不可逆」措辞应改为「**事实不可逆**（补救需抹机，已售设备无法承受）」。

#### 纠正 2 · 把「系统应用」与「Device Owner」当成同一档权限，是事实性错误（新增 Q74）

- DO **拿不到** `signature|privileged` 权限。`05` 2.6.2 写的「Path A 原生层默认可用」不成立——系统级夜览真实色温需要 `WRITE_SECURE_SETTINGS`，**DO 身份下同样做不到**。
- 反过来：**若我们掌握 ROM，把壳做成平台签名的 priv-app，能力比 DO 更强，且可随 OTA 补装。** 这条路径比 DO 更该先问硬件方，**PRD 完全没提**。
- 已登记为 **Q74**，并在优先级上与 Q34 并列（同一次产线会上一并问）。

#### 纠正 3 · 向导 WiFi 步的桥能力表在安卓上做不到（影响 `01` 第四章）

`01` 4.2 列了「开启 / 关闭 WLAN」「连接指定网络（含密码）」「扫描可用网络」四项桥能力。安卓事实：

| 能力 | 安卓现实 |
|---|---|
| `setWifiEnabled` | **Android 10+ 起对三方应用无效** |
| `addNetwork` | **已移除** |
| `WifiNetworkSuggestion` / `Specifier` | 给不了「把这个 SSID 设为默认网络」 |
| 拿扫描结果 | 需 `ACCESS_FINE_LOCATION`，而 `05` 已决定**不申请**该权限 |

**修订方向**：Step 1 改为跳 `Settings.Panel.ACTION_WIFI` + 只显示已连接 / 未连接；或把该能力整体划入 DO / 系统应用档（取决于 Q34 / Q74）。已在 `01` 第四章修订。

#### 纠正 4 · 两条自动化断言在技术上必然失败（影响 `06`）

| 条目 | 问题 |
|---|---|
| `GWT-I18N-03` | Then 要求「不存在生效的 `margin-left/right`」，工具是**运行时** `getComputedStyle` 扫描。但 `getComputedStyle` **会把 `margin-inline-start` 解析回物理属性**——代码写对了也一样命中，断言必然为假 |
| `GWT-PERF-04` | Given 是「书写一个 12 画的汉字」，而 `07` 5.4 实测汉字书写 Canvas 源码是 `// TODO`，**用户根本写不了字**，前置造不出来 |

**修订**：`GWT-I18N-03` 改为**源码 / AST 层扫描并入 lint**，运行时只留溢出与镜像检测。`GWT-PERF-04` 降为 S6 功能出口条件，Canvas 落地后再进回归。

#### 纠正 5 · 三处技术方案在安卓 WebView 上不可行

| 条目 | 问题 | 修订 |
|---|---|---|
| `06` NFR-OFF-04 离线外壳 | **Service Worker 在 `file://` 下不可用**。若用 `file:///android_asset` 加载 H5，方案直接落空 | 必须用 `WebViewAssetLoader` 以 `https://appassets.androidplatform.net` 虚拟域加载；且 SW 接管后请求不再经 `shouldInterceptRequest`，预缓存要在首启注入 |
| `05` 10.1 桥协议 | `addJavascriptInterface` 只能传原始类型与字符串、**同步阻塞主线程**，且对页内任意 origin 可见，与「只暴露白名单」目标相悖 | 改用 `WebViewCompat.addWebMessageListener` 绑定 origin + `callbackId` 异步协议。注意 Binder 单次事务约 1 MB 上限 |
| `05` 4.4.2 家长控制存储 | `EncryptedSharedPreferences` 在应用私有目录，系统「清除数据」会一并删除，`GWT-E-28`「清数据仍锁定」**在无 DO 时不成立** | PIN、错误计数、配额落到 `com.nsk.parental` 这个独立 APK（同签名 + 权限保护的 ContentProvider）。**不需要 DO，且可后补** |

#### 纠正 6 · 应用没有 404 页，未知 URL 渲染「空白壳层」（跟进核实时发现）

这条不是评审给的，是在处理评审行动项时实测发现的，但性质与前五条相同：**PRD 把一个不存在的东西当成了存在的。**

| 项 | 内容 |
|---|---|
| PRD 原文 | `02` 11.3 写「**确认**全局 404 页已就绪（域 A），未知 `/library/hub/xxx` 落到 404 而非白屏」 |
| 实测 | `App.tsx` 里**唯一**的 `path="*"`（L141）是 `MainLayout` 的**包装层**；内层 `<Routes>` 从 L145 到 L213 **没有任何 catch-all**。所以未知路径渲染的是「顶栏 + 底栏 + 空白主内容区」 |
| 为什么比白屏更糟 | 用户看到完整的壳层导航，会以为页面还在加载，不会意识到 URL 错了 |
| 影响面 | **全域**。今天任何拼错的 URL、任何失效的站内链接都是这个表现 |
| 与路由删除的顺序关系 | 这条**必须早于** `/library/hub/:hubId` 的删除。否则未知 hubId 会从「显示 `Content placeholder.`」退化成「空白壳层」，是**净退步** |

已在 `00` 第五节登记为 P0 缺陷并写入 S1 出口条件（含 404 命中埋点、与向导拦截的关系）。

### 7.5 两项容量结论

#### 测试回归成本：一轮 32 人日，发版前 48 人日——**不现实**

推导（路由按 `00` 矩阵：P0 约 19、P1 约 25、P2 约 24）：

| 项 | 推导 | 人日 |
|---|---|---:|
| 破版走查（英文） | 19×4 + 25×2 + 24×1 = 199 单元 × 12 分钟 | 5 |
| 阿语（不适用采样、必须全量） | 68×4 = 272 单元 × 12 项检查表 × 20 分钟 | 11 |
| 功能 GWT 执行 | `01` 81 + `06` 83 + `03` 必跑 30 ≈ 194 条 × 25 分钟（`02`/`04`/`05` **未计**） | 10 |
| 真机专项 | 性能取 5 次中位数、TalkBack、30 分钟内存、迁移演练、抓包 | 4 |
| 覆盖层与弹窗 / 空态 / 错误态 | — | 2 |
| **一轮全量** | | **32** |
| **发版前 1.5 轮** | | **48** |

团队只有 1 名测试，双周 sprint = 10 人日，**等于要吃掉近 5 个 sprint 的测试工时**。

削减方案（目标一轮 12–14 人日）：

1. **阿语改按布局模板采样**——68 条路由复用的模板不超过 12 种。阿语只在主目标档 2000×1200 全量走 68 条（2.8 人日），另三档只走 12 个模板代表页（1.5 人日）。11 → 4.3
2. **分辨率破版交给快照 + 结构断言**（`scrollHeight`、越界、田字格、热区），人只看 diff。5 → 1.5
3. **P2 的 24 条先按 R8 收敛成同一个「锁定 / 敬请期待」组件**，回归退化为「1 组件 × 4 档 + 24 张截图」。≈ 0.5
4. **`03` 必跑集自动化**（pointer 分键、代次令牌、题量递归、URL 锁定四类），把 10 轮重复执行摊成一次性投入；人工只留听力时序与破版

**阿语缺陷分级**：采信 `06` NFR-I18N-06 的 P0–P3 草案，加一条判定规则——**同一路由内同类缺陷合并计 1 条，壳层缺陷记在壳层不记 66 遍**，否则「0 个 P1」会因计数方式而永远不可达。

| 保 | 砍 |
|---|---|
| S1–S6：埋点、i18n 基座、向导、首页与 Profile、教材主线到阅读器、汉字书写与拼音表 | 快乐中文域、60% 文化解锁、卡片小游戏、双商店、Android 壳、应用更新、商务中文、HSK Standard |
| 家长控制 Web 层（**业务要求从 P1 提到 P0、前置到 S3**——它是家长掏钱的决策点） | Camera 只留拍照翻译一个入口 |
| AI 场景对话（Q5 未定则先不做评分） | 阿语从「全域 RTL 交付」降为「基座 + P0 路由」，全量走查挪 3.1 |

业务对 `01`/`05` 五条产品改动提议的表态：移除 `gender` **接受**；开发后门移出生产 **接受**（「顶栏单击清空全部设置，属上线即炸级缺陷」）；WiFi 可跳过 **有条件接受**（须同时把激活改成待激活 + 联网补校验，且桥不可用时禁止 mock 假连接）；下线重复路由 **接受**（做重定向而非直接删）；商务中文与 HSK Standard 延后 **有条件接受**（先确认 HSK Standard 有没有已承诺的学校客户，有则保留一张静态 School Edition 说明页）。

### 7.6 法务专项结论：**高风险**

风险判定原文：把需要家长同意的 Children's Privacy Policy 与 TOS 合成**一个由未成年人自己勾的勾选框**，同时采集邮箱、生日、性别，却无年龄分流、无同意留痕、无拒绝路径——**在 COPPA、GDPR 第 8 条、AADC 下是可直接认定的违规形态，没有解释空间。**

#### 3.0 内最低必须做到（按优先级）

1. 三份文档拆为独立同意项，**儿童隐私政策不得由孩子勾选**
2. 生日采集**前移到分流之前**，低于门槛不进主流程
3. 同意留痕：时间戳、文档版本、**语言版本**、设备 SN；本地存 + 激活接口上报；改版重新征得
4. 移除 `gender`
5. AADC 默认高隐私：埋点最小集，**关闭一切画像与行为定向**
6. 补拒绝 TOS 的分支页
7. 保留期按最严法域：埋点 ≤ 12 个月，**语音不留存或 ≤ 30 天**
8. 无 Device Owner 时，UI 与隐私政策**都不得宣称能管住整台设备**（否则是虚假宣传）

#### 各法域门槛年龄

| 法域 | 门槛 |
|---|---|
| 美国 COPPA | 13 |
| GDPR 第 8 条 | 默认 16，成员国可下调至 13（德 / 爱 16、法 15、西 14、瑞典 13） |
| 英国 | 13；**AADC 适用到 18** |
| 泰国 PDPA | 20（10 岁以下须监护人） |
| 马来 PDPA | 18 |
| 越南 PDPD | 16（7 岁以下须父母同意） |
| 印尼 PDP Law | 17 |
| 阿联酋 PDPL | 18 |

**工程上取两档即可**：< 13 最严、< 16 需家长同意、16–17 仍按未成年人处理。泰国 20 按 18 落地，并在泰语 TOS 写明监护人条款。

#### 可验证家长同意的落地方案（无账号体系下）

| 方案 | 做法 | 代价 |
|---|---|---|
| A 家长邮箱双重回执 + PIN 绑定 | 填家长邮箱 → 一次性链接 → 设备内输 6 位码并设家长 PIN | 需先上邮件通道（当前后端无线上环境）。GDPR 下够用，但**语音一旦外传，COPPA 的 email-plus 就不够** |
| B 支付验真 | 约 0.5 美元预授权后撤销，或信用卡验证 | COPPA 明确认可；需接支付、拒付成本，**东南亚卡覆盖率低** |
| **C 渠道线下同意（建议主通道）** | 随机附同意书，家长签署后经销商在激活时录入同意编号，设备只校验编号 | 依赖渠道执行、审计链偏弱，但**在硬件销售模式下最现实** |

**建议 C 为主通道 + A 兜底**。若想彻底摆脱 COPPA 可验证同意，就把门槛明确设为 13+ 并在向导用生日拒绝低龄用户（AADC 义务仍在）。

### 7.7 评审新增待确认项（Q74–Q78）

全部来自安卓原生与业务两个角色，**都是只有外部方能回答的**。评审能自行定论的已写进 7.3，不占 Q 号。

| # | 待确认项 | 建议默认值 | 阻塞级 | 需谁答 |
|---|---|---|---|---|
| **Q74** | **是否可把 C-LingoAIOS 壳做成平台签名的 priv-app**（掌握 ROM 的前提下）。能力比 Device Owner 更强、**且可随 OTA 补装**，是唯一能真正做到系统级夜览、抗清除数据、WLAN 直控的路径 | 若我们掌握 ROM 则走此路径，优先于 DO | **阻塞开工 + 与 Q34 同级** | 硬件 / ROM 方 |
| **Q75** | **目标机型是否 GMS 认证**。无 GMS 则 ML Kit 中文 OCR 模型无法按需下发、`SpeechRecognizer` 无服务实现、系统 TTS 可能无中文引擎——Camera OCR / ASR / TTS 三块的实现方案完全不同 | 需硬件方明确。`06` N9 已承认主销区大量无 GMS 设备，则**默认按无 GMS 设计**，自带引擎与模型 | **阻塞开工** | 硬件方 |
| **Q76** | **手写笔型号与数字化层**（是否配 EMR / AES 主动笔）。无主动笔时 `PointerEvent.pressure` 只返回常数，压感与掌托抑制在软件侧做不到 | 若 BOM 无主动笔，则汉字书写取消压感需求，只按 `pointerType === 'pen'` 过滤 | 阻塞开工（汉字书写笔迹采集） | 硬件方 BOM |
| **Q77** | **最低 WebView（Chromium）版本基线**。`inset-inline-*` 需 87+、`06` NFR-RES-04 强制的 `dvh` 需 108+、`addWebMessageListener` 需 88+。无 GMS 设备的 WebView 由 OEM 决定，**常年停在旧版** | 定基线并在启动时检测，低于基线给明确升级页，**不要静默破版** | **阻塞开工**（决定 RTL 与响应式能用哪些 CSS） | 硬件方 + 前端共同定 |
