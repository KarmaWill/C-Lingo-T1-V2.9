## 一、概述与本篇范围

### 1.1 本篇要解决的问题

前六篇定义「做什么功能」，本篇定义「这些功能在**一台真实的安卓平板**上必须达到什么工程标准」。C-LingoAIOS 的特殊性让非功能需求的权重高于一般 App：

1. **它是预装系统外壳，不是应用商店里的 App。** 设备出厂即带内容，用户可能长期离线；一次发版的成本远高于服务端热更新，因此「内容与代码分离」「离线能力分级」「跨版本数据迁移」不是优化项，是可发布性的前提。
2. **它面向多分辨率硬件批次。** 同一份前端代码要跑在至少 4 种屏幕规格上，缩放机制若出错，表现是整页破版而不是局部瑕疵。
3. **它要进中东市场。** 阿拉伯语不是「再加一份翻译文件」，而是整页镜像的布局工程改造。
4. **它没有账号体系，只有匿名 `deviceId`。** 隐私成本低，但也意味着**没有任何服务端可信状态**——安全边界、数据留存、指标口径都必须围绕这个前提重新定义。
5. **它当前没有任何埋点。** `00` 第三节 7 项 KPI 全部标 `[待确认]` 且无 baseline，`00` 风险 R1 直接点名此事。

## 二、埋点与指标体系（P0）

> **优先级说明**：`00` 第六节 RICE 给埋点 **0.67**，仅次于开机向导；`00` 第七节把它列为「全部 KPI 验收」的唯一硬阻塞源；`00` 第八节把它排进 **S1**，先于所有功能。本章是本篇的头号章节。

### 2.1 现状基线

| 事实 | 说明 |
|---|---|
| **客户端无任何埋点 SDK** | 全仓库无 analytics / telemetry 依赖，无 `track()` 抽象层，无事件字典 |
| **无上报后端** | `07` 3.3 明确：埋点上报接口「当前既无接口也无契约」（Q14） |
| **无 baseline 数据** | 产品未上线，`00` 第三节 7 项 KPI 全部标 `[待确认]`，RICE 的 Reach 全为推断（`07` Q3） |
| **无错误上报** | 无全局 `ErrorBoundary` 上报通道，白屏与崩溃不可观测 |
| 唯一可用的身份 | `clingo-hsk-device-id` 中的匿名 UUID（`services/hskExamService.ts:185-207`） |

**结论**：3.0 的埋点不是「给现有体系加点位」，而是**从零建立事件模型、采集层、缓存补传层与上报契约**。本章按「能直接开工」的粒度写。

### 2.2 设计原则

| # | 原则 | 含义 |
|---:|---|---|
| P-1 | **匿名优先** | 只用 `deviceId`。**不得**引入任何可识别个人的字段，与第九章禁采清单严格一致 |
| P-2 | **最小必要** | 只采集能支撑 `00` 第三节 7 项 KPI 与错误定位的事件。新增事件必须说明服务于哪个指标 |
| P-3 | **离线优先** | 平板常离线是**常态不是异常**。事件必须先本地入队，网络恢复后补传，不得因离线丢事件 |
| P-4 | **事件即契约** | 事件名、属性名、枚举值一旦上线即为契约，变更走版本号，不得原地改语义 |
| P-5 | **不阻塞主流程** | 埋点全链路异步；采集层任何异常都必须被吞掉并降级，**不得**让埋点故障造成业务白屏 |
| P-6 | **可自证** | 提供调试模式与事件校验工具，测试能在提测前验证点位是否按契约触发 |

### 2.3 需求：事件模型

#### `NFR-TRK-01` 事件命名规范

事件名格式：`<域>.<对象>.<动作>`，三段，全小写，段内用下划线连接多词。

| 段 | 取值 | 说明 |
|---|---|---|
| 域 | `app` \| `onboarding` \| `home` \| `library` \| `lesson` \| `hsk` \| `ai` \| `tool` \| `system` | 与 `00` 第五节的五个域对齐，`app` 为全局 |
| 对象 | 名词，如 `step` / `page` / `cta` / `audio` / `locked_entry` | 被操作的东西 |
| 动作 | **过去式**，如 `viewed` / `clicked` / `started` / `completed` / `failed` / `abandoned` | 描述已发生的事实 |

约束：

1. 动作只允许使用受控词表：`viewed` `clicked` `started` `completed` `failed` `abandoned` `skipped` `selected` `submitted` `crashed`。新增动作词需走事件评审。
2. **禁止**在事件名里编码动态值（不得出现 `lesson_12.viewed`），动态值一律进属性。
3. 事件名长度 ≤ 64 字符。

#### `NFR-TRK-02` 事件信封（Envelope）

每条事件是一个 JSON 对象，由**信封字段 + 公共属性 + 事件专有属性**三部分构成。

**信封字段（全部必填，由采集层自动填充，业务代码不得手工传入）**

| 字段 | 类型 | 说明 |
|---|---|---|
| `schema_version` | string | 事件模型版本，形如 `1.0`。模型破坏性变更时递增 |
| `event_id` | string(UUID) | 单条事件唯一 ID，**用于服务端去重**（补传可能重复投递） |
| `event_name` | string | 见 `NFR-TRK-01` |
| `client_ts` | int64 | 事件发生时的客户端毫秒时间戳 |
| `enqueued_ts` | int64 | 入本地队列时刻 |
| `sent_ts` | int64 | 实际发出时刻。与 `client_ts` 的差值即**补传延迟** |
| `seq` | int64 | 设备内单调递增序号，**用于在时钟回拨时恢复事件顺序** |
| `session_id` | string(UUID) | 见 `NFR-TRK-05` |
| `device_id` | string(UUID) | 取自 `clingo-hsk-device-id`，见第九章 |

> **时钟漂移处理**：平板可能长期离线且用户可改系统时间。服务端必须同时记录 `received_ts`，并以 `seq` 为设备内排序的第一依据、`client_ts` 为第二依据。指标计算中的「时长类」口径（如向导中位耗时）只允许用**同一 session 内两个事件的 `client_ts` 差值**，不得跨 session 相减。

**公共属性（全部必填，采集层自动附加）**

| 字段 | 类型 | 取值来源 | 用途 |
|---|---|---|---|
| `app_version` | string | 构建注入 | 版本对比 |
| `build_number` | string | 构建注入 | 精确定位构建 |
| `screen_size` | string | `VITE_SCREEN_SIZE`，形如 `2000x1200` | **多分辨率破版归因** |
| `viewport` | string | `window.innerWidth x innerHeight` | 实际视口，与 `screen_size` 不一致即为环境异常 |
| `locale_id` | string | `c-lingo-ui-locale-v1` | 语种维度 |
| `text_dir` | enum `ltr` \| `rtl` | 见第四章 | **阿语问题归因** |
| `route` | string | 路由 path 模板（`/lesson/:id`，**不是** `/lesson/12`） | 页面维度 |
| `route_domain` | enum `A`–`E` | 按 `00` 第五节域划分 | 域维度汇总 |
| `net_status` | enum `online` \| `offline` \| `unknown` | 见 `NFR-OFF-02` | 离线归因 |
| `is_onboarded` | bool | `clingo-onboarded-v1` | 区分首启与日常 |
| `learning_path` | enum `clingo` \| `hsk` \| `placement` \| `none` | 向导 Step 5 结果 | 分流后行为对比 |
| `embed_mode` | enum `app` \| `website` | 官网 iframe 嵌入时为 `website` | 排除官网嵌入流量对设备指标的污染 |
| `device_model` | string | 安卓原生桥下发 | 硬件批次归因。`[待确认]` **Q39** |
| `os_version` | string | 安卓原生桥下发 | 同上。`[待确认]` **Q39** |

> `route` **必须用路由模板而非实例路径**。实例路径会把 `/lesson/:id` 打散成上百个基数，既无法聚合又可能间接暴露学习内容偏好。

#### `NFR-TRK-03` 四类事件与专有属性

**（A）页面浏览 `*.page.viewed`**

| 属性 | 类型 | 说明 |
|---|---|---|
| `from_route` | string \| null | 来源路由模板，首个页面为 `null` |

#### `NFR-TRK-04` 事件字典与治理

1. 事件定义集中在**单一事件注册表**（建议 `src/telemetry/events.ts`），包含事件名、属性 schema、所服务的 KPI、负责人。
2. `track()` 只接受注册表中已声明的事件名与属性，**TypeScript 类型层面强约束**；未注册事件在开发环境抛错、在生产环境静默丢弃并记一条 `app.error.raised`（`error_kind = js_error`）。
3. 注册表变更必须在 PR 中单独可见（改动此文件即触发数据侧 review）。
4. 事件字典导出为机器可读的 JSON，作为客户端与后端的共同契约物（`07` Q14）。

#### GWT · 事件模型

- **`GWT-TRK-01`｜Given** 开发在业务代码中调用 `track('onboarding.step.completed', {...})` 且该事件已在注册表声明，**When** 执行 `npm run build`，**Then** 类型检查通过；若属性缺少必填的 `flow_instance_id`，**Then** `tsc` 报错且构建失败。**测量方法**：在 CI 中新增一个故意缺字段的用例文件，断言构建失败。
- **`GWT-TRK-02`｜Given** 任意一条上报事件，**When** 数据侧校验其 JSON，**Then** 信封 9 个字段与公共属性中除 `device_model` / `os_version`（依赖 Q39）外的全部字段均非空，且 `route` 为路由模板格式（不含数字实例段）。**测量工具**：上报接口侧的 schema 校验器；抽样率 100%，校验失败率必须为 **0**。
- **`GWT-TRK-03`｜Given** 一条 `app.error.raised` 事件，**When** 检查 `error_message`，**Then** 长度 ≤ 200 字符，且不含 `@` 符号连接的邮箱形态字符串、不含 URL query 串。**测量方法**：数据侧正则扫描全量错误事件，命中即为 P1 缺陷。

### 2.5 需求：匿名口径

#### `NFR-TRK-09` 埋点禁采清单（与第九章强一致）

| 类别 | 结论 |
|---|---|
| 唯一允许的身份字段 | `device_id`（`clingo-hsk-device-id` 中的匿名 UUID） |
| **禁止采集** | 硬件序列号、IMEI、MAC、Android ID、广告 ID、浏览器指纹、IP 地址（含服务端主动记录）、GPS 与任何地理坐标 |
| **禁止采集** | 开机向导中填写的**邮箱、昵称、生日、性别、头像**（`clingo-onboard-profile-v1` 的全部内容） |
| **禁止采集** | WiFi SSID / BSSID、已安装应用列表、通讯录、剪贴板 |
| **禁止采集** | AI 对话的用户输入原文、Camera 拍摄的图像与 OCR 原文、Reading Buddy 导入的文档内容 |
| 受限采集 | 年龄段可派生为分桶（如 `13-15` / `16-19`）但**不得**上报生日原值；是否采集需业务方与法务确认 `[待确认]` **Q41** |
| 错误信息 | 必须脱敏，见 `NFR-TRK-03`(D) |

> **为什么把「不采 IP」也写进来**：客户端不上报 IP，但**服务端接收 HTTP 请求时天然能看到 IP**。因此这一条是对**上报接口**的要求——接口不得把 IP 落库、不得用 IP 做地域分析，日志中的 IP 保留期限需单独定义（`[待确认]` **Q42**）。不写清楚，「不采集 IP」这条承诺在服务端会自动失效。

#### `NFR-TRK-10` 与「清除数据 = 新设备」的口径一致性

按 `AGENTS.md`，清除浏览器数据等于换了一台新设备，历史最高分相互隔离，**这是一期设计不是 bug**。这对指标口径的直接影响：

1. 一切「设备去重」指标的真实含义是**「安装实例去重」**，不是「人去重」。指标定义文档必须显式写明这一点，避免业务方把它当 DAU/MAU 解读。
2. 清除数据会造成**同一台物理设备重复计入「新设备」**，从而虚高「开机向导完成率」的分母。3.0 接受这个误差，不引入任何补偿性识别手段。
3. 埋点层**不得**为了「更准」而引入指纹、硬件 ID 或任何跨清除持久化手段。这条是硬红线。

#### GWT · 匿名口径

- **`GWT-TRK-07`｜Given** 应用运行在真机上，**When** 抓取一整个会话期间发往上报接口的全部请求体，**Then** 请求体中不出现 `NFR-TRK-09` 禁采清单中的任何字段名与取值形态（邮箱正则、MAC 正则、IPv4 正则、经纬度数值对）。**测量工具**：代理抓包 + 正则扫描脚本，纳入发布前 checklist。
- **`GWT-TRK-08`｜Given** 一台已产生事件的设备，**When** 清除应用数据后重新启动，**Then** 新产生事件的 `device_id` 与清除前不同，且客户端**不存在**任何机制能把新旧 `device_id` 关联起来。**测量方法**：代码走查 + 抓包比对。

平板常离线是常态。补传链路的健壮性直接决定指标的可信度。

#### `NFR-TRK-11` 本地事件队列

| 项 | 要求 | 备注 |
|---|---|---|
| 存储介质 | **IndexedDB** 为主，不可用时降级到 `localStorage` | `localStorage` 与业务数据共享 5–10MB 配额（见第七章），埋点不得挤占业务空间 |

| 溢出策略 | **按优先级丢弃**：先丢 `*.page.viewed` 等高频低价值事件，**错误类事件（D 类）与向导流程事件（C 类）最后丢** | 丢弃时记一条 `app.error.raised`（`error_kind = js_error`、`reason = telemetry_queue_overflow`），该条自身不参与丢弃 |
| 持久化时机 | 入队即持久化，**不得**只放内存 | 否则杀进程即丢，与 N6 同类问题 |
| 单事件体积上限 | 4 KB，超限截断 `error_message` 等长字段 | |

#### `NFR-TRK-12` 上报与重试

| 项 | 要求 |
|---|---|
| 批量策略 | 满 **20 条** 或 **30 秒** 触发一次上报，先到先发 `[待确认]` **Q43** |

## 三、多分辨率与布局适配规范

### 3.1 现状基线

#### 缩放机制

全部壳层与非 HSK 页按 **Figma 1920×1200** 出数，经 `src/utils/figmaScale.ts` 映射到实际屏幕：

```text
figmaPx(n, screenSize) = max(1, round(n × figmaScale(screenSize)))
```

| `screenSize` | `figmaScale` 返回值 | 说明 |
|---|---:|---|
| `960x540` | 960 / 1920 = **0.5** | |
| `2000x1200` | 2000 / 1920 ≈ **1.042** | 默认目标设备 |
| `1920x1125` | **1** | |
| **其他任意值（含 `1920x1080`）** | 1024 / 1920 ≈ **0.533** | **默认分支，见缺陷 N1** |

`APP_SCREEN_SIZE = import.meta.env.VITE_SCREEN_SIZE || '2000x1200'`；`MainLayout.tsx:33` 的 fallback 同为 `2000x1200`。**两处必须是同一字符串**，不能一处按 2000 一处按 1024，否则壳层与页内元素按两套比例渲染。

#### npm script ↔ 分辨率 ↔ 端口（实测）

| 命令 | `VITE_SCREEN_SIZE` | 实际生效端口 | 备注 |
|---|---|---:|---|
| `npm run dev` | 未设 → 代码回落 `2000x1200` | 3001 | |
| `npm run dev:2000` | `2000x1200` | 3004 | `--port` 覆盖 `vite.config.ts` 的 3001 |
| `npm run dev:960` | `960x540` | 3002 | |
| `npm run dev:1920` | `1920x1125` | 3003 | |
| `npm run dev:1920-1080` | `1920x1080` | **3002** | **与 `dev:960` 冲突，见 N2** |
| （无脚本，仅 `vite.config.ts` 映射） | `1024x768` | 3005 | 只能手工设环境变量触发 |

#### 缺陷

| # | 缺陷 | 现状事实 | 后果 |
|---:|---|---|---|
| **N1** | `figmaScale` 无 `1920x1080` 分支 | 落进默认分支按 `1024/1920 ≈ 0.533` 缩放 | 1920×1080 设备上全部固定块只有应有尺寸的一半，整屏破版。**而 1920×1080 是安卓平板最常见的规格之一** |
| **N2** | 端口冲突 | `dev:1920-1080` 与 `dev:960` 同抢 3002，`vite.config.ts` 对两种尺寸也都返回 3002 | `npm run dev:all-4` 并行必失败，且失败信息容易被误读成「项目起不来」 |
| **N3** | 脚本注释与 `package.json` 不一致 | `open-all-resolutions.sh`、`start-and-open-all.sh` 注释称各分辨率都用 3001（`AGENTS.md` 已记，按 `package.json` 为准） | 端口信息有三份来源（`package.json` / `vite.config.ts` / shell 脚本），互相矛盾 |
| — | 底栏尺寸文档与代码不一致 | 代码：dock 828×115、padding 93、Camera 115×115、gap 40、距底 56、蓝色渐变 `148.83deg #7BFFF2→#3ED8F8→#00B1FF`；`AGENTS.md`：870×130、padding 120、gap 130、Camera 150×130、距底 40、青绿 `150.37deg #1BE0CA→#00B4A0` | 没有人知道哪份是对的；改一处不改另一处，回归时无基准 |
| — | 田字格未用 `aspect-ratio` | `CharacterWritingPage.tsx:209-210` 用固定 `300×300` / `350×350`（宽高相等所以当前是方的，但**不是**由 `aspect-ratio` 保证）；`CharacterWritingHubPage.tsx:208-227` 正确使用 `aspectRatio: '1 / 1'` | 一旦父容器施加 `flex` 或缩放，固定值写法会被拉成长方形 |

#### `NFR-RES-04` 高度分配硬约束

这是 `AGENTS.md` 已记录、但必须写进工程规范的一条：**按宽缩放后，1920×1200 稿的总高会超过 2000×1200 与 1920×1125 的设备高度**（1200 × 1.0417 = 1250 > 1200）。1920×1080 档更甚（稿高 1200 > 设备高 1080）。

| 元素类型 | 高度策略 | 理由 |
|---|---|---|
| 固定块（顶栏、底栏、系统状态栏） | 用 `figmaPx` 出绝对高度 | 这些是视觉锚点，必须与稿一致 |
| **中间互动区** | **`flex: 1` 吃满剩余高度** | 吸收稿高与设备高的差值 |
| 互动区内的分割 | 按比例或 flex 分配，不用绝对值累加 | |

**禁止事项（写成硬规则，便于 code review 逐条对照）**

1. **禁止**把稿上的纵向序列（如 160 + 40 + 960 + 40）全部转成 `figmaPx` 后相加作为容器高度。
2. **禁止**给页面根容器设 `height: figmaPx(1200, ...)`。根容器高度一律 `100dvh`（或安卓 WebView 的等效视口单位），内部再分配。
3. **禁止**在互动区内使用 `position: absolute` + `top` 绝对定位来做纵向排版，除非该元素本身就是浮层。
4. 互动区内容超出时，**互动区内部滚动**，不得让整页滚动——这会破坏「首页一屏不滚动」的设计原则（`00` 第二节）。

## 四、国际化与 RTL 工程规范

### 4.1 现状基线

#### 语言配置

| 项 | 事实 |
|---|---|
| `APP_LOCALES`（`localeConfig.ts`） | **9 种**：`zh`(zh-CN)、`en`、`vi`、`ms`、`es`、`fr`、`ja`、`ko`、`ar` |
| `DEFAULT_LOCALE_ID` | `'en'`，符合「英文为第一语言」 |
| UI 语言存储键 | `c-lingo-ui-locale-v1` |
| 向导 `ONBOARD_LANGS` | **10 种**：`zh`/`en`/`vi`/`id`/`ja`/`ko`/`th`/`es`/`fr`/`ar`，其中 **`id`、`th` 的 `localeId` 为 `null`**（选了界面不变），且**缺 `ms`** |
| 字体（`theme/appFont.ts`） | 默认 Google Sans Flex + Noto Sans SC；`ja` → Noto Sans JP；`ko` → Noto Sans KR；`ar` → **Noto Sans Arabic**（注释明确要 MSA UI 字体，不要 Naskh 书法体） |
| 字体注入 | `LocaleContext` 设置 `--app-font-family` 与 `body.style.fontFamily`；`index.html:25` 已加载 `Noto+Sans+Arabic:wght@400;500;700` |
| `ar` 的 `htmlLang` | `'ar'`，非 `'ar-AE'` |

#### 缺陷 N4：全仓库没有 RTL

**这是本章的核心问题。** 实测结论：

1. 全仓库**没有任何一处**设置 `dir="rtl"`，也**没有任何** `[dir=rtl]` CSS 选择器。
2. 唯一被设置的方向相关属性是 `document.documentElement.lang`。
3. 双向文本处理仅靠零散的 `<bdi>` 元素与 `dir="auto"`，它们只做**单节点内的双向隔离**，不影响布局方向。

因此阿拉伯语的当前形态是 **「阿语文案 + LTR 布局」**：文字是阿语，但返回箭头仍指左、进度条仍从左往右长、侧栏仍在左、卡片仍从左排到右。这不是「翻译质量问题」，是**整页方向错误**，对阿语母语用户而言接近不可用。

> `00` 第三节把「阿拉伯语界面布局缺陷 0 个 P1」列为 KPI，`07` Q22 把 RTL 规范列为**阻塞开工**项。本章即 Q22 的交付物。

### 4.2 需求

#### `NFR-I18N-01` 语言表统一（对应 N5 / `07` Q9）

| 要求 | 说明 |
|---|---|
| 单一语言表 | 向导语言选择与设置页语言切换**共用同一份 `APP_LOCALES`**，删除独立的 `ONBOARD_LANGS` |
| 无翻译不上架 | 没有完整翻译资源的语种**不出现在任何选择器里**。当前 `id`、`th` 的 `localeId` 为 `null`，必须二选一：补齐翻译后正式纳入，或从向导下架 |
| 补齐 `ms` | `ms` 在 `APP_LOCALES` 中存在却不在向导里，属遗漏，需补入 |
| 翻译完整度门禁 | 某语种的 key 覆盖率低于 **100%** 时构建告警；低于 **95%** 时该语种不得进入发布版本的语言表 `[待确认]` **Q48** |
| 缺失兜底 | 运行时找不到 key 时回落 `en`，并记一条 `app.error.raised`（`error_kind = js_error`、`reason = i18n_missing_key`），**不得**直接把 key 名显示给用户 |
| 最终语种清单 | 见 `07` **Q9**，业务方拍板 |

#### `NFR-I18N-02` `dir` 设置时机与作用域

| 项 | 要求 |
|---|---|
| 方向来源 | 语言表中每个 locale 显式声明 `dir: 'ltr' \| 'rtl'`，**不靠语言码猜**。3.0 内 `ar` 为 `rtl`，其余为 `ltr` |
| 设置位置 | `document.documentElement` 上**同时**设置 `lang` 与 `dir`。只设 `lang` 不设 `dir` 是当前 N4 的直接成因 |
| 首帧正确 | 必须在**首次渲染前**从 `c-lingo-ui-locale-v1` 读出语言并设好 `dir`，通过 `index.html` 内联脚本或应用入口同步执行。**不允许**先以 LTR 渲染再切换（会出现可见的布局跳动） |
| 切换时机 | 用户在向导 Step 1 或设置页切换语言时，立即更新 `dir`，同帧内完成，**不重载页面** |
| 局部覆盖 | 需要强制某方向的局部节点（如永远 LTR 的拼音行、代码块、数字键盘），在该节点上显式写 `dir="ltr"`，作用域限定在该子树 |
| 埋点 | `text_dir` 作为公共属性上报（`NFR-TRK-02`），用于阿语问题归因 |

#### `NFR-I18N-03` 逻辑属性替换物理属性

RTL 的工程本质是：**停止用「左/右」描述布局，改用「起始/结束」。**

| 禁止使用（物理） | 必须改用（逻辑） |
|---|---|
| `margin-left` / `margin-right` | `margin-inline-start` / `margin-inline-end` |
| `padding-left` / `padding-right` | `padding-inline-start` / `padding-inline-end` |
| `left` / `right`（定位） | `inset-inline-start` / `inset-inline-end` |
| `border-left` / `border-right` | `border-inline-start` / `border-inline-end` |
| `border-top-left-radius` 等四角 | `border-start-start-radius` 等逻辑四角 |
| `text-align: left / right` | `text-align: start / end` |
| `float: left / right` | `float: inline-start / inline-end` |
| `transform: translateX(n)` | 方向相关位移需按 `dir` 取反，或改用逻辑布局避免位移 |
| `flex-direction: row-reverse` 用来做「靠右」 | 用 `justify-content: flex-end`，让 flex 自己跟随 `dir` |

**落地要求**

1. 新增代码**一律**用逻辑属性。lint 规则禁止物理属性（`NFR-QG-03`），确需使用时加行内豁免注释并说明理由。
2. 存量代码按**路由优先级**分批改造：P0 路由在 S1 完成，P1 在 S10 阿语走查前完成，P2 随占位页统一处置。
3. HSK 备考域（`03`）为冻结域，**不回改存量物理属性**；但该域的阿语走查结论仍要记录，作为后续解冻时的输入。
4. 内联样式（`sx` / `style`）同样受此规则约束——本仓库大量使用内联样式，是排查重点。
5. Flexbox 与 Grid 的主轴方向**自动跟随 `dir`**，这是最省力的路径：优先用 flex/grid 布局表达「起始靠齐」，少用绝对定位。

#### `NFR-I18N-04` 图标与图形镜像规则

| 类别 | 处理 | 举例 |
|---|---|---|
| **必须镜像** | 表达「方向 / 前进后退 / 顺序」的图标 | 返回箭头、下一步箭头、面包屑分隔符、展开折叠三角、缩进标记、发送图标、列表项的行首装饰、抽屉滑出方向、页面切换过渡方向 |
| **必须镜像** | 表达「进度沿阅读方向推进」的组件 | 学习进度条、向导 5 步进度轨、单元完成度条、倒计时条的推进方向 |
| **必须镜像** | 布局级容器 | 侧栏位置、卡片排列起点、底栏 4+1 的排列顺序、顶栏头像与标题的左右关系 |
| **不镜像（白名单）** | 数字与数值 | 题号、分数、时间（`12:30` 不写成 `30:12`）、页码、百分比、倒计时数值 |
| **不镜像（白名单）** | 拉丁与拼音 | 拼音音节、声调标记、英文原词、HSK 等级标识（`HSK1`） |
| **不镜像（白名单）** | 汉字与汉字教学元素 | 汉字本身、**田字格**（含格内辅助线、笔画起笔点、描红方向）、部首拆分示意、笔顺序号 |
| **不镜像（白名单）** | 媒体传输控制 | **播放 / 暂停 / 停止 / 录音**图标（这是国际通用符号，镜像后反而错）、音量图标 |
| **不镜像（白名单）** | 音频与视频进度 | 音频播放进度条的推进方向**保持从左到右**，时间轴不镜像。这是媒体播放器的跨语言惯例 |
| **不镜像（白名单）** | 品牌与实物 | Logo、吉祥物、教材封面、文化图片、相机取景框内的实景 |
| **不镜像（白名单）** | 中立图形 | 设置齿轮、搜索放大镜（`[待确认]` **Q49**：放大镜柄的朝向在部分设计体系中镜像，需设计拍板）、关闭叉、加号、勾选 |

> **两条最容易出错的判断**：
> 1. **学习进度条镜像，音频进度条不镜像。** 前者表达「阅读顺序上的推进」，后者表达「时间轴」，语义不同。同一个页面上两者并存时必须区别对待。
> 2. **田字格整体不镜像。** 汉字书写方向与界面方向无关，无论界面是 LTR 还是 RTL，汉字都从左上起笔。田字格所在的**卡片**可以跟随镜像，但**格子内部**绝不镜像。

**实现要求**：镜像通过 `[dir=rtl] .icon-directional { transform: scaleX(-1); }` 一类的集中规则实现，图标组件通过 `directional` 标记声明自己是否参与镜像，**默认不镜像**（安全侧），需要镜像的显式声明。

#### `NFR-I18N-05` 字体与阿语排版

| 项 | 要求 |
|---|---|
| 阿语字体 | **Noto Sans Arabic**（MSA UI 字形）。**禁止**使用 Naskh 等书法体——它的字形高度与连笔在 UI 中难以对齐且可读性差。现有 `appFont.ts` 注释已明确此点，需保持 |
| 字体加载 | 阿语字体必须**随包本地化**，不依赖 Google Fonts CDN。理由见第六章：设备常离线，字体加载失败会导致整屏显示豆腐块 |
| 行高 | 阿语字形含大量上下附加符号，行高需比拉丁文案更大。建议 `line-height` 不低于 **1.6** `[待确认]` **Q50**（设计给值） |
| 字号 | 阿语在同字号下视觉尺寸小于拉丁，需按语种做字号微调 `[待确认]` **Q50** |
| 文案膨胀 | 界面容器必须容忍译文长度变化：拉丁语系（法语、西班牙语）相对英文**膨胀约 30%**，中文收缩，阿语介于两者之间。所有文案容器禁止按英文长度写死宽度 |
| 数字形态 | 阿语环境使用**西阿拉伯数字（0–9）还是东阿拉伯数字（٠–٩）** | `[待确认]` **Q51**。迪拜官方场景通常用西阿拉伯数字，但需业务方确认 |
| locale 标识 | 产品规则要求用**迪拜官方阿拉伯语**，而当前 `htmlLang` 是 `'ar'`。需明确最终标识是 `ar`、`ar-AE` 还是 `ar-001`，以及译文来源与审校方 | `[待确认]` **Q52** |
| 双向隔离 | 阿语与拉丁 / 汉字混排处（如「HSK1 مستوى」）继续使用 `<bdi>` 或 `unicode-bidi: isolate`。**这与整页 `dir` 是两层机制，都要有** |

**缺陷分级（`07` Q27 的建议答案）**

| 级别 | 定义 | 举例 | 处置 |
|---|---|---|---|
| **P0** | 功能不可用 | 按钮被遮挡无法点击、输入框无法输入、内容完全不可见 | 阻塞发布 |
| **P1** | 方向错乱或内容丢失 | 整页未镜像、关键文字被截断看不全、方向图标未镜像导致语义相反（返回箭头指向前进方向）、白名单元素被误镜像（时间显示成 `30:12`） | **阻塞发布**，KPI 口径即此级 |
| **P2** | 观感缺陷不影响理解 | 间距不对称、图标与文字的视觉重心偏移、行高偏紧 | 登记，不阻塞发布 |

#### `NFR-I18N-07` 文案外化与伪本地化

| 要求 | 说明 |
|---|---|
| 文案外化 | UI 中**不允许**出现硬编码可见文案。现状是大量页面内联英文字符串，需随各域改造逐步外化 |

| 复数与变量 | 使用支持复数规则与占位符的 i18n 方案；**禁止**用字符串拼接组装句子（语序在不同语言中不同） |
| 伪本地化 | 提供伪本地化模式：把英文文案自动加长 **40%** 并加方向标记，用于**在没有真实译文时**提前暴露容器溢出与硬编码文案 |
| RTL 预览 | 提供「强制 RTL」调试开关，可在任意语种下预览镜像布局，便于开发自测而不必切到阿语 |

### 4.3 GWT · 国际化与 RTL

- **`GWT-I18N-01`｜Given** 用户在开机向导 Step 1 的语言列表中，**When** 逐项点击每一个语言选项，**Then** 每一项都能真实切换界面语言（无「选了界面不变」的选项），且选择器中的语种数与 `APP_LOCALES` 完全一致。**测量方法**：自动化脚本遍历语言表，切换后断言页面标题文案发生变化。
- **`GWT-I18N-02`｜Given** 设备上次选择的语言为阿拉伯语，**When** 冷启动应用并录制首屏渲染过程，**Then** 第一帧即为 RTL 布局，**不出现**任何从 LTR 跳变到 RTL 的中间帧。**测量工具**：Performance 面板逐帧截图 / 录屏逐帧检查，容许的跳变帧数为 **0**。
- **`GWT-I18N-03`（已按 `07` 第七节评审纠正 4 修订）｜Given** 全仓库源码，**When** 在 **AST / 源码层**扫描物理方向属性（`margin-left|right`、`padding-left|right`、`left`/`right` 定位、`text-align: left|right`、`border-left|right`，含 MUI 的 `pl`/`pr`/`ml`/`mr` 简写与 `sx` 内联样式），**Then** 除显式豁免白名单（HSK 冻结域 + 带行内豁免注释的条目）外**零命中**，且白名单条目数**只减不增**。**测量工具**：ESLint 规则 + AST 扫描脚本，纳入 `npm run lint`（`NFR-QG-04`）。
  > **为什么不能用运行时 `getComputedStyle`**：初稿要求运行时扫描计算样式，但 `getComputedStyle` **会把 `margin-inline-start` 解析回 `margin-left`/`margin-right`**——代码写对了也一样命中，断言必然为假。运行时检查只保留**溢出与镜像**两类（`GWT-I18N-02`、`GWT-I18N-04`），方向属性一律在源码层判。
- **`GWT-I18N-04`｜Given** 应用以阿拉伯语运行且正在播放一段听力音频，**When** 观察音频播放进度条与学习进度轨，**Then** 音频进度条从**左向右**推进、播放/暂停图标未镜像；同页的学习进度轨从**右向左**推进。**测量方法**：人工走查 + 截图对照。
- **`GWT-I18N-05`｜Given** 应用以阿拉伯语运行，**When** 打开 `/character-writing/practice/:character`，**Then** 田字格为正方形、格内辅助线与笔画起笔点未镜像、笔顺序号仍为西阿拉伯数字且顺序正确；承载田字格的卡片整体位置已按 RTL 镜像。**测量方法**：人工走查 + `GWT-RES-05` 的正方形断言。
- **`GWT-I18N-06`｜Given** 68 条路由 × 阿拉伯语 × 支持矩阵各档（按 `07` Q26 采样，阿语全量），**When** 按 `NFR-I18N-06` 的 12 项检查表逐条走查，**Then** P0 与 P1 缺陷合计为 **0**，P2 缺陷全部登记在册。**测量方法**：结构化走查记录表，测试负责人签字后方可发布。
- **`GWT-I18N-07`｜Given** 开启伪本地化模式（文案加长 40%），**When** 走查 P0 路由，**Then** 无文字截断、无容器溢出、无布局错位；页面上出现的任何**未被加长的文案**即为硬编码文案，记为缺陷。**测量方法**：伪本地化模式下的截图走查。
- **`GWT-I18N-08`｜Given** 设备处于完全离线状态且语言为阿拉伯语，**When** 冷启动应用，**Then** 阿语文字正常渲染（无豆腐块、无回落字体），证明字体已随包本地化。**测量方法**：飞行模式 + 清缓存后冷启动截图。

## 五、性能预算

### 5.1 现状基线

| 事实 | 数据 |
|---|---|
| 超大单文件 | `AIChatPage.tsx` 约 **4012 行**；`HSKPrepTrainingPage.tsx` **逾 4600 行**；`AppsPage.tsx` 约 **1650 行** |
| 内容硬编码进 bundle | `FunChineseInteractiveEbook.tsx` 内嵌巨型 `LESSONS_DATA` 常量；`LibraryBookSelectionPage.tsx` 内嵌 `INITIAL_BOOKS`；汉字笔画数据、拼音字库均为页内常量 |
| 远程资源 | `/grammar-puzzle` 使用 **Unsplash 远程图 URL**（`07` Q13） |
| 无性能门禁 | 无 bundle 体积上限、无 TTI 监控、无帧率监控（N8） |
| 无性能 baseline | 未上线、无埋点，**当前所有性能阈值均为推断** |

#### 缺陷 N7：内容与代码未分离

把教材、题库、词表以 TypeScript 常量形式写进源码，带来三个必然后果：

1. **首屏体积与解析时间随内容量线性恶化。** 内容是要持续增长的（多套教材、多语种），代码体积却无法随之收敛。
2. **内容更新必须重新发版。** 对预装设备而言，发版意味着 APK 更新通道 + 用户确认安装，成本极高。
3. **内容无法按需下载，离线策略无从谈起。** 所有内容要么全在包里（包无限大），要么完全没有。

### 5.2 需求

> **本节全部阈值为推断，标 `[待确认]` **Q53**（需业务方与开发在拿到真机 baseline 后共同核定）。但每条都给出了明确的测量工具与测量场景——阈值可以后定，测量方法现在就要固化，否则埋点上线后依然无从判断。**

#### `NFR-PERF-01` 体积预算

| 指标 | 建议阈值 | 测量工具 | 测量场景 |
|---|---:|---|---|
| 首屏关键 JS（gzip 后） | ≤ **300 KB** `[待确认]` | `vite build` 产物分析 / rollup-plugin-visualizer | 冷启动落地 `/Home` 所需的全部 JS |
| 首屏关键 CSS（gzip 后） | ≤ **60 KB** `[待确认]` | 同上 | 同上 |
| 单个路由懒加载 chunk | ≤ **150 KB** `[待确认]` | 同上 | 任一 P0 路由的按需 chunk |
| 单个源文件行数 | ≤ **600 行** `[待确认]` | ESLint `max-lines` | 全仓库（HSK 冻结域豁免） |
| APK 内置内容包总量 | `[待确认]` | 构建产物统计 | 与 `05` 内容缓存策略联动 |

**要求**

1. 全部路由级组件走 `React.lazy` + `Suspense` **按需加载**，首屏只加载壳层 + `/Home`。
2. 建立 bundle 体积基线文件，CI 中对比，**增幅超过 5% 需 PR 中显式说明**（`NFR-QG-05`）。
3. 三方依赖引入需评估体积；同类能力不引入第二个库。

#### `NFR-PERF-02` 启动与加载

| 指标 | 定义 | 建议阈值 | 测量工具 |
|---|---|---:|---|
| 冷启动到首帧（FCP） | 应用进程启动 → 首个有意义像素 | ≤ **1.5 s** `[待确认]` | Performance 面板 / 真机录屏逐帧 |
| 冷启动到可交互（TTI） | → `/Home` 主入口可响应点击 | ≤ **3.0 s** `[待确认]` | Lighthouse（模拟）+ 真机埋点 |
| 路由切换 | 点击入口 → 目标页首帧 | ≤ **400 ms** `[待确认]` | 埋点 `*.page.viewed` 与 `*.cta.clicked` 的 `client_ts` 差值 |
| 懒加载 chunk 拉取失败 | — | 必须有重试与错误态，**不得白屏** | 断网场景走查 |
| 首屏骨架 | 任何加载超过 **300 ms** 的区域必须展示骨架或加载态 | — | 人工走查 |

> **测量基准机型 `[待确认]` Q54**：性能阈值离开机型就没有意义。必须指定一台**出厂低配批次**作为基准机，所有阈值在该机上测。用开发机的 Chrome 测出来的数字不可作为验收依据。

#### `NFR-PERF-03` 交互响应与动画

| 指标 | 建议阈值 | 测量工具 | 场景 |
|---|---:|---|---|
| 点击到视觉反馈 | ≤ **100 ms** `[待确认]` | Performance 面板 Interaction 记录 | 所有可点元素必须有按下态 |
| 输入响应（INP） | ≤ **200 ms** `[待确认]` | Web Vitals | 文本输入、拖拽、手写 |
| 动画帧率 | ≥ **55 FPS**（目标 60）`[待确认]` | Performance 面板 / `requestAnimationFrame` 采样 | 页面切换、卡片翻转、进度动画 |
| 手写笔迹跟随延迟 | ≤ **50 ms** `[待确认]` | 真机高速录像 | `/character-writing/practice/:character` 的 Canvas 书写 |
| 长任务 | 单个任务 ≤ **50 ms** | Long Task API | 全局 |
| 滚动 | 长列表滚动无掉帧、无白块 | Performance 面板 | 书架、题库、错题列表 |

**要求**

1. 动画一律用 `transform` 与 `opacity`，避免触发布局重排的属性。
2. 遵守系统「减少动态效果」无障碍设置（`prefers-reduced-motion`），见第十一章。
3. 手写 Canvas 必须使用指针事件合并（`getCoalescedEvents`）以保证笔迹平滑。

#### `NFR-PERF-04` 内存与稳定性

| 指标 | 建议阈值 | 测量工具 | 场景 |

| 常驻内存（JS Heap） | ≤ **150 MB** `[待确认]` | Memory 面板 / 安卓 `dumpsys meminfo` | 在 `/Home` 静置 5 分钟 |

| 长列表 | 超过 **50 项**的列表必须虚拟化 | code review | 书架、错题、题库、应用商店 |

**要求**：页面卸载时必须清理定时器、事件监听、音频实例（与第八章代次令牌规范一致）、`AbortController`。

| 阶段 | 要求 |

## 六、离线能力分级

### 6.1 现状基线

C-LingoAIOS 是**平板设备预装**场景：设备可能在学校、家庭、网络条件不稳定的地区长期使用，**离线是常态而非异常**。

| 事实 | 说明 |
|---|---|
| **假的 OFFLINE 徽章** | `LibraryPage.tsx:84-108` 在 `/Home` 上渲染一个静态 OFFLINE 徽章，**它不读任何网络状态**，永远显示 |
| 无 Service Worker | 全仓库无 SW 注册，无应用外壳缓存，断网后刷新页面直接失败 |
| 无真实网络检测 | 无 `navigator.onLine` 监听，无连通性探测 |
| 无内容预置策略 | 内容要么硬编码在 bundle（N7），要么是假进度条的 mock 下载（`07` 5.2） |
| 远程依赖 | `/grammar-puzzle` 的 Unsplash 图、Google Fonts 的字体加载，离线必失败 |

#### 缺陷 N10

**UI 上向用户承诺「离线可用」，工程上却没有任何离线能力。** 这比「没有离线能力」更糟——它制造了一个会在真实使用场景中被戳破的承诺。用户在没网的教室里打开平板，看到 OFFLINE 徽章却什么都加载不出来，对产品信任的损伤是一次性的。

### 6.2 需求

#### `NFR-OFF-01` 能力分级

3.0 把每一项能力显式归入三级之一。**未归级的能力不得上线。**

| 级别 | 定义 | 断网时的表现 |
|---|---|---|
| **L0 · 完全离线可用** | 不依赖任何网络，功能与在线时完全一致 | 正常使用，**不展示任何网络相关提示** |
| **L1 · 降级可用** | 主体可用，部分能力退化或使用本地缓存 | 可用，**明示降级范围**（如「离线模式，成绩将在联网后同步」） |
| **L2 · 需网络** | 无网络则无法工作 | **入口保持可见但置为不可用态**，展示离线说明与「重试」入口。**禁止**点进去后白屏或无限转圈 |

**分级表（按 `00` 第五节的五个域）**

| 域 | 能力 | 级别 | 说明与依赖 |
|---|---|---|---|
| A 壳层 | 应用启动、`/Home`、底栏、顶栏、语言切换 | **L0** | 应用外壳必须完全离线可用，这是最低底线 |
| A 向导 | Step 1 语言、Step 4 资料、Step 5 路径 | **L0** | 均为本地操作 |
| A 向导 | Step 2 WiFi 连接 | **L2** | 本身就是联网步骤；需支持**跳过**并在后续补连 `[待确认]` **Q55** |
| A 向导 | Step 3 激活（邮箱 + SN + TOS） | **L1** | 离线时允许本地记录待激活状态，联网后补校验 `[待确认]` **Q55**。当前激活是 mock，必然「成功」 |
| B 教材 | 已下载教材的阅读、课文、练习 | **L0** | 依赖内容包预置（`NFR-PERF-05`） |
| B 教材 | 未下载教材的下载 | **L2** | 依赖 `07` Q16 |
| B 教材 | 课程视频播放 | **L1** | 已缓存的可播；未缓存的置不可用并提示下载 |
| B 教材 | 学习进度记录与学习报告 | **L0** | 本地存储，见第七章 |
| B 教材 | 文化视频、有声阅读 | **L1** | 同视频 |
| C HSK | 试卷列表、开始考试、提交判卷 | **L2** | **考试全链路依赖后端 8082**，无本地判卷能力。断网时必须在**进入考试前**拦截并说明，**绝不能**让用户答完 60 题才发现提交不了 |
| C HSK | 作答中断网 | **L1** | 答案与听力播放次数已存本地（键以 `attemptId` 为准），联网后可继续提交。**这是已有能力，需在 UI 上说清楚** |

#### `NFR-OFF-02` 真实网络状态检测

| 要求 | 说明 |
|---|---|
| 三层判定 | ①`navigator.onLine`（快但**不可信**：连上 WiFi 但无外网时它仍返回 `true`）；②**连通性探测**：对后端健康端点发轻量请求；③安卓原生桥下发的网络类型与连通性 `[待确认]` **Q20** |
| 探测策略 | 应用启动时探测一次；`navigator.onLine` 变化时探测；有 L2 能力的页面进入时探测；周期性探测间隔 **60 s** `[待确认]` **Q57**，且仅在前台执行 |
| 探测端点 | 轻量 `GET`，超时 **3 s** `[待确认]` **Q57**。**不得**用 `/admin/health` 或 `/api/health` 判定业务可用性——按工作区 `AGENTS.md`，这两个端点**不查数据库**，通了不代表后端能提供数据 |
| 状态模型 | `online`（外网与后端均可达）/ `limited`（有本地网络但后端不可达）/ `offline` / `unknown`（探测中） |
| 状态广播 | 统一的网络状态 Context，全应用订阅同一个源，**禁止**各页自己判断 |
| 埋点 | 网络状态作为公共属性 `net_status` 上报（`NFR-TRK-02`）；状态由 `offline` 转 `online` 时触发埋点补传 |
| 去抖 | 状态变化需去抖 **2 s** `[待确认]` **Q57**，避免弱网下 UI 反复闪烁 |

> **为什么要区分 `limited`**：设备连上了没有外网的校园 WiFi，是这个产品最常见的网络形态之一。此时 `navigator.onLine` 为 `true`，如果直接按「在线」处理，所有 L2 能力都会走到超时才失败，用户体验比直接判离线更差。

#### `NFR-OFF-03` 离线态 UI 规范

| 场景 | 规范 |
|---|---|

| 加载失败 | 统一失败态组件：图标 + 一句话原因 + 「重试」按钮 +（可选）「去下载」入口。**禁止**无限转圈、**禁止**破图、**禁止**空白页 |

#### `NFR-OFF-04` 应用外壳与内容预置

| 项 | 要求 |
|---|---|
| 应用外壳缓存 | 通过 Service Worker（或安卓 WebView 的等效本地资源方案 `[待确认]` **Q58**）缓存 HTML / JS / CSS / 字体 / 图标，做到**断网刷新仍可启动** |

### 6.3 GWT · 离线能力

- **`GWT-OFF-01`｜Given** 设备处于飞行模式且应用已冷启动过一次，**When** 用户重启应用，**Then** 应用正常启动并落地 `/Home`，壳层（顶栏、底栏 4+1、语言）完全可用，**不出现**白屏或资源加载失败。**测量工具**：飞行模式真机走查 + Console 无资源报错。
- **`GWT-OFF-02`｜Given** 设备连接到一个**有 WiFi 信号但无法访问后端**的网络，**When** 应用完成连通性探测，**Then** 网络状态判定为 `limited`（而非 `online`），HSK 考试入口在 **5 秒**内置为不可用态并说明原因，用户**不会**进入考试后才发现无法开始。**测量方法**：用本地防火墙屏蔽 8082 端口构造该场景 + 秒表计时。
- **`GWT-OFF-03`｜Given** 用户正在进行一场 HSK 模考且已答 20 题，**When** 网络中断，**Then** 答案与听力播放次数保持在本地（键以 `attemptId` 为准），页面提示「网络已断开，答案已保存」，作答可继续；**When** 网络恢复且用户提交，**Then** 提交成功且答案完整。**测量方法**：真机断网走查 + 提交结果比对。
- **`GWT-OFF-04`｜Given** 设备离线，**When** 用户依次进入全部 **L0** 级能力（壳层、`/Home`、已下载教材阅读、拼音表、汉字书写、卡片、小游戏、错题回顾、Profile），**Then** 每一项都可完整使用，且页面上**不出现**任何离线提示条或失败态。**测量方法**：按 `NFR-OFF-01` 分级表逐项走查打勾。
- **`GWT-OFF-05`｜Given** 设备在线，**When** 打开 `/Home`，**Then** 页面上**不存在**任何 OFFLINE 徽章（现有假徽章已删除）。**测量方法**：DOM 断言 + 视觉走查。
- **`GWT-OFF-06`｜Given** 构建产物已生成，**When** 扫描产物中的外部域名引用，**Then** 结果为**零个**第三方 CDN / 图床域名（允许清单仅含后端 API 基址）。**测量工具**：构建后扫描脚本，纳入 CI 阻塞项。

#### 缺陷 N6：大量状态只在内存不落盘

以下状态**只存在于 React / Redux 内存中，刷新即丢**（`07` 第五节 Mock 全表已列出部分，此处汇总为工程问题）：

| 状态 | 位置 | 用户感受 |
|---|---|---|
| 书架下载状态与进度 | 选书页 / 书架 | 「刚下载好的书没了」 |
| 课程 `completedUnits` 学习进度 | 教材域 | **「我学过的全白学了」——最严重的一项** |
| AI 会话历史 | `/ai-chat` Redux | 「上次的对话找不到了」 |
| Profile 编辑结果 | `/profile/edit` | 「改了昵称没保存」 |
| 家长控制设置 | `/parental-controls` | 「设的限制自己失效了」 |

> 对一个**没有账号、没有云同步**的产品而言，本地不落盘等于数据不存在。N6 是 3.0 用户信任风险最高的一类缺陷。

### 7.2 需求

#### `NFR-STOR-01` 命名与版本规范

| 项 | 规则 |
|---|---|
| 统一格式 | `clingo.<域>.<名>.v<N>`（承接 `07` E2 的结论），域取 `onboarding` / `library` / `lesson` / `hsk` / `ai` / `tool` / `system` / `telemetry` |
| 分隔符 | 段间一律用 `.`，段内多词用驼峰。**禁止**混用 `-` 与 `_` |
| 版本后缀 | **所有新增键必须带 `.v<N>`**。无版本后缀的键不允许通过 code review |
| 值格式 | 一律 JSON。**禁止**裸字符串与裸数字（`syntax-snap-points` 用 `points.toString()` 是反例） |
| 值信封 | 每个值包一层信封：`{ v: <schema 版本>, t: <写入时间戳>, d: <数据> }`，便于迁移与过期判定 |
| 动态键 | **禁止**新增「一条记录一个键」的模式（E3 的根因）。集合类数据一律单键存 map/array |
| 键清单 | 全部键集中声明在**单一常量模块**，与 `07` 第二节表互为镜像；新增键必须同步更新 `07` 表 |

#### `NFR-STOR-02` 统一读写封装

承接 `07` E5，本篇补充封装的具体职责：

| 职责 | 要求 |
|---|---|
| 命名空间 | 只接受键清单常量，不接受任意字符串 |
| 序列化 | 自动 JSON 序列化 / 反序列化 + 信封包装 |
| Schema 校验 | 读取时按 schema 校验，**校验失败返回默认值并记一条 `app.error.raised`（`error_kind = js_error`、`reason = storage_schema_mismatch`）**，不抛异常给业务代码 |
| 默认值 | 每个键必须声明默认值，读取永不返回 `undefined` |
| 异常吞噬 | `getItem` / `setItem` 全部包 try/catch；隐私模式或存储被禁用时降级为内存 Map 并告警 |
| **配额处理** | 捕获 `QuotaExceededError`，触发 `NFR-STOR-03` 的清理流程，重试一次；仍失败则提示用户并记埋点 |
| 写入节流 | 提供节流 / 防抖写入 API，见 `NFR-STOR-04` |
| 变更订阅 | 提供跨标签页 `storage` 事件订阅，但**多标签页的当前作答指针必须按 `attemptId` 用独立存储键，旧页面只能清自己的键**（HSK 域既有约束，见 `07` 2.3 与 `03`） |
| 迁移钩子 | 承载 `NFR-STOR-05` 的迁移逻辑 |

#### `NFR-STOR-03` 容量预算与清理

`localStorage` 的浏览器配额通常为 **5–10 MB**（按 origin 计），且**没有标准化的剩余空间 API**。

| 项 | 要求 |
|---|---|
| 总预算 | 全应用 `localStorage` 占用 ≤ **3 MB** `[待确认]` **Q60**，留出安全余量 |
| 分域预算 | 学习记录 ≤ 1.5 MB、HSK 作答缓存 ≤ 0.5 MB、系统与工具 ≤ 0.5 MB、其余 ≤ 0.5 MB `[待确认]` **Q60** |
| 大数据外迁 | 超过 **100 KB** 的数据不进 `localStorage`，改用 IndexedDB（教材内容、音频、图片、Reading Buddy 文档、埋点队列） |
| 用量监控 | 启动时估算当前占用（遍历键累加字符串长度 × 2 字节），超过预算 **80%** 时在设置页展示提示 |
| 条数上限 | 集合类数据统一设上限 + LRU 淘汰（承接 `07` E3）：学习记录默认上限 `[待确认]` **Q60** |
| 清理入口 | `/system/content-cache` 或 Profile 下提供「清理学习记录 / 清理缓存」入口，**分项展示占用大小**，删除前二次确认 |
| 清理分级 | ①清缓存（可再生数据，如翻译历史、临时文件）；②清学习记录（不可再生，强警告）；③恢复出厂（等同换新设备，最强警告并说明历史最高分将丢失） |
| 配额耗尽 | 见 `07` 2.6 的 GWT：不崩溃、不白屏、提示「存储空间不足，请清理学习记录」并提供跳转入口 |

#### `NFR-STOR-04` 必须持久化的状态清单（N6 的正向需求）

**判定原则**：凡是**用户投入了时间或做出了选择**而产生的状态，必须持久化。凡是**可由其他状态推导或一次性重建**的，不持久化。

| 状态 | 持久化 | 建议键 | 写入时机 | 优先级 |
|---|---|---|---|---|
| 课程 / 单元完成进度 `completedUnits` | **必须** | `clingo.lesson.progress.v1` | 单元完成事件发生时**立即写** | **P0** |
| 当前教材指针 | 已有 | `clingo.library.activeBook.v1`（现有键，待改名迁移） | 切换教材时立即写 | P0 |
| 主线阶段（视频已看 / 练习已做 / 报告已看） | **必须** | 并入 `clingo.lesson.progress.v1`（替代 `lesson_<id>_seen_video`，解 E3） | 阶段切换时立即写 | P0 |
| Profile 编辑结果 | **必须** | 写回 `clingo.onboarding.profile.v1`（解 E1） | 点「保存」时写 | P0 |
| 书架下载状态与进度 | **必须** | `clingo.library.downloads.v1` | 进度**节流 1 s** 写；状态变化立即写 | P1 |
| 家长控制设置 | **必须** | `clingo.system.parentalControls.v1` | 每次设置变更立即写 | P1 |
| AI 会话历史 | **必须** | IndexedDB `clingo.ai.sessions.v1`（体积大，不进 `localStorage`） | 每轮对话结束后写；上限与 LRU 见 Q60 | P1 |
| AI 练习报告 | **必须** | 同上 | 报告生成时写 | P1 |
| 学习时长统计 | **必须** | `clingo.study.timeStats.v1` | **节流 30 s** 写 + 页面隐藏时强制写 | P1 |
| 错题与单题结果 | 已有（需重构） | `clingo.study.questionResults.v1`（单索引键，解 E3） | 作答提交时写 | P1 |
| Deep Dive 日配额 | 已有 | 沿用，改名迁移 | 消耗时写 | P2 |
| 滚动位置、临时筛选条件、UI 折叠态 | **不持久化** | — | — | — |
| AI 对话的输入框草稿 | 不持久化 `[待确认]` **Q61** | — | — | — |

**写入策略**

| 类型 | 策略 |
|---|---|
| 关键节点（完成、提交、保存） | **立即同步写**，不节流 |
| 高频连续变化（下载进度、学习时长、书写笔迹） | **节流写**（1 s / 30 s，见上表），并在 `visibilitychange → hidden`、`pagehide`、路由离开时**强制刷写一次** |
| 失败重试 | 写失败立即重试 1 次；再失败走 `NFR-STOR-03` 的配额清理流程；仍失败则记埋点并提示用户，**不静默丢弃** |
| 写入验证 | 关键状态（P0 项）写入后**回读校验**，不一致则重试并记埋点 |

#### `NFR-STOR-05` 跨版本迁移与回滚

| 项 | 要求 |
|---|---|
| 执行时机 | 应用启动后、**首帧渲染前**，同步执行迁移；迁移未完成前不渲染依赖这些数据的页面 |
| 迁移单元 | 每次版本升级的迁移写成独立的、幂等的迁移函数，按 schema 版本号顺序执行 |
| 幂等 | 迁移函数必须可重复执行而不产生副作用（迁移中途被杀进程后重启仍能正确完成） |
| 备份 | 迁移前把旧键快照写入 `clingo.system.migrationBackup.v1`，保留 **1 个版本**；迁移成功且应用正常启动 **3 次**后删除备份 `[待确认]` **Q62** |
| 回滚 | 迁移过程抛异常时：恢复备份、保持旧键、标记迁移失败、记埋点，**应用仍必须能启动**（降级到旧数据可读的状态） |
| 降级安装 | 用户从 3.0 降级回 2.x 时的行为 `[待确认]` **Q62**（建议：新键对旧版本不可见，旧键保留，表现为「进度回到升级前」而不是崩溃） |
| 耗时预算 | 迁移总耗时 ≤ **500 ms** `[待确认]` **Q60**；超过则改为后台分批迁移 + 首帧用旧数据渲染 |
| 埋点 | 迁移开始 / 成功 / 失败各记一条事件，含 `from_version`、`to_version`、`duration_ms`、`migrated_key_count` |

## 八、音频与语音能力规范

### 8.1 现状基线

#### 已有的良好实现：代次令牌

`src/hsk/exclusiveAudioPlayer.ts` 用 **`generation` 代次令牌**解决了「异步 `play()` 回来后把已停止的音频又启动起来」这个经典缺陷：

```text
stop()  → generation += 1；pause()；清除 listener
play()  → 捕获当前 generation；await 之后若 generation 已变，直接放弃，不启动播放
```

`ExamScreen` 在**切题、进入宽限期、离开答题页**三处都调用 `stop()`。这套机制与 `AGENTS.md`「音频需独占控制」的要求完全一致，是全仓库音频处理质量最高的一处。

#### 其余音频与语音的现状

| 能力 | 现状 |
|---|---|
| 教材点读、播客、闪卡、AI 对话 TTS、拼音发音 | **各页自行 `new Audio()` 或调 `speechSynthesis`**，无统一管控 |
| TTS | 全部走浏览器 `speechSynthesis`，中文 `zh-CN` |
| ASR | 全部走浏览器 `SpeechRecognition` |
| 男女声选择 | **不存在**（`07` 5.4），只有系统默认声音 |
| Camera 语音输入 | **无真麦克风**，1.2 秒后返回固定文本（mock） |
| 拼音嘴型示范视频 | **完全不存在**（`07` 5.4） |

#### 缺陷 N9：Web Speech API 在安卓 WebView 上不可靠

| 风险 | 说明 |
|---|---|
| 可用性不确定 | 安卓 WebView 的 `SpeechRecognition` 支持情况取决于系统版本、WebView 版本与是否安装了 Google 语音服务。**在无 GMS 的设备上基本不可用**——而东南亚与中东市场存在大量此类设备 |
| 音色不可控 | `speechSynthesis` 的中文音色取决于系统已安装的 TTS 引擎，不同设备差异巨大，无法保证教学所需的标准普通话发音 |
| 离线能力不确定 | 部分设备的 TTS / ASR 需要联网；与第六章 L0 定级冲突 |
| 无降级 | 当前代码不检测可用性，能力缺失时表现为**静默无反应** |

### 8.2 需求

#### `NFR-AUD-01` 全站独占音频规范

把 `exclusiveAudioPlayer` 的代次令牌机制**提升为全站规范**。

| 要求 | 说明 |
|---|---|
| 单例播放器 | 全应用**只有一个**音频播放器实例。任一时刻最多一个音频在响 |
| **禁止裸播** | **禁止**任何页面自行 `new Audio()`、`<audio autoplay>`、直接调 `speechSynthesis.speak()`。全部必须经统一播放器 |
| 代次令牌 | `stop()` 递增代次并 pause + 清 listener；`play()` 捕获代次，`await` 后代次不匹配则放弃启动 |
| 覆盖范围 | HSK 听力（已有）、**教材点读、有声阅读、播客、闪卡发音、AI 对话 TTS、拼音发音、汉字读音、文化视频音轨、小游戏音效** |
| 抢占语义 | 新的 `play()` 自动 `stop()` 当前播放，不排队、不混音 |
| 音效例外 | 极短反馈音（< 300 ms，如答对提示音）可走独立的轻量通道，但**不得**与主音频抢占 `[待确认]` **Q63** |
| lint 约束 | ESLint 规则禁止 `new Audio(` 与 `speechSynthesis.speak(` 出现在播放器模块之外（`NFR-QG-03`） |

#### `NFR-AUD-02` 音频生命周期

**必须 `stop()` 的时机（全站统一，不只 HSK）**

| # | 时机 | 说明 |
|---:|---|---|
| 1 | 路由变化 | 任何 `navigate` 发生时 |
| 2 | 切题 / 切课 / 切卡片 | 内容单元切换 |
| 3 | 进入 HSK 宽限期 | 既有规则 |
| 4 | 页面隐藏（`visibilitychange → hidden`） | 切后台、锁屏 |
| 5 | 打开全屏覆盖层 | 开机向导、弹窗、抽屉 |
| 6 | 组件卸载 | `useEffect` cleanup |
| 7 | 用户开始录音（ASR） | 避免自己录到自己的播放声 |
| 8 | 系统音频焦点被抢占 | 来电、其他应用播放，需原生桥告知 `[待确认]` **Q20** |

**其他要求**

| 项 | 要求 |
|---|---|
| 播放次数限制 | HSK 听力的播放次数限制沿用既有规则（后端下发的听力规则），**计数与 `attemptId` 绑定并落本地** |
| 错误处理 | 音频加载失败、解码失败、播放被浏览器策略阻止，各有明确的失败态与重试，并记 `app.error.raised`（`error_kind = media_error`） |
| 自动播放策略 | 安卓 WebView 可能要求用户手势才允许播放。首次播放失败时展示「点击播放」引导，**不静默失败** |
| 资源释放 | `stop()` 时释放 `MediaSource` / `ObjectURL`，避免内存泄漏（与 `NFR-PERF-04` 一致） |
| 音量与静音 | 尊重系统音量与静音开关；应用内不提供独立音量条 `[待确认]` **Q63** |
| RTL | 音频进度条**不镜像**（`NFR-I18N-04` 白名单） |

#### `NFR-AUD-03` TTS 能力矩阵与降级链

| 层级 | 实现 | 优先级 | 适用 | 离线 |
|---|---|---:|---|---|
| T-1 | **预录音频**（教材课文、词表、拼音音节、HSK 听力） | 最高 | 一切**教学内容**的发音 | **可离线**（随内容包） |
| T-2 | **安卓原生 TTS**（经原生桥调用系统 TTS 引擎） | 次之 | 动态文本：AI 对话回复、翻译结果、用户自定义内容 | 取决于引擎，需探测 |
| T-3 | 云 TTS | 再次 | T-2 不可用且在线时 | 不可离线 |
| T-4 | 浏览器 `speechSynthesis` | **最低，仅兜底** | 开发环境与 Web 预览 | 不确定 |
| T-5 | 纯文本降级 | 最后 | 全部不可用时：**隐藏发音按钮**或置不可用并说明 | — |

**硬性规则**

1. **教学内容的发音必须走 T-1 预录音频，不得用 TTS 合成。** 理由：中文声调与轻声、儿化的准确度直接决定教学质量，系统 TTS 音色不可控（N9）。这条是产品质量底线，不是技术偏好。
2. **动态文本优先走 T-2 原生 TTS**，以获得可控的离线能力与音色。原生桥协议见 `07` **Q20**。
3. 启动时探测各层可用性，结果缓存并在能力变化时更新。
4. 男 / 女声选择（产品规则第 7 条要求，默认女生）在 T-1 需要**两套预录音频** `[待确认]` **Q64**；在 T-2 依赖系统引擎是否提供多音色。若均不可得，则**下架该选项**而不是提供一个无效的假开关（参照 `07` 5.6「不留静默假象」）。
5. 降级发生时**不得静默**：若从 T-1 降到 T-4，音质明显变化，需在首次发生时轻提示一次。

#### `NFR-AUD-04` ASR 能力矩阵与降级链

| 层级 | 实现 | 适用 | 离线 |
|---|---|---|---|
| A-1 | **安卓原生 ASR**（经原生桥） | 主路径：AI 口语练习、Camera 语音输入、跟读 | 取决于引擎，需探测 |
| A-2 | 云 ASR / 发音评测 | 需要**评分**的场景（发音准确度打分依赖专门的发音评测能力，普通 ASR 不够） | 不可离线 |
| A-3 | 浏览器 `SpeechRecognition` | 仅开发环境兜底 | 不确定 |
| A-4 | **文本输入降级** | 全部不可用时：提供键盘输入替代，口语练习退化为文字练习 | 可离线 |

**硬性规则**

1. **发音评分能力与 ASR 是两回事。** ASR 解决「听懂说了什么」，发音评测解决「说得准不准」。`/ai-chat` 的四维评分当前是 `mockVoiceScore()`（`07` 5.4），真实实现走 `07` **Q5** 的能力选型。
2. 麦克风权限：首次使用时申请，**说明用途**；拒绝后直接走 A-4 文本降级，不反复弹窗。
3. 录音期间必须 `stop()` 当前播放的音频（`NFR-AUD-02` 第 7 条）。
4. 录音时长上限与静音自动停止阈值 `[待确认]` **Q64**。
5. 评分口径遵守产品规则第 6 条：**评分在整个对话结束后统一展示，不每说一句就打断**。
6. 不可用时**不得**返回假分数。参照 `07` 的 GWT：「AI 评分能力调用超时 → 展示明确的失败态与重试按钮，不展示任何伪造分数」。

#### `NFR-AUD-05` 能力探测与声明

| 要求 | 说明 |
|---|---|
| 启动探测 | 应用启动时探测 TTS / ASR / 麦克风 / 音频输出的可用性，形成一份**能力清单** |
| 能力驱动 UI | 页面根据能力清单决定是否展示发音按钮、录音按钮、男女声选项。**禁止**先展示再失败 |
| 能力上报 | 能力清单摘要作为埋点上报（布尔组合，**不含**任何设备标识），用于判断不同硬件批次的能力分布 |
| 原生桥协议 | TTS / ASR / 音频焦点的 JS ↔ Native 协议、权限申请时机、超时与错误码，见 `07` **Q20** |

### 8.3 GWT · 音频与语音

## 九、隐私与匿名身份

### 9.1 现状基线

#### `deviceId` 生成机制（`services/hskExamService.ts:185-207`）

| 项 | 事实 |
|---|---|
| 存储键 | `clingo-hsk-device-id` |
| 生成 | 优先 `crypto.randomUUID()`；不可用时 fallback `web-${Date.now()}-${Math.random().toString(16).slice(2)}` |
| 复用 | 写入 `localStorage` 后一直复用 |
| 使用 | 每次考试 API 请求带请求头 `X-Clingo-Device-Id` |
| 向导展示 | Step 2 展示的 SN 是它的**短码**：`formatOnboardSn` 去掉非字母数字后取前 10 位并转大写 |

#### 隐私设计（`AGENTS.md`，一期设计，3.0 继承）

| 事实 | 说明 |
|---|---|
| **不采集**硬件序列号、浏览器指纹、IP | 一期硬性约定 |
| 清除浏览器数据 = 新设备 | 历史最高分相互隔离，**是设计不是 bug** |
| **禁令** | 不得手工伪造用户账号或设备 ID |
| 无账号体系 | 一期不做学员注册登录、跨设备成绩同步 |

#### 待改进点

| 项 | 现状 |
|---|---|
| `deviceId` 语义偏窄 | 键名是 `clingo-hsk-device-id`，但它实际上是**全产品唯一的设备身份**（埋点、未来的内容下发都要用它），键名却把它绑在 HSK 上 |
| 无隐私设置入口 | 用户看不到自己有哪些本地数据、无法选择性删除、无法关闭数据上报（上报本身尚不存在） |
| `clingo-user-token` 悬空 | 与一期无账号体系矛盾（`07` E4 / Q8），给人「有账号有鉴权」的错觉 |
| TOS 与隐私政策 | 向导 Step 3 有 TOS 勾选，但**具体文本、适用法域、未成年人条款**均未定 |

### 9.2 需求

#### `NFR-PRIV-01` 匿名设备身份机制

| 项 | 要求 |
|---|---|
| 唯一身份 | 全产品**只有一个**设备身份，供考试 API、埋点、内容下发、反馈上报共用 |
| 键名 | 迁移到 `clingo.system.deviceId.v1`（符合 `NFR-STOR-01`），**旧键 `clingo-hsk-device-id` 的值必须原样迁移**，不得重新生成 `[待确认]` **Q65** |
| 生成 | `crypto.randomUUID()`；不可用时的 fallback 需保证**足够的随机性**，现有 `Date.now() + Math.random()` 碰撞概率虽低但可预测性偏高，建议改用 `crypto.getRandomValues` 构造 UUIDv4 |
| 不可伪造入口 | 客户端**不提供**任何修改 `deviceId` 的用户界面或调试入口（生产构建） |
| 不可关联 | 清除数据后生成的新 `deviceId` 与旧值**无任何可关联手段**。这是 `NFR-TRK-10` 的红线在身份层的体现 |
| 不派生 | `deviceId` **不得**由任何硬件信息派生（序列号、MAC、Android ID）。必须是纯随机 |
| 展示 | 向导 Step 2 展示的 SN 短码仅供售后核对，展示逻辑沿用 `formatOnboardSn`；页面需说明「这是本机随机编号，不含任何个人信息」 |
| 传输 | 仅通过 `X-Clingo-Device-Id` 请求头传输，不放 URL query（避免进日志与 Referer） |

#### `NFR-PRIV-02` 采集与不采集清单

**允许采集（客户端主动上报到服务端的全部数据）**

| 类别 | 内容 | 用途 |
|---|---|---|
| 设备身份 | `deviceId`（随机 UUID） | 去重与漏斗拼接 |
| 环境 | `app_version`、`build_number`、`screen_size`、`viewport`、`locale_id`、`text_dir`、`net_status`、`embed_mode` | 归因 |
| 设备型号与系统版本 | `device_model`、`os_version` | 硬件批次归因 `[待确认]` **Q39** |
| 行为 | `NFR-TRK-07` 的 18 个事件及其声明属性 | KPI 计算 |
| 错误 | 脱敏后的错误信息与栈摘要 | 稳定性 |
| 考试 | 考试 API 既有请求（作答提交等） | 业务功能 |
| 反馈 | 用户主动提交的反馈内容（`/api/feedback`） | 用户主动行为 |

#### `NFR-PRIV-03` 本地数据的可见与可删

因为没有账号体系，**用户的全部数据都在这台设备上**，所以「可见、可删」是本产品能提供的最实质的隐私控制。

| 要求 | 说明 |
|---|---|
| 数据清单页 | 设置下提供「我的数据」页，分类展示本机存了什么（学习进度、作答记录、AI 会话、翻译历史、下载内容），各项**显示占用大小** |

### 9.3 GWT · 隐私与匿名身份

- **`GWT-PRIV-01`｜Given** 一台已在 2.x 版本产生过 `clingo-hsk-device-id` 的设备，**When** 升级到 3.0 并首次启动，**Then** 新键 `clingo.system.deviceId.v1` 的值与旧键**完全相同**，且该设备在考试后端的历史成绩仍可读取。**测量方法**：迁移演练 + 后端查询比对。这条防止升级造成全量用户「变成新设备」。
- **`GWT-PRIV-02`｜Given** 应用运行一整个会话，**When** 抓取全部出站 HTTP 请求（头 + 体 + URL），**Then** 不出现禁采清单中的任何数据形态。**测量工具**：代理抓包 + 正则扫描，纳入发布前 checklist，容忍度为 **0 条**。
- **`GWT-PRIV-03`｜Given** 用户进入「我的数据」页，**When** 查看清单，**Then** 展示的数据类别与实际存储的键覆盖一致（对照 `07` 第二节键表 + IndexedDB 存储），每类均显示占用大小且可单独删除。**测量方法**：逐项对照表走查。
- **`GWT-PRIV-04`｜Given** 用户执行「清除全部数据」并确认，**When** 应用重启，**Then** 应用回到首次开机状态（向导重新展开），`deviceId` 为全新值，且客户端不存在任何指向旧 `deviceId` 的残留。**测量方法**：清除后检查全部存储介质（`localStorage`、IndexedDB、Cache Storage、Cookie）。
- **`GWT-PRIV-05`｜Given** TOS 文本已定稿（Q67），**When** 逐条比对 TOS 声明与 `NFR-PRIV-02` 的允许采集表，**Then** 两者**完全一致**，不存在「TOS 未声明但实际采集」或「TOS 声明了但实际不采集」的条目。**测量方法**：法务与开发共同签字的对照表。

#### `NFR-SEC-02` 「无鉴权」对功能设计的硬约束

**必须内化的前提**：任何人都可以用任意 `deviceId` 直接调用考试 API。因此客户端与产品设计必须满足：

| 约束 | 说明 |
|---|---|
| **客户端不是安全边界** | 前端的等级锁定、次数限制、时间限制**只是 UI 约束**，服务端必须独立校验。HSK3–6 锁定若只靠前端隐藏，构造请求即可绕过 |
| **不放敏感数据** | 既然接口对任何 origin 开放，考试接口**不得**返回超出当前作答所需的数据（如未开始试卷的答案） |
| **答案只来自快照，且服务端判分** | 沿用既有契约：不从前端题型代码推导答案；判卷只用作答开始时冻结的快照（`07` 3.1 契约约束） |
| **不做依赖身份可信的功能** | 排行榜、跨设备成绩、付费权益等依赖「这个人是谁」的功能，在无鉴权前提下**不可实现**，3.0 不做（与一期禁令一致） |
| **不把 `deviceId` 当密钥** | 不用它加密、不用它做签名、不用它推导任何其他标识 |
| **限流按设备 + IP 双维度** | 服务端防刷不能只按 `deviceId`（可伪造），需结合 IP 限流。注意与 `NFR-PRIV-02` 的「IP 不落库」并不冲突——**限流可用 IP，但不得持久化与分析** |
| **文档化** | 这一条必须写进给后端与测试的接口文档，避免任何人把该请求头误当鉴权 |

#### `NFR-SEC-03` 客户端不存密钥、不做安全决策

| 要求 | 说明 |
|---|---|
| 无密钥 | 客户端代码与构建产物中**不得**包含任何 API Key、AK/SK、私钥、签名密钥。`VITE_*` 变量会被打进前端产物，**一切放进去的东西都等同公开** |
| 第三方能力 | AI、翻译、OCR 等需要密钥的云能力，**一律经自有后端中转**，客户端不直连第三方 |
| 禁止提交 | 沿用工作区 `AGENTS.md` 通用禁令：不输出、复制或提交 `customer-mysql-test.env`、`mysql-local.env`、`tos-test.env`、`.env.local` 中的值；不把密码、AK/SK 写入源码、Git、Issue、PR、日志 |
| `clingo-user-token` | 按 `07` **Q8** 处置：一期无账号体系，建议**删除该键与 `/api/auth/*` 调用**，消除「看似有鉴权」的错觉 |

## 十一、无障碍

> **前提**：目标用户是 **12 岁以上、主力 13–19 岁的青少年**。无障碍改造**不等于幼儿化**——不放大成巨型卡通按钮、不加拟声引导、不简化到小学生界面。要做的是**符合国际化学习 App 标准的可达性**：手指点得准、文字看得清、顺序读得顺。

### 11.1 现状基线

### 11.2 需求

#### `NFR-A11Y-01` 触控目标最小尺寸（按食指指腹推算）

**推算依据**

| 项 | 数值 |
|---|---|
| 成人食指指腹宽度 | 约 **16–20 mm** |
| 触摸时的有效接触椭圆 | 约 **10–14 mm** |
| 安卓 `dp` 的物理定义 | 1 dp = 1/160 英寸 = **0.15875 mm** |
| 主目标设备 | `2000x1200` 物理像素；假定对角 **10.1 英寸** `[待确认]` **Q23** → 约 **231 dpi** → **1 dp ≈ 1.44 设备像素** |
| Figma 稿 → 设备像素 | ×1.0417（`figmaPx`），故 **1 设备像素 ≈ 0.96 Figma 稿 px** |

**最小尺寸表**（正方形热区边长；`[待确认]` **Q23** 由设计确认并写入设计手册）

| 级别 | dp | 物理尺寸 | 设备像素（2000×1200） | Figma 稿 px | 适用 |
|---|---:|---:|---:|---:|---|
| **绝对下限** | **48 dp** | 7.6 mm | 69 px | **66** | 任何可点元素不得低于此值 |
| **标准** | **64 dp** | 10.2 mm | 92 px | **88** | 常规按钮、列表项、卡片上的操作点 |
| **推荐** | **72 dp** | 11.4 mm | 104 px | **100** | 主操作、底栏入口、答题选项 |
| **关键** | **88 dp** | 14.0 mm | 127 px | **122** | 高频且误触代价高的操作（提交试卷、开始考试、删除数据） |
| 目标间距 | ≥ **8 dp** | 1.3 mm | 12 px | **11** | 相邻可点元素之间的最小净间距 |

**规则**

1. **视觉尺寸 ≠ 触控热区。** 图标可以只有 60 Figma px，但其**触控热区必须用透明 padding 扩到 ≥ 64 dp**。`AGENTS.md` 记录的底栏四图标 60 Figma px ≈ **43 dp ≈ 6.9 mm**，低于绝对下限，必须扩热区（但**不得**改变视觉尺寸，以免破坏已锁定的底栏视觉）。
2. 答题选项、拖拽元素、田字格等**教学交互元素**按「推荐」级 72 dp。
3. 相邻热区**不得重叠**；净间距不足时缩小热区而非允许重叠。
4. 小分辨率档（`1024x768`、`960x540`）下若按 `figmaPx` 缩放后热区低于 48 dp，**热区不参与缩放**，保持物理最小值。这条是缩放规范的一个例外，需在 `figmaPx` 使用规范中显式说明。
5. 拖拽手势的触发阈值与误触撤销见 `07` **Q25**。

| 项 | 要求 | 测量 |
|---|---|---|

- **`GWT-QG-01`｜Given** 一个故意引入横向溢出的 PR，**When** CI 执行多分辨率快照测试，**Then** CI 失败并指出具体路由、分辨率与溢出元素。**测量方法**：构造故障 PR 验证门禁真的会拦。

### 14.7 本篇阻塞开工项摘要

`00` 第八节把埋点与壳层多分辨率排进 **S1**。要让 S1 真的能开工，下列 **8 项**必须在 S1 启动前有结论：

| 排序 | 编号 | 一句话 | 归属 |
|---:|---|---|---|
| 1 | **Q14** | 埋点上报接口契约——不定则 S1 出口条件「埋点可上报」无法达成（可退化为「可采集、可导出」） | 后端 |
| 2 | **Q20** | 原生桥清单——网络状态、TTS / ASR、音频焦点四块的地基 | 安卓 |
| 3 | **Q22 / Q23 / Q27** | RTL 规范、触控尺寸、阿语缺陷分级——本篇已给出草案，需设计签字才能进设计手册 | 设计 |
