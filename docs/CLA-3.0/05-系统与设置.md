## 一、概述与本篇范围

### 1.1 本篇管什么

域 E 是 C-LingoAIOS 的**设备侧与个人侧**。它不承载学习内容本身，而承载「让这台平板可以被一个青少年长期、安全、合规地使用」所需的全部能力：

1. **设备中枢**：Explore 页 `/apps`，时钟 / 工具栏 / 学习 App 网格 / 系统设置入口四合一。
2. **用户档案**：`/profile`、`/profile/edit`，以及与开机向导收集的资料打通。
3. **学习报告**：学习时长、做题准确率、学习效率三块，消费统一埋点。
4. **家长控制与青少年合规**：`/parental-controls`，PIN、屏幕时间、内容分级、enforcement 分层。
5. **语言与本地化设置**：`/system/language-packs`，设置内语言切换、语言包真实分发。
6. **内容与存储管理**：`/system/content-cache`，内容包分级、配额、LRU、断点续传。
7. **应用分发与安装**：`/apps-catalog`、`/android-app-picker`、`/nsk-app-store`、`/jxw-app-store`。
8. **客户端自更新**：`/system/app-updates`。
9. **安卓壳页**：`/android/home`、`/android/settings`，附带一个必须先回答的定位问题。

### 1.3 系统域信息架构

Explore 作为设备中枢，向下分**工具 / 应用 / 系统设置**三支。这是 3.0 的目标 IA：

```text
底栏第 4 键「Explore」
  └─ /apps  ← 设备中枢（唯一的系统域总入口）
      │
      ├─【工具支】左卡：时钟 / 日期 / 工具栏
      │    ├─ 内置工具（弹层，不跳路由）：Alarm、Calendar、Day Countdown、Pomodoro
      │    └─ 「+」→ 添加工具弹层（内置工具 + 系统小工具）
      │
      ├─【应用支】左卡右半：学习 App 网格
      │    ├─ 内置 5 个 → /ai-chat、/pinyin-chart、/lingo-flash、/favorites、/character-writing
      │    └─ 「+」→ /apps-catalog ──→ /android-app-picker（系统应用选择器）
      │
      └─【系统设置支】右卡：System settings
           ├─ Language & Region      → /system/language-packs
           ├─ Eye Protection         → 就地开关 + 「定时」二级页
           ├─ Content & Storage      → /system/content-cache
           ├─ App Updates            → /system/app-updates
           ├─ Parental Controls       → /parental-controls   ← 3.0 新增入口
           ├─ App Store（APK）        → /nsk-app-store
           └─ 「Go to Settings」黑条 → 安卓系统设置（走向由第九章决策项决定）

顶栏右侧头像 → /profile ──→ /profile/edit
```

**3.0 对 IA 的三条硬要求：**

1. **系统域不得有孤儿路由**。现状有 3 条路由在 UI 中完全不可达（见 1.4），3.0 必须全部补上入口或从路由表移除。
2. **`/apps` 是系统域唯一总入口**。除顶栏头像进 `/profile` 外，不允许从其他域旁路跳进系统页。
3. **每个系统页必须能原路返回**。统一走 `resolveBackPath(location)`，`from` 缺失时兜底到 `/apps`。

## 二、Explore 设备页 `/apps`

### 2.1 职责与版式

`/apps` 是系统域唯一总入口，一屏不滚动。左右双卡：

| 区域 | 内容 | 版式约束 |
|---|---|---|
| 顶栏 | 标题 `Explore` + 顶栏右侧语言胶囊与头像（`HubLangProfile`） | 沿用壳层规范，见 `01` |
| 左卡 · 左半 | 时钟（`HH:mm`，24 小时制）+ 日期（`Mon D · Weekday`）+ 工具栏 | 时钟字号按 `figmaPx(100)`；工具栏图标 78×78、圆角 24、`gap 14` |
| 左卡 · 右半 | 学习 App 网格，3 列 | 图标容器 `aspect-ratio: 1 / 1`，**禁止用 `flex: 1` 拉成矩形** |
| 右卡 | System settings 卡 + 底部「Go to Settings」黑条 | 固定 `EXPLORE_MAIN1.settingsW × settingsH`，由 `HubContainBoard` 等比缩放 |

**食指可点约束（对全篇生效）**：任何可点元素的实际渲染尺寸 ≥ **48×48 dp**，相邻可点元素间距 ≥ 8 dp。工具栏图标 78 figmaPx、网格图标按 `EXPLORE_MAIN1.icon`、系统设置行高 ≥ 48 dp 均满足。**编辑模式的红色删除角标是本篇唯一的例外风险**：现状在 960×540 下为 22×22，远低于 48 dp。3.0 要求删除角标的**可点热区**扩到 48×48（视觉仍可保持 24–32），用透明 padding 撑开。

### 2.2 时钟与日期

| 字段 | 取值 | 默认 | 校验 / 异常 |
|---|---|---|---|
| 时间显示 | `HH:mm`，24 小时制 | 跟随系统时区 | 每秒刷新一次；页面不可见时（`document.visibilityState !== 'visible'`）暂停 `setInterval`，可见时立即重算一次 |
| 日期显示 | `MMM D · Weekday`，英文缩写月 | — | 语言切换后随 locale 变化；**现状硬编码英文数组，3.0 必须走 i18n** |
| 时区变更 | — | — | 监听 `visibilitychange` 后重算；不依赖后台定时器跨时区自愈 |

**现状基线**：`AppsPage.tsx:522-525` 用 `setInterval(…, 1000)` 常驻，页面不可见时仍然跑。月份与星期名是页内硬编码英文数组（`AppsPage.tsx:560-561`），切语言不变。弹层里的日历/时钟却用 `toLocaleDateString('zh-CN', …)` 硬编码中文 locale（`AppsPage.tsx:1189`、`1244`、`1252`），与页面英文主体冲突。

**3.0 需求**：所有日期时间格式化统一走当前 `locale.htmlLang`，不得出现硬编码 `'zh-CN'` 或硬编码英文月份表。

### 2.3 工具栏

工具栏由**内置工具**与**系统小工具**两类拼成，最多 4 个内置 + 5 个系统小工具 + 1 个「+」键。

#### 2.3.1 内置工具（4 项）

| id | 标签 | 行为 | 3.0 处置 |
|---|---|---|---|
| `alarm` | Alarm | 打开时钟弹层（只读，显示当前时间与日期） | **改为跳系统时钟**（见第十章 `openSystemApp`）；若 Path B 则降级为只读时钟弹层并改名 `Clock`，不叫 Alarm（因为不能设闹钟） |
| `calendar` | Calendar | 打开日历弹层（只读，显示今天与年内第几天） | 保留只读；**去掉「Day N」这种无产品意义的数字** |
| `daycountdown` | Day Countdown | 倒计时弹层，可选目标日 | 保留并升级：目标日与**考试日**联动（见 2.3.4） |
| `pomodoro` | Pomodoro | 番茄钟弹层，25/15/5 预设 + Start/Pause/Reset | **保留并做实**（见 2.3.3） |

#### 2.3.2 系统小工具（`GOOGLE_SYSTEM_TOOLS`，8 项）

现状 8 项：`calculator`、`notes`、`weather`、`compass`、`recorder`、`files`、`settings`、`translate`。

**3.0 处置（三选一，按工具逐项判）：**

| 处置 | 含义 | 适用工具 |
|---|---|---|
| **跳系统 App** | 通过原生桥 `openSystemApp(packageName)` 启动设备上真实的应用 | `calculator`、`files`、`settings`、`recorder` |
| **跳产品内页** | 复用 C-LingoAIOS 自己的能力 | `translate` → `/camera` 的文本翻译标签页 |
| **移除** | 与中文学习无关、又需要额外权限或联网服务 | `notes`、`weather`、`compass` |

**理由**：`weather` 需要定位权限与天气服务，`compass` 需要磁力计，`notes` 需要另做一个记事本——三者对「学中文」零贡献，属于「能砍则砍」的典型对象。保留下来的 4 项全部是**跳转**，不需要 C-LingoAIOS 自己实现。

#### 2.3.3 番茄钟 · 3.0 做，不标「即将推出」

**决策依据**：用户规则 #15 说「后续加入番茄钟 / 25 分钟学习法」，而代码里番茄钟**已有可用的倒计时实现**（`AppsPage.tsx:527-539` 有真实 `setInterval` 递减、`1322-1373` 有完整弹层与 25/15/5 预设、Start/Pause/Reset）。补齐持久化的工作量远小于砍掉再重做，因此 3.0 **做**，并计入学习时长。

| 字段 | 类型 | 取值 / 默认 | 校验 / 异常 |
|---|---|---|---|
| `preset` | `25 \| 15 \| 5`（分钟） | 默认 `25` | 只接受这三个值；其他值回落 `25` |
| `startedAt` | ISO 8601 UTC | — | 运行中必填 |
| `endsAt` | ISO 8601 UTC | `startedAt + preset` | — |
| `pausedAt` | ISO 8601 UTC \| `null` | `null` | 暂停时写入，恢复时清空并顺延 `endsAt` |
| `remainingSeconds` | 整数 ≥ 0 | `preset × 60` | 从 `endsAt - now` 现算，不信任缓存值 |
| `completedSessions` | 整数 ≥ 0 | `0` | 当日计数，跨自然日归零 |

**3.0 需求：**

1. **持久化**：状态写 `localStorage` 键 `system-pomodoro-v1`；关闭弹层、切页、刷新、切到其他 App 后回来，倒计时按 `endsAt - now` 继续，不重置。
2. **跨页存活**：番茄钟运行中，在 `/apps` 工具栏图标上显示剩余时间小徽标；离开 `/apps` 后仍在跑。
3. **结束提示**：倒计时到 0 时弹一次轻量提示 + 一次短震动（`navigator.vibrate(200)`，不可用则静默）。**不用夸张音效或卡通动画**（游戏化不儿童化）。
4. **计入学习时长**：一个完整番茄钟（未中途 Reset）上报一次 `pomodoro_complete` 事件，`durationSeconds = preset × 60`，进入学习报告的「学习时长」（事件名与 `06` 对齐，[待确认]）。中途 Reset 不计。
5. **与屏幕时间冲突**：若家长控制的当日配额在番茄钟运行中耗尽，按第四章 4.6 的宽限规则处理——**不允许**番茄钟延长配额。

#### 2.3.4 Day Countdown

| 字段 | 类型 | 取值 / 默认 | 校验 / 异常 |
|---|---|---|---|
| `targetDate` | `YYYY-MM-DD` | 默认 = 今天 + 30 天 | 正则 `^\d{4}-\d{2}-\d{2}$`；不合法时回落默认值 |
| `label` | 字符串 ≤ 24 字符 | 默认 `"My exam"` | **3.0 新增**，现状无标签 |
| `daysLeft` | 整数 ≥ 0 | 现算 | 目标日已过时显示 `0`，并提示「重设目标日」而不是显示负数 |

**3.0 需求**：目标日的默认值改为——若用户在开机向导 Step 5 选了 HSK 路径，默认标签取 `"HSK {level} exam"`；未选则 `"My goal"`。目标日支持从 `/hsk-test` 页反向设置（该链路属域 C，本篇只定接口）。

#### 2.3.5 工具栏编辑模式

| 触发 | 行为 |
|---|---|
| 长按任一工具图标（≥ 500 ms） | 进入编辑模式：全部工具图标 `scale(0.96)`、`opacity 0.88`，右上角出现删除角标，首位出现黑色「Done」键 |
| 右键 / 上下文菜单 | 同长按（供桌面调试；触屏无此路径） |
| 编辑模式下轻点工具本体 | **不触发**工具功能（`showDelete` 早退） |
| 点删除角标 | 从工具栏移除该项并立即持久化 |
| 点「Done」 | 退出编辑模式 |
| 点「+」 | 退出编辑模式并打开「Add System Tools」弹层 |

**3.0 需求（补现状缺口）：**

#### 2.6.2 3.0 需求 · 能力分层

护眼是**两层能力**，必须分清，否则会出现「开了护眼但离开 App 就没有」的用户投诉。

| 层 | 能做到 | 做不到 | 需要的安卓权限 | 用户授权时机 |
|---|---|---|---|---|
| **Web 层**（WebView 内） | 全屏 `position: fixed` 暖色遮罩层（`pointer-events: none`，`z-index` 高于全部业务层，`mix-blend-mode: multiply`）+ 主题变量降低纯白亮度 + 20-20-20 在 App 内的计时与提示 | ① 覆盖不到系统状态栏、导航栏与其他 App；② **不降低背光物理输出**，只是内容偏黄，蓝光实际强度不变；③ 全屏 `<video>` 的合成层可能盖在遮罩之上；④ 截图会带上暖色 | 无 | 不需要 |
| **原生层** | ① 系统级夜览（真实色温位移，全局生效）；② 背光亮度调节；③ 系统级定时开关；④ 离开 C-LingoAIOS 后仍生效 | — | ① `WRITE_SETTINGS`（特殊权限，需 `Settings.System.canWrite()` 判定 + 引导 `Settings.ACTION_MANAGE_WRITE_SETTINGS` 让用户在系统设置里授予）；② 若要遮罩覆盖其他 App，需 `SYSTEM_ALERT_WINDOW`（引导 `Settings.ACTION_MANAGE_OVERLAY_PERMISSION`）；③ 系统夜览 API（`ColorDisplayManager`）是 `@SystemApi`，**只有 C-LingoAIOS 以系统应用 / Device Owner 身份预置时可用** | 用户在护眼二级页把生效范围从「Inside C-LingoAIOS」切到「Whole device」时，**才**弹权限说明并跳系统授权页。不在开机向导里预先索要 |

**分层结论**：

- **默认档 = Web 层**，零权限、开箱可用，文案必须诚实写「Inside C-LingoAIOS」。
- **进阶档 = 原生层**，用户主动选「Whole device」才申请权限；权限被拒或系统 API 不可用时，**自动回落到 Web 层并明示原因**，不留开着但无效的开关。
- 若第九章决策走 **Path A（C-LingoAIOS 作为 launcher / Device Owner）**，原生层为默认可用，默认档可直接升到「Whole device」。

#### 2.7.3 缺陷 S2b · Alarm 加了等于没加

**现状基线**：`utilityBarConfig.ts` 的读取函数硬过滤掉 `alarm`：

```17:28:local-agent-app/src/data/utilityBarConfig.ts
const STORAGE_KEY = 'apps-builtin-utilities-v1';
const DEFAULT_IDS: BuiltinUtilityId[] = ['calendar', 'daycountdown', 'pomodoro'];

export function loadBuiltinUtilityIds(): BuiltinUtilityId[] {
  if (typeof window === 'undefined') return [...DEFAULT_IDS];
  try {
    const raw = window.localStorage.getItem(STORAGE_KEY);
    if (!raw) return [...DEFAULT_IDS];
    const parsed = JSON.parse(raw) as unknown;
    if (!Array.isArray(parsed)) return [...DEFAULT_IDS];
    return parsed.filter((id): id is BuiltinUtilityId =>
      typeof id === 'string' && id !== 'alarm' && BUILTIN_UTILITY_ITEMS.some((item) => item.id === id)
    );
```

而 `BUILTIN_UTILITY_ITEMS` 仍把 `alarm` 列在目录里，`toggleBuiltinUtility('alarm')` 会把 `'alarm'` 写进 `localStorage` 并返回包含它的数组，页内 state 立刻显示 Alarm 图标——但下一次读取（切页回来、刷新）就被过滤掉。用户体验是：**Add 之后显示已添加，过一会儿自己消失。**

**3.0 需求**：二选一，不许并存。

- 若 Alarm 按 2.3.1 改为跳系统时钟 → **删掉 `id !== 'alarm'` 这个过滤条件**，让它正常参与增删。
- 若决定不要 Alarm → **从 `BUILTIN_UTILITY_ITEMS` 里删除该条目**，目录里不再出现。

2. **日期做语义校验**。`targetDate` 除正则外还要 `Number.isFinite(new Date(...).getTime())` 判定，非法值回落默认并在弹层提示 `Invalid date — reset to default`。
3. **写失败可感知**。`localStorage` 写入可能因配额满或隐私模式抛异常，现状全部裸调 `setItem` 无 `try/catch`（`exploreAppsConfig.ts:41`、`utilityBarConfig.ts:37`、`systemToolsCatalog.ts:59,77`、`appsCatalog.ts:54`）。3.0 必须包 `try/catch`，失败时保留页内 state 并提示 `Couldn't save — device storage is full`，引导去 `/system/content-cache`。
4. **多标签页/多 WebView 一致性**。现状靠 `window` 的 `focus` 事件重读（`AppsPage.tsx:544-553`），漏掉同窗口内的其他修改路径。3.0 改为监听 `storage` 事件 + 保留 `focus` 兜底。
5. **不受清数据保护**。这 5 个键是 UI 偏好，清浏览器数据后回落默认是**可接受的**（与 `AGENTS.md`「清除浏览器数据 = 新设备」一致）。**但家长控制的状态绝不能放在这一类存储里**，见 4.7。

#### GWT · 配置存储

### 3.3 缺陷 S11 · 3.0 需求：统一用户档案模型

#### 3.3.1 单一数据源

新增 `localStorage` 键 **`clingo-user-profile-v1`** 作为用户档案的**唯一权威来源**。开机向导写它，`/profile` 读它，`/profile/edit` 改它，顶栏头像读它。

`clingo-onboard-profile-v1` 降级为**向导的一次性输出**，仅用于首启迁移，之后不再被任何页面直接读取。

```text
开机向导 Step 0/2/3/5 完成
  ↓ writeOnboarded(profile)
clingo-onboarded-v1 = '1'
clingo-onboard-profile-v1 = { path, localeId, email, nickname, dob, gender, avatar, wifiId, hskLevel }

clingo-user-profile-v1  ← 唯一权威来源
```

#### 3.3.3 API 契约（`onboarding/userProfileStorage.ts`，新增）

现状 `onboardingStorage.ts` 只有 `writeOnboarded` / `readOnboarded` / `clearOnboarded`，**没有 `readProfile`**，所以 Profile 页根本读不到向导数据。3.0 必须补齐：

| 函数 | 签名 | 行为 | 异常 |
|---|---|---|---|
| `readUserProfile()` | `() => UserProfile` | 读 `clingo-user-profile-v1`；不存在时尝试从 `clingo-onboard-profile-v1` 迁移；迁移源也不存在时返回默认档案 | 解析失败 → 返回默认档案，**不抛异常** |

| `subscribeUserProfile(cb)` | `(cb: (p: UserProfile) => void) => () => void` | 监听 `storage` 事件与同窗口写入，供顶栏头像与 Profile 页实时同步 | — |

#### 3.3.5 `dob` 变更的联动

修改 `dob` 会改变 `ageTier`，从而可能改变内容分级与家长控制策略。3.0 规则：

1. `dob` 变更导致 `ageTier` **降低**（例如从 `16to17` 变为 `under13`）时，内容分级立即收紧到新等级的默认策略。
2. `dob` 变更导致 `ageTier` **升高**时，若家长控制已启用，变更需 **PIN 验证**——否则学习者只要把生日改大就能解除限制，家长控制形同虚设。
3. 家长控制未启用时，`dob` 可自由修改。

### 3.4 缺陷 S12 · 3.0 需求：学习报告数据口径

#### 3.4.1 数据来源的唯一性约束

**硬约束**：学习报告**只消费 `06-非功能需求.md` 第五节定义的同一套埋点事件**，不得自建第二套统计逻辑。这条是因为 `00-总纲` 已把「埋点与指标体系」列为 P0 新增需求，如果 Profile 自己再数一遍，两处口径必然漂移，KPI 就没法验收。

一期**无账号体系、无跨设备同步**（`AGENTS.md` 一期禁令），所以：

- 事件既**本地落盘聚合**（供学习报告即时展示），又**上报后端**（供 KPI 分析）。
- 本地聚合结果存 IndexedDB（非 `localStorage`，因为要存 90 天的日粒度明细），库名 `clingo-metrics`，表 `daily_rollup`。
- 清除浏览器数据 = 学习报告归零。这是一期设计，**不是 bug**，与匿名设备身份的设计一致。

#### 3.4.2 三块指标的计算口径

| 板块 | 指标 | 口径 | 数据源事件 | 一期是否做 |
|---|---|---|---|---|
| **① 学习时长统计** | 累计有效学习时长 | Σ 有效学习会话时长。**有效**定义：应用在前台（`document.visibilityState === 'visible'`）且 30 秒窗口内有过至少一次用户交互（触摸 / 键入 / 音频播放）。超过 30 秒无交互的时间段**不计入** | `session_start` / `session_heartbeat`（30 s 一次）/ `session_end` | ✅ |
| | 本周增量 | 最近 7 个自然日（含今天）之和 − 前 7 个自然日之和 | 同上 | ✅ |
| | 7 日柱图 | 每个自然日的有效学习时长，按设备本地时区切日 | 同上 | ✅ |
| | 番茄钟时长 | 完整番茄钟按 `preset × 60` 秒计入，**与会话时长去重**（同一时间段不双计） | `pomodoro_complete` | ✅ |
| **② 做题准确率分析** | 首答正确率 | 首次提交正确的题数 ÷ 首次提交的总题数。**只算首答**，重做不计入分子分母 | `question_answer`（带 `isFirstAttempt`、`isCorrect`、`questionType`） | ✅ |
| | 按题型拆分 | 同上，按 `questionType` 分组。HSK 域用 `L01`…`W02` 九种；教材域用自己的题型码 | 同上 | ✅ |
| | 示例题排除 | `isExample === true` 的子题**一律不计入**（与 `03` 的不计分规则一致） | 同上 | ✅ |
| | 错题趋势 | 最近 7 日每日首答正确率 | 同上 | ⚠️ 一期简化：只出总正确率 + 按题型 Top 3 最弱项，不出趋势线 |
| **③ 学习效率分析** | 每有效学习小时完成题数 | 首答题数 ÷ 有效学习小时数 | 上两者 | ✅ |
| | 单题平均耗时 | Σ 单题作答耗时 ÷ 首答题数，按题型分组 | `question_answer.durationMs` | ✅ |
| | 新掌握词数 | 达到「掌握」判定的词数。**掌握**定义 [待确认]：建议「同一词在 3 次不同会话中首答正确」 | `vocab_mastered` | ⚠️ 一期简化：先用「已学习词数」（出现过即计），口径在 UI 上明确标 `words seen`，不叫 `mastered` |
| | 连续学习天数 | 连续有有效学习时长 > 5 分钟的自然日数 | `session_*` | ✅ |

**第一代简化结论**（用户规则「第一代可简化，后续迭代优化」）：

- 三个板块**都要有**，但每块只出 2–3 个数 + 一个 7 日柱图。
- 柱图 metric toggle 必须真的换数据：`time` → 每日有效学习分钟数；`accuracy` → 每日首答正确率。**现状的 `vocab` 换成 `accuracy`**，因为「做题准确率分析」是产品规则明确要求的三块之一，词汇量不是。
- 不做「学习效率评分」这类合成分——没有基线数据，合成分只会误导。

## 四、家长控制与青少年合规（本篇重点章节）

### 为什么这是本篇最重的一章

三件事叠在一起，构成一个必须在 3.0 内闭环的合规缺口：

1. **目标用户明确含未成年人**。`00-总纲` 写 12 岁以上、主力 13–19 岁，87% 在 HSK1 水平。
2. **产品已经在向用户承诺儿童隐私保护**。开机向导 Step 2 的 TOS 勾选项里包含 **Children's Privacy Policy**（`OnboardingFlow.tsx:497-503` 的 `onboard.tos` 带 `kids` 插槽）。用户勾了这个框，就是收到了一个承诺。
3. **家长控制目前完全没有实现**。`/parental-controls` 是纯占位 UI：4 个 Switch 加一组 1–4h 屏幕时间选择，**无保存、无 PIN、无任何 enforcement**，而且**没有任何 UI 入口能进到这一页**。

结果是：产品声明保护儿童，代码里一行保护措施都没有。这在任何一次合规审查或客户尽调中都是硬伤。

### 4.1 现状基线 · `/parental-controls`

| 控件 | 现状 | 持久化 | enforcement |
|---|---|---|---|
| Daily Screen Time（Switch） | `useState(true)`（`ParentalControlsPage.tsx:17`） | ❌ | ❌ |
| 屏幕时间小时数（1/2/3/4h 四选一） | `useState(2)`（`:18`），开关开启时才显示（`:50-71`） | ❌ | ❌ |
| Content Filter（Switch） | `useState(true)`（`:19`） | ❌ | ❌ |
| App Lock（Switch） | `useState(false)`（`:20`） | ❌ | ❌ |
| PIN Protection（Switch） | `useState(true)`（`:21`） | ❌ | ❌ · **没有任何 PIN 输入、设置或校验代码** |
| 页面入口 | **无**。全仓库仅 `App.tsx:178` 注册路由、`MainLayout.tsx:99` 做布局判断 | — | — |
| 返回 | `resolveBackPath(location, …)`，兜底 `/apps` | — | — |

另有一条重要事实：向导 Step 3 收集的 `dob`（生日）**目前未被任何逻辑使用**——既不做年龄分级，也不影响任何内容可见性。

### 4.2 3.0 需求 · 身份模型：学习者态 vs 家长态

家长控制的第一性问题是**谁在操作这台平板**。一期无账号体系（`AGENTS.md` 禁令），所以不能用登录区分身份，只能用 **PIN 门禁的临时会话**区分。

| 态 | 进入方式 | 权限 | 退出 |
|---|---|---|---|
| **学习者态**（默认） | 开机默认 | 学习全功能；可看家长控制的**只读摘要**；不能改任何家长控制项；不能安装 App；不能改 `dob`（家长控制开启时） | — |
| **家长态** | 在 `/parental-controls` 输入正确 PIN | 可改全部家长控制项、审批安装请求、改 `dob`、改激活邮箱、关闭家长控制 | ① 主动点「Exit parent mode」；② **闲置 5 分钟**自动退出；③ 离开 `/parental-controls` 及其子页超过 60 秒自动退出；④ 应用进入后台自动退出 |

**关键设计点**：家长态是**页面级临时会话**，不是全局登录态。这样即使家长忘了退出，5 分钟后也会自动关上，孩子拿到平板不会直接获得管理员权限。

**家长态会话不落盘**，只存内存。刷新即失效。

### 4.3 3.0 需求 · 家长控制总开关与首次设置流程

```text
学习者在 /apps → System settings → Parental Controls
  ↓
家长控制未启用？
  ├─ 是 → 引导页「Set up Parental Controls」
  │        ├─ 说明将限制什么（屏幕时间 / 内容分级 / 应用安装）
  │        ├─ Step 1：设置 6 位 PIN（输两遍，不一致则重来）
  │        ├─ Step 2：展示一次性恢复码（12 位，分 3 组 4 位），要求用户抄下并勾选
  │        │           「I have saved this recovery code」才能继续
  │        ├─ Step 3：按 ageTier 预置默认策略，家长可调整
  │        └─ 完成 → 落盘，回到 /parental-controls 的家长态视图
  │
  └─ 否 → PIN 输入面板
           ├─ 正确 → 进入家长态，展示可编辑的全部策略
           └─ 错误 → 计数 +1，按 4.4 的锁定规则
```

**学习者态下的只读摘要**：不需要 PIN 就能看到「今天还剩多少时间」「内容分级是哪一档」。这是有意设计——让孩子知道规则，比让规则神秘化更有效，也避免孩子把配额耗尽时一脸困惑。**只读摘要不显示 PIN、不显示恢复码、不显示可修改的控件。**

### 4.4 3.0 需求 · PIN 设置、校验与找回

#### 4.4.1 PIN 规格

| 项 | 规格 | 理由 |
|---|---|---|
| 长度 | **6 位纯数字** | 4 位在安卓平板上被暴力试出的成本太低（1 万种组合，孩子有整晚时间）；6 位是 100 万种。不用字母密码，因为家长在平板上输入字母密码体验差 |
| 弱 PIN 拒绝 | 拒绝：① 6 位全相同（`111111`）；② 连续递增/递减（`123456`、`654321`）；③ 等于设备激活 SN 后 6 位；④ 等于 `dob` 的 `YYYYMM` 或 `DDMMYY` 组合 | 孩子最先试的就是自己生日 |
| 输入界面 | 自绘 6 格数字键盘，**每键 ≥ 72×72 dp**（食指指腹 + 家长可能站着单手操作）；不用系统软键盘（避免键盘记录与自动填充） | — |
| 显示 | 输入时显示 6 个圆点，已输入的填实；提供「显示 PIN」长按键（松手即隐藏） | — |

#### 4.4.2 PIN 存储（安全要求）

**绝不明文存储 PIN。** 存储的是派生值：

| 字段 | 内容 | 说明 |
|---|---|---|
| `pinHash` | Base64 | PBKDF2-HMAC-SHA256(`pin`, `salt`, `iterations`, 32 字节) |
| `salt` | Base64，16 字节 | 每台设备首次设置 PIN 时用 `crypto.getRandomValues()` 生成 |
| `iterations` | 整数 | ≥ `210000`（2024 年 OWASP 对 PBKDF2-SHA256 的建议下限），[待确认] 实机性能后定档 |
| `recoveryCodeHash` | Base64 | 同算法对恢复码派生；恢复码本身**只在设置时展示一次**，不落盘 |
| `algo` | 字符串 | `'PBKDF2-SHA256'`，便于后续算法升级 |

**存储位置（关键）：**

- Web 层用 `crypto.subtle.deriveBits` 计算，结果**不得**存在 `localStorage`——`localStorage` 会被「清除浏览器数据」清掉，等于孩子清一下数据就解除家长控制。
- **必须存在原生层**：Android `EncryptedSharedPreferences`（AndroidX Security，主密钥存 Android Keystore），通过原生桥 `secureStore.set/get` 读写。
- **但必须放在独立 APK 里（按 `07` 第七节评审纠正 5 修订）**：`EncryptedSharedPreferences` 位于**应用私有目录**，系统设置里的「清除数据」会**连同它一起删掉**——所以「清数据后仍保持锁定」这个要求在无 Device Owner 时**根本不成立**，加密与否都不影响这一点。正确做法是把 `pinHash`、`failedAttempts`、`lockedUntil`、配额计数落到 **`com.nsk.parental` 这个独立 APK**（同签名 + 权限保护的 `ContentProvider`）：清除 C-LingoAIOS 的数据不会影响它。**这条不需要 Device Owner，且可以后补**——是整个家长控制方案里唯一不依赖 Q34 / Q74 裁决的关键项。
- **计时基准**：配额计时统一用 `elapsedRealtime`（单调时钟），**不用墙上时间**，否则改系统时间即可绕过。
- 若原生桥不可用（H5 单跑 / 浏览器调试），家长控制整体降级为**只读演示态**，页面顶部横幅明示 `Parental controls require the C-LingoAIOS device runtime`，全部控件禁用。**不允许**在无原生桥时假装启用。

#### 4.4.3 错误次数与锁定

| 累计连续错误 | 处置 |
|---:|---|
| 1–4 | 提示 `Incorrect PIN · {n} of 5 attempts` |
| 5 | 锁定 **60 秒**，倒计时显示 |
| 6 | 锁定 **120 秒** |
| 7 | 锁定 **300 秒** |
| 8 及以上 | 锁定 **900 秒**（15 分钟，上限不再翻倍） |

- 连续错误计数与锁定截止时刻**存在原生安全存储**，重启应用、重启设备、清浏览器数据均不重置。
- 输入一次正确 PIN 后计数归零。
- 锁定期间「使用恢复码」入口仍可用（恢复码有独立的错误计数，规则相同）。

#### 4.4.4 PIN 找回（两条通道）

| 通道 | 流程 | 一期可用性 |
|---|---|---|
| **恢复码**（主通道） | 在 PIN 面板点「Forgot PIN」→ 输入 12 位恢复码 → 校验通过后**强制重设新 PIN** 并生成新恢复码（旧码失效） | ✅ 一期可用，**不依赖任何后端** |
| **激活邮箱**（备通道） | 向向导 Step 2 填的邮箱发一次性重置码，有效期 15 分钟，单设备 24 小时内最多 3 次 | ❌ **一期不做**。理由：`AGENTS.md` 明确 HSK 后端没有任何线上环境，也没有邮件服务；做一个发不出邮件的找回入口就是第二个死按钮。3.0 在 UI 上**不展示**这个入口 |
| **厂商重置**（兜底） | 恢复码也丢了 → 联系售后，凭设备 SN + 购买凭证由客服签发一次性重置令牌 | ⚠️ [待确认]：需要客服流程与令牌签发服务，属运营侧。3.0 的 UI 只需给出一句 `Contact support with your device serial number` 与 SN 展示 |

### 4.5 3.0 需求 · 内容分级与 `dob` 联动

#### 4.5.1 年龄档划分

由 `clingo-user-profile-v1.dob` 现算。`dob` 缺失时保守取 `'13to15'`。

| `ageTier` | 年龄 | 划分理由 |
|---|---|---|
| `under13` | < 13 岁 | COPPA 在美国以 13 岁为界；产品目标用户声明 12 岁以上，所以这一档是**声明外用户**，必须最严 |
| `13to15` | 13–15 岁 | GDPR 各成员国的数字同意年龄在 13–16 岁间浮动；英国 AADC 把 13–15 列为独立档 |
| `16to17` | 16–17 岁 | 多数辖区已可自主同意，但仍是未成年人 |
| `adult` | ≥ 18 岁 | — |

> **[待确认] 法规适用范围**。本节的分档与默认策略是**产品侧的保守设计**，不是法律意见。需法务就以下各项逐一确认：
> - 美国 **COPPA**：< 13 岁需可验证的家长同意（verifiable parental consent）。当前开机向导只是一个 TOS 勾选框，**不构成**可验证家长同意。若产品会被 < 13 岁用户使用，需要补真正的同意机制（信用卡验证、家长邮箱回执、视频通话等），或在产品层**明确拒绝** < 13 岁注册。
> - 欧盟 **GDPR** 第 8 条 + 各成员国的数字同意年龄（13–16 不等）。
> - 英国 **Age Appropriate Design Code**（儿童适龄设计准则）15 项标准，含默认高隐私、数据最小化、关闭画像推送等。
> - 东南亚：泰国 **PDPA**、马来西亚 **PDPA**、越南 **PDPD**、印尼 **PDP Law**。
> - 阿联酋 **Federal Decree-Law No. 45 of 2021 (PDPL)** 与迪拜本地规则。
> - 三项当前实际收集的数据是否触发上述法规的同意要求：`email`（激活邮箱）、`dob`（生日）、`gender`（性别）、`nickname`（昵称）。**数据最小化审查建议**：`gender` 对中文学习没有功能价值，只用于 Profile 上一枚徽章——建议 3.0 直接**移除性别字段**，这是成本最低的合规改善。若业务侧坚持保留，需给出保留理由并记入隐私政策。

| 策略项 | `under13` | `13to15` | `16to17` | `adult` |
|---|---|---|---|---|
| 家长控制默认状态 | **强制开启**，不可关 | 默认开启，可关（需 PIN） | 默认关 | 默认关 |
| 每日屏幕时间 | 1 h | 2 h | 3 h | 无限制 |
| 宵禁时段 | 20:00–07:00 | 21:00–06:30 | 22:00–06:00 | 无 |
| AI 口语对话（`/ai-chat`） | 仅场景模式，**Free Chat 关闭** | 全开，含内容安全过滤 | 全开 | 全开 |
| Camera 拍照翻译 | 开 | 开 | 开 | 开 |
| 第三方 App 安装 | **禁止** | 需家长审批 | 需家长审批 | 允许 |
| 已安装第三方 App 启动 | **禁止** | 允许（白名单内） | 允许 | 允许 |
| 浏览器类 App（Chrome 等） | **禁止** | 需家长审批 | 允许 | 允许 |
| 外链跳出 | 禁止 | 需家长审批 | 允许 | 允许 |

**`under13` 的强制开启**：当 `dob` 计算出 < 13 岁时，家长控制被强制打开且总开关置灰不可关。这是对「产品声明 12 岁以上」与「实际有更小用户」之间落差的最低限度兜底。此时页面显示说明 `Parental controls are required for users under 13`。

#### 4.5.3 AI 对话的内容安全

`/ai-chat` 的 Free Chat 允许用户自定义场景，这是内容风险最高的点（属域 D，本篇只定策略接口）：

| 层 | 要求 |
|---|---|
| 输入侧 | 用户自定义场景文本与对话输入送模型前，过一道内容安全检查；命中则拒绝并提示，不把原文送出 |
| 输出侧 | 模型返回内容过一道检查；命中则不渲染，改显示 `Let's talk about something else` 并换一个学习话题 |
| 策略来源 | 严格度由 `ageTier` 决定；`under13` 直接关闭 Free Chat |
| 供应商 | [待确认]。与 `00-总纲` R7「AI 评分能力未选型」同一个决策，内容安全应与评分能力一并选型 |

### 4.6 3.0 需求 · 屏幕时间

#### 4.6.1 字段

| 字段 | 类型 | 取值 | 默认 | 校验 |
|---|---|---|---|---|
| `screenTime.enabled` | 布尔 | — | 按 `ageTier` | — |
| `screenTime.dailyMinutes` | 整数 | `30 \| 60 \| 90 \| 120 \| 180 \| 240`（6 档，比现状的 1/2/3/4h 多出 30 min 与 90 min） | 按 `ageTier` | 非枚举值 → 回落该档默认 |
| `screenTime.scope` | `'learning' \| 'device'` | `learning` = 只算 C-LingoAIOS 内的有效学习时长；`device` = 算整机前台时长 | `'learning'` | `'device'` 需原生 `UsageStatsManager` 授权；无授权时回落 `'learning'` 并明示 |
| `screenTime.curfew.enabled` | 布尔 | — | 按 `ageTier` | — |
| `screenTime.curfew.start` / `.end` | `HH:mm` | — | 按 `ageTier` | 允许跨零点 |
| `screenTime.weekendMultiplier` | 数字 | `1.0 \| 1.5 \| 2.0` | `1.5` | 周六日的配额 = `dailyMinutes × multiplier` |
| `screenTime.graceMinutes` | 整数 | `0 \| 5 \| 10` | `5` | 配额耗尽后允许完成当前活动的宽限时长 |
| `screenTime.consumedToday` | 整数（秒） | 派生 | `0` | 按设备本地时区在自然日 00:00 归零 |

#### 4.6.2 消耗与拦截逻辑

1. **消耗口径 = 与学习报告同一套「有效学习时长」**（3.4.2）。不能一个按墙上时间、一个按有效交互，否则孩子会发现「挂着不动就不扣时间」这种漏洞，或者反过来抱怨「我没在用也在扣」。
2. **剩余时间提示**：剩 10 分钟、5 分钟各弹一次轻量横幅。剩 1 分钟时在顶栏常驻一个倒计时。
3. **配额耗尽**：
   - **不立刻黑屏**。进入 `graceMinutes` 宽限期，允许完成当前活动。
   - 宽限期内：**HSK 作答中的 `attemptId` 不被强制中断**（与 `03` 的作答生命周期冲突会造成数据损坏）。按 `03` 的既有规则处理——进入宽限期要停当前音频并用播放代次令牌阻止旧 `play()` 回来，但不作废 `attemptId`。
   - 宽限期结束：跳到全屏「Time's up」页，显示明日配额恢复时间与「Ask parent for more time」按钮（点击后进 PIN 面板，家长可授予一次性 15/30/60 分钟延时）。
4. **宵禁**：宵禁时段内进入应用，直接落「Time's up」页的宵禁变体，文案 `Available again at {end}`。宵禁与配额独立——宵禁内即使配额有剩也不可用。
5. **家长一次性延时**：家长态下授予的延时记为 `bonusMinutesToday`，当日有效，次日归零。每日最多授予 2 次（防止「问一次给一次」变成无限）。

#### 4.6.3 enforcement 分层（必须写清）

| 能力 | Web 层能做到 | 必须原生层做 | 安卓权限 | 用户授权时机 |
|---|---|---|---|---|
| 统计 C-LingoAIOS 内有效学习时长 | ✅ `visibilitychange` + 交互心跳 + 每 30 秒持久化 | — | 无 | — |
| 统计整机（含其他 App）前台时长 | ❌ 完全拿不到 | ✅ `UsageStatsManager.queryUsageStats` | `android.permission.PACKAGE_USAGE_STATS`（**特殊权限**，不能用 `requestPermissions`，必须引导用户到 `Settings.ACTION_USAGE_ACCESS_SETTINGS` 手动开启） | 家长在家长态把 `screenTime.scope` 切到 `device` 时 |
| 在 C-LingoAIOS 内拦截（跳「Time's up」页） | ✅ 路由守卫 + 全屏覆盖层 | — | 无 | — |
| 阻止孩子退出 C-LingoAIOS 去用别的 App | ❌ | ✅ LockTask / kiosk 模式：`DevicePolicyManager.setLockTaskPackages` + `Activity.startLockTask` | 需 **Device Owner** 身份（出厂预置，见第九章） | 无需运行时授权（Device Owner 天然具备） |
| 禁用/隐藏特定第三方 App | ❌ | ✅ `DevicePolicyManager.setPackagesSuspended` 或 `setApplicationHidden` | 需 **Device Owner** | 同上 |
| 宵禁到点自动拦截（应用未在前台时） | ⚠️ 只能等用户下次打开时判断 | ✅ `AlarmManager.setExactAndAllowWhileIdle` + 前台服务 | `SCHEDULE_EXACT_ALARM`（Android 13+）、`POST_NOTIFICATIONS`（Android 13+ 通知） | 首次开启宵禁时 |
| 重启后策略仍生效 | ⚠️ 依赖用户再次打开应用 | ✅ `BOOT_COMPLETED` 广播接收器 | `android.permission.RECEIVE_BOOT_COMPLETED`（普通权限，清单声明即可） | 无需运行时授权 |
| 抵抗「清除应用数据」绕过 | ❌ `localStorage` 会被清空。**`EncryptedSharedPreferences` 同样会被清掉**（在应用私有目录，加密不影响这一点） | ✅ **状态落 `com.nsk.parental` 独立 APK**（同签名 + 权限保护的 `ContentProvider`）；DO 下还可 `setUninstallBlocked` + `DISALLOW_APPS_CONTROL` | **独立 APK 方案不需要 DO，且可后补**——见 4.4.2 修订 | 无需运行时授权 |
| 抵抗改系统时间绕过 | ✅ **配额计时用 `elapsedRealtime` 单调时钟即可**，与墙上时间无关 | ✅ 再加 `addUserRestriction(DISALLOW_CONFIG_DATE_TIME)` | 单调时钟不需要任何权限 | 无需运行时授权 |
| 抵抗 ADB 绕过（`adb shell pm clear`） | ❌ **一根 USB 线即可清掉家长控制** | ✅ 需一整组限制：`DISALLOW_DEBUGGING_FEATURES`、`DISALLOW_FACTORY_RESET`、`DISALLOW_SAFE_BOOT`、`DISALLOW_ADD_USER`，且 **bootloader / recovery 必须锁** | 需 **Device Owner** + 产线锁 bootloader | 同上 |

**最重要的一条结论**：**没有 Device Owner，屏幕时间就只是一个建议。** 孩子可以退出 C-LingoAIOS 去玩别的、可以用 ADB 清掉状态。所以第九章的 launcher / Device Owner 决策**不是一个 P2 的皮肤问题，它是家长控制能否成立的前提**。

> **但上表有两行已被评审下调（`07` 第七节纠正 5）**：「抵抗清除数据」用 `com.nsk.parental` 独立 APK 即可，「抵抗改系统时间」用 `elapsedRealtime` 单调时钟即可——**这两项都不需要 Device Owner，且都可以后补**。真正只有 DO 能做的是 LockTask、禁用第三方 App、禁 ADB 这三类。
>
> 另有两条评审补充的事实：① **DO 拿不到 `signature|privileged` 权限**，所以 2.6.2 写的「Path A 原生层默认可用」对系统级夜览（需 `WRITE_SECURE_SETTINGS`）**不成立**；② 若掌握 ROM，**平台签名 priv-app 的能力比 DO 更强且可随 OTA 补装**（`07` **Q74**）。③ 宵禁在前台服务之外还需**电池优化白名单与 OEM 自启**——小米 / OPPO / vivo / 传音会杀掉前台服务，无 DO 时必须能在下次前台补算。

3.0 的处置：

- **Path A（Device Owner）可用** → 全部 enforcement 生效，`screenTime.scope` 可选 `device`。
- **Path A 不可用** → 家长控制以 Web 层能力交付，并在设置页顶部常驻一条诚实说明：`Limits apply inside C-LingoAIOS only`。**不允许**在 UI 上暗示能管住整台设备。

### 4.7 3.0 需求 · 数据模型与存储位置

家长控制的存储是本篇唯一**不允许**放 `localStorage` 的数据。

| 数据 | 存储位置 | 理由 |
|---|---|---|
| `pinHash`、`salt`、`iterations`、`recoveryCodeHash`、`failedAttempts`、`lockedUntil` | **原生 `EncryptedSharedPreferences`**（主密钥在 Android Keystore） | 必须抗「清除应用数据」；且是凭据类数据 |
| 策略配置（屏幕时间、内容分级、白名单、宵禁） | **原生 `EncryptedSharedPreferences`**，Web 层通过桥读写 | 同上 |
| `consumedToday`、`bonusMinutesToday` | **原生**，每 30 秒从 Web 层同步一次 | 抗绕过；且需要在应用未运行时也能被宵禁服务读到 |
| 家长态会话 | **仅内存** | 不落盘，刷新即失效 |
| 学习者态只读摘要的展示缓存 | `localStorage` 可用（只是展示） | 被清掉也无安全影响，下次从桥重读 |

**桥接口**（详见第十章）：`parentalStore.read()` / `parentalStore.write(patch)` / `parentalStore.verifyPin(pin)` / `parentalStore.setPin(pin, recoveryCode)` / `parentalStore.consumeTime(seconds)`。

**PIN 校验必须在原生层完成**，Web 层只传候选 PIN、收布尔结果。原因：如果把 `pinHash` 和 `salt` 交给 Web 层比对，任何能打开 WebView DevTools 的人都能拿到 hash 离线爆破，而 6 位数字的 100 万种组合离线爆破是分钟级的。

### 4.8 3.0 需求 · 应用白名单与安装审批

| 项 | 规则 |
|---|---|
| 白名单粒度 | 按 `packageName` |
| 默认白名单 | C-LingoAIOS 自身 + NSK 产品套件（`com.nsk.clingo`、`com.nsk.scanpen`、`com.nsk.pinyin`、`com.nsk.launcher`、`com.nsk.parental`）+ 系统必需（设置、时钟、文件、计算器） |

### 4.9 GWT · 家长控制

**GWT-E-25 入口存在且需 PIN**
- **Given** 家长控制已启用，PIN 已设置，用户处于学习者态
- **When** 用户在 `/apps` → System settings 点击 `Parental Controls`
- **Then** 进入 `/parental-controls`；页面上半显示只读摘要（今日剩余时间、当前内容分级档）；下半为 PIN 输入面板；**全部策略控件处于禁用态且不显示当前具体数值以外的可编辑项**

**GWT-E-26 首次设置 PIN**
- **Given** 家长控制从未启用，`clingo-user-profile-v1.dob` 对应 `ageTier = '13to15'`
- **When** 家长点击 `Set up Parental Controls`，输入 PIN `481937` 两次一致，抄下恢复码并勾选确认

**GWT-E-27 弱 PIN 被拒**
- **Given** 家长处于 PIN 设置流程，用户生日为 `2010-05-14`
- **When** 家长依次尝试 `111111`、`123456`、`201005`
- **Then** 三次均被拒绝，分别提示 `PIN can't be all the same digit`、`PIN can't be a sequence`、`PIN can't be based on your birthday`；均不落盘

**GWT-E-28 错误锁定跨重启存活**
- **Given** 家长控制已启用
- **When** 学习者连续输入 5 次错误 PIN，然后杀掉应用进程并重新打开，再进入 `/parental-controls`
- **Then** PIN 面板处于锁定态并显示剩余倒计时（≤ 60 秒）；**重启未重置计数**；此时清除应用的浏览器数据后再进入，**仍处于锁定态**（状态在原生安全存储）

**GWT-E-29 恢复码重设 PIN**
- **Given** 家长控制已启用，家长忘记 PIN，持有设置时抄下的 12 位恢复码
- **When** 家长在 PIN 面板点击 `Forgot PIN`，输入正确恢复码
- **Then** 进入强制重设新 PIN 的流程；设置成功后生成**新的**恢复码并展示一次；旧恢复码立即失效（再次输入旧码提示错误）；错误计数归零

**GWT-E-30 屏幕时间耗尽走宽限期**
- **Given** `screenTime.enabled = true`、`dailyMinutes = 120`、`graceMinutes = 5`，`consumedToday` 已达 120 分钟，用户正在 `/hsk-prep-training` 的一道题上，存在 `in_progress` 的 `attemptId`
- **When** 有效学习时长跨过 120 分钟
- **Then** 弹出宽限提示 `5 minutes left to finish up`；**`attemptId` 不被作废**；当前音频按 `03` 规则停止并用播放代次令牌阻止旧 `play()` 重启；5 分钟后跳全屏 `Time's up` 页，显示明日恢复时间与 `Ask parent for more time`；该 `attemptId` 仍可在下次进入时按 `attemptId` 缓存键恢复

**GWT-E-31 家长授予一次性延时**
- **Given** 用户处于 `Time's up` 页，今日已获 0 次延时
- **When** 家长点击 `Ask parent for more time`，通过 PIN 验证，选择授予 30 分钟
- **Then** `bonusMinutesToday = 30`，用户立即可继续使用 30 分钟；当日第 3 次请求延时被拒绝并提示 `Daily extension limit reached`；次日 00:00 `bonusMinutesToday` 归零

**GWT-E-32 宵禁独立于配额**

- **When** 系统时间到达 21:00
- **Then** 在 60 秒内跳全屏宵禁页，文案 `Available again at 06:30`；配额剩余不解除宵禁；06:30 后正常可用；若 Device Owner 可用，21:00 时即使 C-LingoAIOS 不在前台也触发拦截

**GWT-E-33 `under13` 强制开启**
- **Given** `clingo-user-profile-v1.dob` 对应年龄 11 岁（`ageTier = 'under13'`）

**GWT-E-34 改生日不能绕过限制**

## 五、语言与本地化设置

### 5.1 现状基线

#### 5.1.1 两份语言表不一致（S7 的一半）

| 表 | 位置 | 条目数 | 内容 |
|---|---|---:|---|
| `APP_LOCALES` | `data/localeConfig.ts:19-92` | **9** | `zh` `en` `vi` `ms` `es` `fr` `ja` `ko` `ar` |
| `ONBOARD_LANGS` | `onboarding/OnboardingFlow.tsx:116-129` | **10** | `zh` `en` `vi` **`id`** `ja` `ko` **`th`** `es` `fr` `ar` |
| i18n 资源目录 | `i18n/locales/` | **9** | `ar` `en` `es` `fr` `ja` `ko` `ms` `vi` `zh` |

差异有三处：

1. **`ms`（马来语）有 locale 和 i18n 资源，但向导里选不到**。目标市场含马来西亚，这是一个市场覆盖缺口。
2. **`id`（印尼语）和 `th`（泰语）在向导里能选，但 `localeId: null`**——代码注释写得很直白：「id / th 一期没有 i18n 包，只记选择，界面仍走 en」。用户认真选了印尼语，界面还是英文。目标市场恰好含印尼和泰国。
3. 翻译覆盖度极不均衡：`en` 与 `ar` 各 262 行，`zh` 178 行，其余 6 种各 **129 行**（不到英文的一半）。也就是说 `vi` / `ms` / `es` / `fr` / `ja` / `ko` 切过去会看到**大量英文兜底文案混在译文里**（`localeRecord()` 的 `?? en` 兜底，`localeConfig.ts:119-142`）。

#### 5.1.2 语言切换的当前入口

- **唯一可用的切换入口在顶栏语言胶囊**（`components/home/HubLangProfile.tsx`），点开 MUI `Menu` 列出 `APP_LOCALES` 全 9 项，选中即 `setLocaleId`。
- `LocaleContext` 写 `localStorage` 键 `c-lingo-ui-locale-v1`，同时设 `document.documentElement.lang`、`--app-font-family`、`body.style.fontFamily`，并调 `i18n.changeLanguage`（`context/LocaleContext.tsx:26-45`）。
- **`/system/language-packs` 页与 `LocaleContext` 完全没有关系**。该页有自己的 7 项硬编码列表（`en` `th` `vi` `ms` `id` `ar` `es`，`LanguagePacksPage.tsx:8-16`），第三份语言表，与前两份都不一致；点 Download 只是 `setInterval` 每 280 ms 加 18% 的假进度条（`LanguagePacksPage.tsx:24-37`），走完把 `status` 改成 `installed`，**不下载任何东西、不持久化、刷新即回到初始状态**。
- **产品规则明确要求「语言选择器放在设置区域」**，但现状的权威入口在顶栏，设置区域里那一页反而是假的。

#### 5.1.3 RTL 与字体

`localeConfig.ts` 为 `ja` / `ko` / `ar` 分别指定了专用字体常量（`APP_FONT_JA` / `APP_FONT_KO` / `APP_FONT_AR`），但 `APP_LOCALES` 的字段里**没有 `dir`**，`applyLocaleToDocument` 也**没有设 `document.documentElement.dir`**。阿拉伯语切过去是 LTR 布局的阿拉伯文。（RTL 布局规范归 `01` 第五节，此处只记事实。）

### 5.2 3.0 需求 · 语言表收口为单一数据源

`APP_LOCALES` 升级为**全产品唯一语言表**，向导 Step 0、设置页、顶栏胶囊、语言包页全部从它渲染。

新增字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `AppLocaleId` | 扩为 11 种：`en` `zh` `vi` `ms` `id` `th` `es` `fr` `ja` `ko` `ar` |
| `name` | 字符串 | 该语言的**自称**（`Bahasa Indonesia`，不是 `Indonesian`） |
| `englishName` | 字符串 | 英文名，供英文界面下的二级说明 |
| `flag` | emoji | — |
| `label` | 字符串 | 2 字母短标签，顶栏胶囊用 |
| `htmlLang` | 字符串 | BCP 47，如 `ar-AE` |
| `dir` | `'ltr' \| 'rtl'` | **新增**。`ar` 为 `rtl`，其余 `ltr` |

|---|---|---|---|

| `ar` | العربية | `full` | 262 行，中东市场重点，RTL |

| `fr` | Français | `partial` | 129 行，欧美市场 |
| `ja` | 日本語 | `partial` | 129 行 |
| `ko` | 한국어 | `partial` | 129 行 |
| `id` | Bahasa Indonesia | `planned` | **无 i18n 资源**，印尼市场。3.0 需补译 |

### 5.3 3.0 需求 · `status` 的 UI 语义

「选了语言但界面不变」是 `00-总纲` 风险 R6 的核心。3.0 的解法不是隐藏，而是**说清楚**：

| `status` | 向导 Step 0 | 设置页 | 选中后行为 |
|---|---|---|---|
| `full` | 正常可选 | 正常可选 | 完整切换 |
| `partial` | 正常可选，卡片右下角一枚小标 `Beta` | 正常可选，副文案 `Partly translated` | 切换；未翻译的键兜底到英文（现有 `localeRecord` 行为） |
| `planned` | 显示但**不可选**，置灰 + 标 `Coming soon` | 同上，并提供「通知我」占位（一期不做通知，占位也不放，见下） | 不可选，点击弹一次说明 `Not available yet — the interface will stay in English` |

**关键决策：`planned` 的语言做成不可选，而不是「可选但界面不变」。** 理由——让用户选一个明知无效的选项，是本篇要清掉的「假控件」的同一类问题。`00-总纲` R8 已经定下「全部占位页统一锁定 / 敬请期待处理，不留裸空页」，语言选项适用同一原则。

**一期不做「通知我」**：没有后端邮件能力（同 4.4.4 的理由），一个点了没反应的「通知我」就是新的死按钮。

### 5.4 3.0 需求 · 设置内语言切换的正式设计

产品规则要求「语言选择器放在设置区域」。3.0 的收口方案：

| 入口 | 3.0 角色 |
|---|---|
| `/system/language-packs`（**改名为 `Language & Region`**） | **唯一权威切换入口**。承载：当前语言、语言列表与切换、语言包下载/更新/卸载、存储占用 |
| `/apps` → System settings → `Language & Region` 行 | 进入上页；副文案显示当前语言自称 |
| 顶栏语言胶囊（`HubLangProfile`） | **降级为指示器 + 快捷跳转**。点击**不再内联展开切换菜单**，改为 `navigate('/system/language-packs')` |
| `/android/settings` → Languages | 走向由第九章决策；Path A 下改为跳系统 `ACTION_LOCALE_SETTINGS`（那是**安卓系统语言**，与 C-LingoAIOS 界面语言是两件事，UI 上必须区分清楚） |
| 开机向导 Step 0 | 首次选择。与设置页共用同一张表、同一份 `status` 语义 |

**为什么把顶栏胶囊降级而不是保留双入口**：现状两处入口对应两份不同的语言表（顶栏 9 项 / 语言包页 7 项），用户在哪一处看到的就是哪一套，口径不一致本身就是缺陷。3.0 收成一处，顶栏只负责「告诉你现在是什么语言」+「一键去改」。

#### 5.4.1 `Language & Region` 页结构

```text
┌─ 顶栏：返回 + 标题 Language & Region + 副标题「Interface language and downloaded packs」
├─ 区块 1 · Current language
│    └─ 大卡：旗帜 + 自称 + 英文名 + status 标签 + 「Change」按钮（点击滚到区块 2）
├─ 区块 2 · Available languages（按 status 分三组，组内按目标市场优先级排序）
│    ├─ Ready to use（full / partial 且包已下载）  → 单选，点即切换
│    ├─ Download to use（full / partial 且包未下载）→ 每行带体积 + Download 按钮
│    └─ Coming soon（planned）                     → 置灰不可选
├─ 区块 3 · Storage
│    └─ 「Language packs use {n} MB」+ 「Manage storage」→ /system/content-cache
└─ 区块 4 · Region format（3.0 可选，[待确认] 是否一期做）
     └─ 日期格式、数字格式、一周起始日。默认跟随语言，可单独覆盖
```

### 5.5 3.0 需求 · 与开机向导 Step 0 的关系

| 维度 | 向导 Step 0 | 设置页 |
|---|---|---|
| 时机 | 首次开机，一次性 | 任何时候 |
| 数据源 | 同一张 `APP_LOCALES` | 同一张 |
| `status` 语义 | 一致（5.3） | 一致 |
| 写入目标 | ① `c-lingo-ui-locale-v1`（生效语言）② `clingo-user-profile-v1.localeId`（档案） | 同样两处 |
| 语言包 | **向导不下载语言包**。Step 0 时 WiFi 还没连（WiFi 是 Step 1），下载必然失败 | 可下载 |
| 未下载包的语言 | 向导中可选：先切界面（用内置的 `en` 兜底 + 已内置的最小译文），并**记下待下载**；进 Step 1 连上 WiFi 后在后台静默拉取 | 需先下载才能切 |
| 回改 | 向导内可多次改，最后一次生效 | 随时可改 |

**关键顺序问题**：向导第一步就是选语言，但网络在第二步才连上。所以 3.0 要求：

1. **内置最小语言包**。11 种语言的「向导 + 壳层 + 底栏」这批高频文案（约 60 条）**打进 APK**，不依赖下载。这样 Step 0 选任何 `full`/`partial` 语言，向导本身立刻是该语言。
2. **业务文案按需下载**。教材、题型说明、AI 提示词等大体量文案走语言包，Step 1 连网后静默拉取，进度在 Step 2 页脚以一行细字显示，**不阻塞向导流程**。
3. 下载失败不阻塞：向导照常走完，进首页后在 `/apps` 的 Language & Region 行显示一枚提示徽标。

#### 5.6.1 清单接口

| 项 | 规格 |
|---|---|
| 接口 | `GET /api/i18n/manifest?appVersion={v}&deviceId={id}` |
| 响应 | `{ schemaVersion, generatedAt, packs: LanguagePack[] }` |
| `LanguagePack` | `{ localeId, version, sizeBytes, sha256, downloadUrl, minAppVersion, status }` |
| 缓存 | 清单本地缓存 6 小时；进入 Language & Region 页时若缓存过期则刷新 |
| 离线 | 清单不可达时用本地缓存渲染；无缓存时显示「Ready to use」组（已装包）+ 一行 `Connect to the internet to see more languages` |
| 鉴权 | 沿用 `X-Clingo-Device-Id` 匿名设备标识，与 `AGENTS.md` 一致 |

#### 5.6.2 下载与校验

| 阶段 | 规则 | 失败处理 |
|---|---|---|
| 预检 | 校验 `minAppVersion ≤ 当前版本`；校验剩余空间 ≥ `sizeBytes × 1.2` | 版本不足 → 提示先更新应用；空间不足 → 提示并给去 `/system/content-cache` 的操作 |
| 下载 | HTTP Range 分块，块大小 1 MB；**支持断点续传**（记录已完成块与 ETag） | 网络中断 → 保留已下载部分，状态置 `paused`，UI 显示 `Paused · {n}% · Resume`；恢复时从断点继续 |
| 重试 | 指数退避：1 s / 2 s / 4 s / 8 s / 16 s，最多 5 次 | 5 次仍失败 → 状态 `failed`，UI 显示 `Download failed · Retry`，**保留已下载分块** 24 小时后清理 |
| 校验 | 全量下载完成后计算 SHA-256 并与清单比对 | 不匹配 → 丢弃全部分块、状态 `failed`、提示 `Download corrupted · Retry`；**不允许**装载未通过校验的包 |
| 装载 | 解包写入 i18n 资源存储；写入成功后原子切换版本指针 | 装载中断 → 保留旧版本可用，新版本标记为不完整并在下次进入时重试 |
| 生效 | 装载成功后，若该语言是当前语言，立即热替换文案（不重启应用） | 热替换失败 → 提示 `Restart to apply` |

#### 5.6.3 切换生效的范围

| 项 | 切换后是否立即生效 |
|---|---|
| 界面文案（i18n 键） | ✅ 立即 |
| `document.documentElement.lang` | ✅ 立即 |
| `document.documentElement.dir`（**3.0 新增**） | ✅ 立即。`ar` 切为 `rtl`，全局布局镜像（规范见 `01`） |
| 字体族 | ✅ 立即。字体文件未加载完成时用系统兜底，避免白字 |
| 日期 / 数字格式 | ✅ 立即（依赖 `Intl`，按 `htmlLang`） |
| 教材内容语言 | ❌ **不变**。教材是中文学习材料，界面语言不改变教材本身 |
| AI 对话的辅助语言（拼音/翻译） | ✅ 跟随界面语言 |
| 已生成的学习报告 | ✅ 标签跟随；历史数值不变 |
| HSK 作答中的题目 | ❌ **不变**。按 `03` 规则，作答只用开始时冻结的快照，切语言不得改变题目内容或选项 |

#### 5.6.4 卸载语言包

| 规则 |
|---|
| `en` 为内置包，**不可卸载**（卸载按钮不显示） |
| 当前正在使用的语言不可卸载；需先切到别的语言 |
| 卸载弹二次确认，说明将释放的空间 |
| 卸载后该语言回到「Download to use」组 |
| 卸载不影响 `clingo-user-profile-v1.localeId` 的历史值 |

### 5.7 3.0 需求 · 迪拜官方阿拉伯语

用户规则明确「阿拉伯语需特别注意（使用迪拜官方阿拉伯语）」。3.0 的落地要求：

| 项 | 规格 | 状态 |
|---|---|---|
| `htmlLang` | `ar-AE`（不是泛用的 `ar`） | ✅ 可定 |
| 书写体系 | **现代标准阿拉伯语（MSA / الفصحى）**，非海湾方言 | ⚠️ [待确认] |
| 数字形式 | 东阿拉伯数字（`٠١٢٣`）vs 西阿拉伯数字（`0123`） | ⚠️ [待确认] |
| 术语表 | HSK、拼音、声调、部首等专业名词的官方阿语对照表 | ⚠️ [待确认] |
| 审校 | 需母语审校签字 | ⚠️ [待确认] |
| 字体 | 沿用 `APP_FONT_AR`；需确认该字体对所有目标字形（含 tashkeel 变音符号）的覆盖 | ⚠️ [待确认] |

> **[待确认] 「迪拜官方阿拉伯语」的确切定义。** 这个说法在语言学上不是一个标准 locale 名。合理推断是「迪拜政府公文所用的现代标准阿拉伯语」——迪拜政府对外公文确实使用 MSA，而非海湾方言。但需业务方确认以下三点，否则译文风格会在整个产品里不一致：
> 1. 是否就是 MSA？还是要带海湾地区的用词习惯（如某些日常词汇）？
> 2. 数字用东阿拉伯数字还是西阿拉伯数字？迪拜政府网站两者并用，需产品定一个。
> 3. 面向 13–19 岁青少年，MSA 的书面语调性是否过于正式？是否需要一份「青少年友好但仍属 MSA」的语体指引？

## 六、内容与存储管理

### 6.1 现状基线 · `/system/content-cache`

| 项 | 现状 |
|---|---|
| 数据 | 页内常量 `CACHE_ITEMS` 5 条（`ContentCachePage.tsx:9-15`），字段 `id`/`label`/`type`/`size`/`cached` |
| 总量显示 | `parseInt(item.size, 10)` 把 `"286 MB"` 解析成 `286` 后求和（`:23`），单位靠约定，**不同单位混排会算错** |
| Clear | `setClearingId` → 600 ms 后把 `cached` 置 `false`（`:25-31`），**不删任何文件** |
| Prefetch | 按钮**无 `onClick`**（`:64-66`），点了完全没反应 |
| 持久化 | **无**，刷新回到初始 5 条全部 `cached` 状态 |
| 剩余空间 | **不显示** |
| 与书架的关系 | 无。`02` 域的书籍下载状态只在内存，刷新即丢，两边完全没有共享模型 |

**产品规则明确要求「下载管理、存储管理」是系统设置三大项之一，现状这一页两个操作一个假一个死。**

### 6.2 3.0 需求 · 内容包模型

统一用「内容包」（content package）作为所有可下载内容的唯一抽象。书架下载、语言包、HSK 听力音频、文化视频，全部是内容包。

#### 6.2.1 分级

| 级 | `tier` | 内容 | 默认策略 | 可否清理 |
|---|---|---|---|---|
| L0 | `core` | 应用壳层、内置最小语言包、UI 资源 | 随 APK 内置 | ❌ 不可 |
| L1 | `text` | 教材文本、课程结构、词表、题库 JSON | 首次进入对应书籍/等级时自动下载 | ⚠️ 可清，但清后进入该内容需重新下载 |
| L2 | `audio` | 课文朗读、单词发音、HSK 听力音频 | 用户点下载，或进入内容时按需流式 + 边播边缓存 | ✅ 可清 |
| L3 | `video` | 文化视频、笔画演示视频、课程视频 | **仅手动下载**，不自动 | ✅ 可清，**LRU 首选淘汰对象** |
| L4 | `locale` | 语言包（第五章） | 用户选择 | ✅ 可清（`en` 除外） |

**分级的意义在配额与淘汰优先级**：空间不足时，先淘汰 L3，再 L2，L1 只在用户明确操作时清理，L0 永不清理。

#### 6.2.2 内容包字段

| 字段 | 类型 | 说明 | 校验 |
|---|---|---|---|
| `packId` | 字符串 | 全局唯一 | — |
| `tier` | `'core' \| 'text' \| 'audio' \| 'video' \| 'locale'` | 见上 | 非枚举值 → 拒绝装载 |
| `scope` | `{ kind: 'book' \| 'unit' \| 'hskLevel' \| 'locale' \| 'global', refId: string }` | 归属，供按书/按单元聚合展示 | — |
| `label` | 字符串 | 展示名，**需 i18n** | — |
| `version` | 字符串 | 语义化版本 | — |
| `sizeBytes` | 整数 | **字节数，不是 `"286 MB"` 字符串** | > 0 |
| `sha256` | 字符串 | 完整包校验和 | 64 位十六进制 |
| `state` | `'absent' \| 'queued' \| 'downloading' \| 'paused' \| 'failed' \| 'ready' \| 'stale'` | — | — |
| `downloadedBytes` | 整数 | 断点续传游标 | 0 ≤ x ≤ `sizeBytes` |
| `pinned` | 布尔 | 用户置顶保护，LRU 不淘汰 | 默认 `false` |
| `lastAccessedAt` | ISO 8601 UTC | LRU 依据 | — |
| `expiresAt` | ISO 8601 UTC \| `null` | 授权内容的有效期 | `null` = 永久 |

#### 6.2.3 状态机

```text
absent ──下载──> queued ──> downloading ──完成+校验通过──> ready
                                 │  │
                       网络中断  │  │  校验失败 / 重试耗尽
                                 ↓  ↓
                              paused  failed
                                 │       │
                              Resume   Retry
                                 └───┬───┘
                                     ↓
                                downloading

ready ──服务端版本更新──> stale ──更新──> downloading ──> ready
ready ──手动清理 / LRU 淘汰──> absent
```

**`stale` 的处理**：旧版本仍可用，页面显示 `Update available`。**不自动替换正在使用的内容包**——尤其是 HSK 题库，替换正在作答的快照会直接违反 `03` 的冻结规则。

### 6.3 3.0 需求 · 配额与 LRU 淘汰

| 项 | 规格 | 说明 |
|---|---|---|
| 总配额 | 默认 **8 GB**，[待确认] | 需硬件侧给出目标机型的存储规格。若机型是 32 GB，8 GB 内容占 25% 是合理上限；若是 64 GB 可放宽 |
| 分级上限 | `video` ≤ 总配额 50%；`audio` ≤ 30%；`text` 无上限（体量小）；`locale` ≤ 500 MB | 防止一个文化视频包吃掉全部空间 |
| 硬性预留 | 设备剩余空间必须始终 ≥ **1 GB**；低于时禁止新下载并提示 | 安卓在剩余空间过低时会出现系统级异常 |
| LRU 触发 | 新下载会使总占用超过配额，或设备剩余空间将低于预留 | — |
| 淘汰顺序 | ① `pinned === false` 且 `tier === 'video'`，按 `lastAccessedAt` 升序 → ② 同条件的 `audio` → ③ 同条件的 `locale`（非当前语言） → ④ 停止，`text` 与 `core` 不参与自动淘汰 | — |
| 淘汰上限 | 单次自动淘汰释放的空间不超过「本次所需 + 500 MB」 | 避免一次下载清掉用户半年攒的缓存 |
| 淘汰告知 | 自动淘汰发生后，在下载完成提示里附一行 `Freed {n} MB by removing unused videos`，并可点开看清单 | 静默删用户内容会引发信任问题 |
| 无可淘汰 | 全部候选都 `pinned` 或已清空仍不够 → 下载失败，提示 `Not enough space · free up {n} MB` 并列出最大的几个可清理项 | — |

### 6.5 3.0 需求 · 能力分层（Web vs 原生）

| 能力 | Web 层能做到 | 必须原生层做 | 安卓权限 | 用户授权时机 |
|---|---|---|---|---|
| 存储内容包（≤ 数百 MB） | ⚠️ Cache Storage / IndexedDB 可用，但 WebView 的 origin 配额通常只是剩余空间的一个比例，且**可能被系统在低空间时清除** | ✅ 落到应用私有目录（`Context.getFilesDir()` / `getExternalFilesDir()`），不受 WebView 配额限制、不被浏览器数据清除影响 | 私有目录无需权限 | — |
| 读取 origin 已用/配额 | ✅ `navigator.storage.estimate()` | — | 无 | — |
| 读取**设备**剩余空间 | ❌ 拿不到 | ✅ `StatFs.getAvailableBytes()` / `StorageManager.getAllocatableBytes()` | 无（自身私有目录所在卷） | — |
| 预留空间（避免下载中途被其他应用占满） | ❌ | ✅ `StorageManager.allocateBytes()` | 无 | — |
| 请求存储不被系统清理 | ⚠️ `navigator.storage.persist()`，WebView 支持情况不稳定 [待确认] | ✅ 私有目录天然持久 | — | — |
| 大文件后台下载（应用切后台/息屏仍继续） | ❌ WebView 被挂起后 `fetch` 会停 | ✅ `DownloadManager` 或 `WorkManager` + 前台服务 | Android 13+ 需 `POST_NOTIFICATIONS` 才能显示下载通知；前台服务需 `FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_DATA_SYNC`（Android 14+） | 首次启动后台下载时申请通知权限；拒绝则下载仍可进行但无通知，且切后台可能被系统限流 |
| 断点续传 | ✅ `fetch` + Range 可实现（前台） | ✅ 后台场景必须原生 | 无 | — |
| SHA-256 校验 | ✅ `crypto.subtle.digest`（大文件需分块流式，注意内存） | ✅ 原生更省内存 | 无 | — |
| 写入外置 SD 卡 | ❌ | ✅ `getExternalFilesDirs()` 取第二个卷 | Android 10+ 应用私有目录无需权限；共享目录需 `MANAGE_EXTERNAL_STORAGE`（**不申请**，政策风险高且无必要） | — |
| 清理其他应用缓存 | ❌ | ❌ 普通应用做不到；Device Owner 可 `clearApplicationUserData(其他包)` | 需 Device Owner | — |

**结论**：内容与存储管理**必须走原生下载与原生文件存储**。Web 层只负责 UI、清单解析与状态展示。这不是优化，是可行性问题——一个 500 MB 的文化视频包，在 WebView 里下载会因为切后台被挂起而永远下不完。

### 6.6 3.0 需求 · 与教材域书籍下载打通

`02-首页与教材.md` 的书架下载状态当前只在内存、刷新即丢。3.0 规定：

| 要求 |
|---|
| 书架的每本书对应一组内容包（`scope.kind === 'book'`，`refId` 为 `bookId`），至少含一个 `text` 包，可选 `audio` / `video` 包 |
| 书架上的下载按钮与进度条**直接读 `contentStore` 的包状态**，不维护自己的内存 state |
| 书架显示的下载进度 = 该书全部所选包的加权进度（按 `sizeBytes` 加权） |
| 刷新、杀进程重开后，书架的下载状态与进度**完整恢复** |
| 在 `Content & Storage` 页删除某书的 `audio` 包后，书架上该书的下载态**立即同步**变为「部分已下载」 |
| 书籍内容包的 `lastAccessedAt` 在用户进入阅读器时更新，供 LRU 参考 |
| 「当前正在学的书」的内容包自动 `pinned = true`，不被 LRU 淘汰 |

**GWT-E-50 LRU 淘汰有告知**
- **Given** 内容占用 7.8 GB（配额 8 GB），存在 3 个 `pinned === false` 的视频包，`lastAccessedAt` 分别为 90/60/30 天前

- **When** 用户点击 Download
- **Then** 下载不开始；提示 `Not enough space · free up 420 MB`，并列出占用最大的可清理项与「Free up space」入口；不产生任何部分下载的残留文件

**GWT-E-52 书架状态打通**
- **Given** 用户已下载 `HSK Standard Course 1` 的 `text` 与 `audio` 包，书架显示该书「已下载」

**GWT-E-53 更新不影响进行中的作答**
- **Given** HSK1 题库包有服务端新版本（状态 `stale`），用户当前有一个 `in_progress` 的 `attemptId`

| 桥方法 | `listInstalledApps(): Promise<InstalledApp[]>` |
| `InstalledApp` | `{ packageName, appLabel, iconDataUri, versionName, versionCode, isSystemApp, canLaunch }` |
| 原生实现 | `PackageManager.queryIntentActivities(new Intent(ACTION_MAIN).addCategory(CATEGORY_LAUNCHER), 0)`；只返回**有启动入口**的应用（`canLaunch === true`），不返回无界面的服务型包 |
| 图标 | `ActivityInfo.loadIcon(pm)` → `Bitmap` → PNG → Base64 data URI。**图标必须做尺寸上限**（建议 192×192）与本地缓存（按 `packageName + versionCode` 缓存到原生私有目录），否则 50 个应用的 Base64 会把 WebView 的桥消息撑爆 |
| 分页 | 应用数可能上百。桥返回**不含图标**的基础列表 + 单独的 `getAppIcon(packageName)` 按需拉取；列表滚动时懒加载图标 |
| Android 11+ 可见性 | Android 11（API 30）起，应用默认看不到其他应用的包信息。需要**二选一**：① 清单声明 `<uses-permission android:name="android.permission.QUERY_ALL_PACKAGES" />`；② 清单 `<queries>` 声明具体要查询的 intent/包 |
| 权限选择 | **用 `QUERY_ALL_PACKAGES`**。理由：C-LingoAIOS 的功能就是「做这台平板的应用入口」，无法预先枚举所有要查询的包；而 Google Play 对该权限的政策限制**不适用**——本产品是随硬件出厂预置、不经 Play 分发。若后续要上 Play，需改为 `<queries>` 白名单方案，这是一个分发渠道决策 [待确认] |
| 权限类型 | `QUERY_ALL_PACKAGES` 是 **normal 级权限**，清单声明即获得，**无运行时弹窗**，无需用户授权时机 |

#### 7.4.3 原生桥：启动应用

| 项 | 规格 |
|---|---|
| 桥方法 | `openSystemApp(packageName: string): Promise<{ ok: boolean; reason?: 'NOT_INSTALLED' \| 'NO_LAUNCHER' \| 'BLOCKED_BY_POLICY' \| 'FAILED' }>` |
| 原生实现 | `pm.getLaunchIntentForPackage(packageName)`；为空则返回 `NO_LAUNCHER`；`startActivity(intent.addFlags(FLAG_ACTIVITY_NEW_TASK))` |
| 家长控制 | 启动前查白名单与内容分级；被策略拦截返回 `BLOCKED_BY_POLICY`，Web 层显示 `Blocked by parental controls` |
| 权限 | 无额外权限（`QUERY_ALL_PACKAGES` 已覆盖可见性） |
| 用户授权时机 | 无 |
| 返回行为 | 用户从被启动的应用按返回/Home 回到 C-LingoAIOS 时，**回到离开时的页面**（由 Activity 生命周期保证，Web 层无需处理） |

#### 7.5.2 完整链路

```text
① 清单接口
   GET /api/apps/manifest?deviceModel={m}&osVersion={v}&channel={c}&deviceId={id}
   → { schemaVersion, generatedAt, apps: ApkEntry[] }
   ApkEntry = {
     packageName, label, versionName, versionCode,
     sizeBytes, sha256, signatureSha256, downloadUrl,
     minSdk, releaseNotes, rolloutPercent, forceUpdateBelowVersionCode
   }
     ↓
② 本地对比
   原生 pm.getPackageInfo(packageName) 取已装 versionCode
   → 状态判定：not_installed / up_to_date / update_available / force_update
     ↓
③ 灰度判定
   hash(deviceId + packageName) % 100 < rolloutPercent ？纳入灰度：否则视为 up_to_date
     ↓
④ 家长控制门禁
   ageTier 策略 + 白名单 + 安装审批（4.8）
     ↓
⑤ 下载（原生 DownloadManager / WorkManager，支持断点续传与后台）
     ↓
⑥ 完整性校验
   ├─ 文件 SHA-256 == manifest.sha256   （防传输损坏）
   └─ APK 签名证书 SHA-256 == manifest.signatureSha256  （防替换与中间人）
       原生：PackageManager.getPackageArchiveInfo(path, GET_SIGNING_CERTIFICATES)
             → SigningInfo.getApkContentsSigners() → 证书摘要比对
   任一不通过 → 删除文件、状态置 failed、提示 Download corrupted
     ↓
⑦ 安装
   ├─ 常规路径：PackageInstaller Session API，系统弹安装确认
   │            需 REQUEST_INSTALL_PACKAGES 权限
   └─ Device Owner 路径：静默安装（无用户确认），见第九章 Path A
     ↓
⑧ 安装结果回调
   PackageInstaller 的 IntentSender 回调 → STATUS_SUCCESS / STATUS_FAILURE_* 
   成功 → 刷新已装版本、状态置 up_to_date
   失败 → 按 failureCode 映射提示（见 7.5.4）
     ↓
⑨ 失败重试与回滚
   见 7.5.5
```

#### 7.5.3 安卓权限清单（本链路）

| 权限 | 类型 | 用途 | 用户授权时机 |
|---|---|---|---|
| `android.permission.INTERNET` | normal | 下载 | 清单声明即得 |
| `android.permission.REQUEST_INSTALL_PACKAGES` | **special（appop）** | 允许应用请求安装 APK | Android 8+ 起必须声明；Android 8–12 由系统在首次安装请求时引导用户到「安装未知应用」开关；**Android 13+ 需先 `packageManager.canRequestPackageInstalls()` 判定，为 false 时引导 `Settings.ACTION_MANAGE_UNKNOWN_APP_SOURCES`**。授权时机：用户第一次在 `Device Apps` 点 Install/Update 时，先弹一段说明（为什么需要、会发生什么），再跳系统开关页 |
| `android.permission.QUERY_ALL_PACKAGES` | normal | 读已装版本号做对比 | 清单声明即得 |
| `android.permission.RECEIVE_BOOT_COMPLETED` | normal | 重启后恢复未完成的安装任务 | 清单声明即得 |
| `android.permission.POST_NOTIFICATIONS` | runtime（Android 13+） | 下载与安装进度通知 | 首次启动后台下载时申请；拒绝则无通知但功能可用 |
| `android.permission.FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_DATA_SYNC` | normal（Android 14+ 需类型） | 后台下载前台服务 | 清单声明即得 |
| Device Owner 身份 | — | 静默安装、`setUninstallBlocked` | 出厂预置，无运行时授权 |

**`REQUEST_INSTALL_PACKAGES` 被拒的处理**：`Device Apps` 页顶部显示常驻横幅 `Allow C-LingoAIOS to install apps` + 「Open settings」按钮；全部 Install/Update 按钮置为禁用态并说明原因。**不允许**在无权限时让按钮看起来可点。

#### 7.5.4 安装失败码映射

| `PackageInstaller` 状态 | 用户可见提示 | 可重试 |
|---|---|---|
| `STATUS_FAILURE_STORAGE` | `Not enough space · free up {n} MB` + 去 `Content & Storage` | ✅ 清理后 |
| `STATUS_FAILURE_INVALID` | `Installation file is invalid` | ✅ 重新下载 |
| `STATUS_FAILURE_CONFLICT`（签名不一致 / 已存在更高版本） | `Can't update — please contact support` | ❌ 需人工 |
| `STATUS_FAILURE_INCOMPATIBLE`（`minSdk` 不满足 / ABI 不匹配） | `Not supported on this device` | ❌ |
| `STATUS_FAILURE_ABORTED`（用户取消） | 静默回到 `update_available`，不报错 | ✅ |
| `STATUS_FAILURE_BLOCKED` | `Installation blocked by device policy` | ❌ |
| 其他 / 超时 | `Installation failed · Retry` | ✅ 最多 3 次 |

#### 7.5.5 强制更新与版本回滚

| 项 | 规格 |
|---|---|
| 强制更新阈值 | 清单的 `forceUpdateBelowVersionCode`。已装版本低于该值时，**启动即拦截**：全屏更新页，只有「Update now」一个出口，不可跳过 |
| 强制更新的使用场景 | 仅用于**安全漏洞**或**接口不兼容**。功能性更新不得设强制 |
| 强制更新离线 | 无网络时全屏页显示 `Connect to the internet to update`，仍不放行。**例外**：C-LingoAIOS 自身的强制更新不得把设备锁成砖——必须保留进系统设置连 WiFi 的出口（Path A 下由 launcher 保证） |
| 灰度 | `rolloutPercent` 0–100；分桶用 `hash(deviceId + packageName) % 100`，同一设备在同一应用上的分桶**稳定**，不会今天在灰度里明天不在 |
| 回滚 | 安卓**不支持降级安装**（除 Device Owner 下 `INSTALL_ALLOW_DOWNGRADE` + `debuggable` 包，生产不可用）。所以「回滚」的真实含义是**服务端回滚清单**：把 `rolloutPercent` 降为 0 并把 `versionCode` 指回上一个稳定版，阻止新设备升上问题版本。**已升级的设备只能靠发布修复版前进，不能回退**——这一点必须让运营侧明确知道 |
| 回滚流程 | ① 运营在后台把问题版本 `rolloutPercent` 置 0；② 客户端 6 小时内刷新清单后不再提示该版本；③ 发布修复版并设较高 `rolloutPercent` |
| 更新记录 | 本地保留最近 20 条安装/更新记录（`packageName`、`fromVersion`、`toVersion`、`result`、`at`），供排查 |

> **[待确认]** ① 清单接口 `/api/apps/manifest` 尚不存在，需与 Java 后端确认归属与路径。② APK 的托管位置与 CDN（当前交付包用 TOS，需确认是否复用）。③ 签名证书摘要的下发与轮换流程——如果签名密钥更换，旧版本客户端会因证书不匹配拒绝安装新包，需要一套证书过渡方案。

| 与 `Device Apps` 的关系 | `/system/app-updates` 与 `/nsk-app-store` 是**同一份数据的两个视图**：前者只看「已装且有更新」，后者看全部（含未装）。共用清单接口、下载器、校验器、安装器 |
| 入口 | `/apps` → System settings → `App Updates` 行，带红色徽标数（修孤儿路由） |
| 徽标数口径 | 已装版本 `versionCode < latest.versionCode` **且在灰度内** 的应用数。现状那个恒为 2 的静态计算必须废掉 |
| 检查时机 | ① 进入本页时；② 应用冷启动后延迟 10 秒；③ 每 6 小时一次（仅在有网络且非计量连接时） |
| 自动更新 | 默认**关闭**。开关放本页顶部：`Auto-update over Wi-Fi`。开启后在设备空闲（息屏 + 充电 + Wi-Fi）时静默更新——**仅 Device Owner 下可静默**，否则每次仍需用户确认，此时开关置灰并说明 |
| 计量连接 | 通过原生 `ConnectivityManager.isActiveNetworkMetered()` 判定；计量网络下不自动下载，手动下载时二次确认 `This will use mobile data` |
| 更新日志 | 清单的 `releaseNotes` 按当前 locale 展示；缺失时显示 `Bug fixes and improvements` |
| 强制更新 | 见 7.5.5 |
| 灰度与回滚 | 见 7.5.5 |
| C-LingoAIOS 自身更新的特殊性 | 更新自己的 APK 会导致进程被杀。要求：① 更新前把当前路由与关键状态（含 `attemptId` 缓存）落盘；② **存在 `in_progress` 的 `attemptId` 时禁止自更新**，提示 `Finish your current attempt first`；③ 更新完成后重启到 `/Home`，不尝试恢复到更新前的深层页面 |

### 8.3 GWT · 自更新

**GWT-E-68 入口与徽标**
- **Given** ScanPen 与 Pinyin Keyboard 各有一个在灰度内的可用更新，其余应用已是最新
- **When** 用户进入 `/apps`
- **Then** System settings 的 `App Updates` 行显示红色徽标 `2` 与副文案 `2 updates available`；点击进入 `/system/app-updates`（**不是** `/nsk-app-store`）；页面列出这 2 个待更新应用

**GWT-E-69 作答中禁止自更新**
- **Given** C-Lingo 自身有一个非强制更新可用，用户存在一个 `in_progress` 的 `attemptId`
- **When** 用户点击 C-Lingo 的 `Update`
- **Then** 不开始下载；提示 `Finish your current attempt first`；作答提交后再次点击可正常更新；更新完成后应用重启到 `/Home`，该 `attemptId` 的作答记录与判卷结果完整可查

**GWT-E-70 计量网络提示**
- **Given** 设备当前通过计量连接（移动热点）联网，`Auto-update over Wi-Fi` 为开启
- **When** 定时检查触发
- **Then** 检查到更新但**不自动下载**；页面显示 `Waiting for Wi-Fi`；用户手动点 Update 时弹二次确认 `This will use mobile data`，确认后才下载

**GWT-E-71 自动更新开关的诚实降级**
- **Given** 设备上 C-LingoAIOS **不是** Device Owner（无静默安装能力）
- **When** 用户进入 `/system/app-updates`
- **Then** `Auto-update over Wi-Fi` 开关置灰不可开，附说明 `Automatic updates require device management`；页面不显示「已开启自动更新」的假状态

## 九、产品定位决策：C-LingoAIOS 是否为安卓 launcher

### 9.1 现状基线 · 两个安卓仿真页

#### 9.1.1 `/android/home`

| 项 | 现状 |
|---|---|
| 内容 | 模拟安卓桌面：深蓝渐变背景、大号时钟 `HH:mm`、日期、右上 Settings 圆键、`ALL APPS` 4 列图标网格、底部毛玻璃 dock（Chrome / Gmail / Maps / Play Store）、底部手势条 |
| 数据 | 全部来自 `ANDROID_SYSTEM_APPS` 常量（`AndroidHomePage.tsx:4,17-18`） |
| Settings 键 | → `/android/settings`（`:38-39`） |
| 网格图标点击 | **全部**指向 `/android-app-picker`（`:55`），不管点的是哪个应用 |
| dock 图标点击 | `ButtonBase` 无 `onClick`，点了没反应 |
| 入口 | **无任何入口**（见 1.4） |
| 时钟 | `new Date()` 在渲染时求一次，**不刷新**（`:13`）——停在进页那一刻的时间 |

#### 9.1.2 `/android/settings`

| 项 | 现状 |
|---|---|
| 内容 | 模拟 Android 设置：设备卡（`NSK Tablet` / `Android 14 · Build TQ3A.230805.001`，硬编码）+ 三个分组共 9 项 |
| 分组与项 | Network & connections：Wi-Fi（`C-Lingo-Office`）、Bluetooth（`On`）；Device：Display（`Brightness 72%`）、Sound（`Media 65%`）、Battery（`87% · Optimized`）、Storage（`24 GB free`）；System：Apps、Languages（`English`）、Security（`Screen lock on`） |
| 可导航项 | **只有 2 个有 `path`**：Apps → `/android-app-picker`（`:35`）、Languages → `/system/language-packs`（`:36`） |
| 其余 7 项 | 无 `path`，`onClick` 里 `item.path &&` 短路，点击完全无反应。全部值为硬编码字符串 |
| 入口 | `/apps` 的「Go to Settings」黑条（`AppsPage.tsx:1082`） |

**定性**：这两页是**安卓系统界面的仿真**。它们展示的 Wi-Fi 名、亮度、电量、存储数字全是编的；点击 7 个项没有任何反应。用户从 C-LingoAIOS 点「Go to Settings」，进到一个长得像系统设置、但什么都调不了的假页面。

### 9.2 缺陷 S6 · 这是一个产品定位问题，不是一个 UI 问题

在写这两页的需求之前，必须先回答一个问题：

> **C-LingoAIOS 到底是不是取代安卓桌面的启动器（launcher）？**

这个问题的答案决定这两页的存在意义：

- **如果是 launcher**：C-LingoAIOS 就是这台平板的「桌面」。用户开机看到的就是它，没有别的桌面可回。那么 `/android/home` 完全没有存在理由（真实桌面就是 C-LingoAIOS 自己，仿真一个安卓桌面是自相矛盾的），而 `/android/settings` 应该是**真实系统设置的跳转清单**。
- **如果不是 launcher**：C-LingoAIOS 只是安装在平板上的一个应用，安卓原生桌面仍然存在。那么 `/android/home` 仿真一个桌面更没意义（按 Home 键就能看到真的），`/android/settings` 也该直接跳系统设置。

**两种答案下，这两页的仿真形态都不成立。** 所以无论走哪条路，现状的「仿真界面」都必须改掉。区别在于**替代方案的能力边界**，以及更重要的——**家长控制和屏幕时间能不能真的生效**（见 4.6.3）。

### 9.3 支持「是 launcher」的现有证据

| 证据 | 来源 |
|---|---|
| `00-总纲` 明确写「它不是一个装在平板上的 App，而是**开机即接管整台设备的学习操作系统外壳**」 | `00-总纲.md` 第一节 |
| 定位一句话：「一台开机就只能学中文的平板」 | 同上 |
| 竞品对比表写「**独占整台平板**，无外部干扰源」 | 同上 |
| 变现方式是「硬件销售 + 内容授权」，不是订阅 | 同上 |
| 产品系统名叫 **C-LingoAIOS**（AI + OS），不叫 C-Lingo App | 术语强制 |
| `PRODUCT_APPS` 里有独立的 `com.nsk.launcher`（NSK Launcher `2.4.0`）包 | `data/appUpdatesCatalog.ts:13` |
| `/apps` 页本身就是一个桌面形态：时钟 + 工具栏 + 应用网格 + 系统设置 | `AppsPage.tsx` |

### 9.4 一个必须同时回答的子问题

`PRODUCT_APPS` 里已经有 `com.nsk.launcher`，版本 `2.4.0`——这说明**硬件侧已经有一个独立的 launcher APK 在维护**。那么：

> **[待确认] C-LingoAIOS 与 NSK Launcher 谁是 Home？**
>
> 三种可能，需硬件与运营侧明确：
> 1. **NSK Launcher 是 Home，C-LingoAIOS 是它上面的一个应用**。那么 C-LingoAIOS 不是 launcher，走 Path B；`/android/home` 该删；家长控制的设备级 enforcement 要由 NSK Launcher 与 `com.nsk.parental`（Parental Service）承担，C-LingoAIOS 只是策略的一个消费方。
> 2. **C-LingoAIOS 是 Home，NSK Launcher 是历史遗留 / 其他产品线在用**。走 Path A。
> 3. **两者是同一个东西的不同层**：NSK Launcher 是原生壳（含 Device Owner / DPC 能力），C-LingoAIOS 的 H5 跑在它的 WebView 里。这是最可能的真相，也最符合「H5 + 原生桥」的架构。若是这种，Path A 的全部原生能力都已经有归属，本篇第十章的桥接口就是向 NSK Launcher 提的需求。
>
> **这个问题不回答，第四章的家长控制无法排期**，因为不知道 enforcement 由谁实现。

### 9.5 Path A · C-LingoAIOS 是 launcher（推荐）

#### 9.5.1 需求轮廓

| 项 | 需求 |
|---|---|
| Home 注册 | C-LingoAIOS 的主 Activity 声明 `<intent-filter>` 含 `ACTION_MAIN` + `CATEGORY_HOME` + `CATEGORY_DEFAULT` |
| 默认 Home 锁定 | 以 Device Owner 身份调 `DevicePolicyManager.addPersistentPreferredActivity(admin, homeIntentFilter, clingoComponent)`，使 C-LingoAIOS 成为**不可更改**的默认 Home。用户按 Home 键始终回到 C-LingoAIOS |
| Device Owner 取得 | 出厂镜像阶段 `dpm set-device-owner`，或通过 NFC / QR 配置。**只能在设备未 provision 且无账号时设置**。**抹机后可补设**（见下方修订），但对已售设备而言等于要清掉用户全部数据——这是一个**产线流程要求**，不是软件能力 |
| 零触碰配置的前提（评审补充） | Google Zero-Touch 门户依赖 **GMS**，而 `06` N9 已承认主销区大量设备**无 GMS**（`07` **Q75**）。无 GMS 时只剩**产线 ADB** 与 **NFC / QR** 两条路 |
| `/android/home` | **从 3.0 路由表移除**。真实桌面就是 C-LingoAIOS，仿真一个安卓桌面是自相矛盾 |
| `/android/settings` | 改造为 **`Device Settings` 跳转清单**（见 9.5.2） |
| `/apps` 的「Go to Settings」黑条 | 保留，但目的地改为改造后的 `Device Settings`；或直接 `startActivity(Settings.ACTION_SETTINGS)` 跳系统设置。**二选一，[待确认]**：走中间页的好处是可以按家长控制策略筛选哪些设置项可跳；直跳的好处是少一层。**建议走中间页**，因为家长控制需要筛选能力 |
| 退出 launcher | 提供一个「Exit to Android」入口，需 PIN（家长态）。用于售后与家长自己装应用 |
| Kiosk / LockTask | 家长控制的屏幕时间与宵禁生效时，可用 `startLockTask` 把设备锁在 C-LingoAIOS 内 |
| 系统栏 | Device Owner 可用 `setStatusBarDisabled(true)` 隐藏状态栏与通知栏，防止孩子从通知栏绕出去。**默认不开**（会影响电量与时间的可见性），仅在宵禁/超时拦截页临时开启 |

#### 9.5.2 `Device Settings` 跳转清单

每一行跳到**真实的**安卓系统设置面板。这是安卓专有能力（iOS 无法深链到具体设置项），必须用起来。

| 行 | 安卓 Intent Action | 家长控制门禁 |
|---|---|---|
| Wi-Fi | `Settings.ACTION_WIFI_SETTINGS` | 无（连网是基本需求） |
| Bluetooth | `Settings.ACTION_BLUETOOTH_SETTINGS` | 无 |
| Display（亮度等） | `Settings.ACTION_DISPLAY_SETTINGS` | 无 |
| Sound | `Settings.ACTION_SOUND_SETTINGS` | 无 |
| Battery | `Intent.ACTION_POWER_USAGE_SUMMARY` | 无 |
| Storage | `Settings.ACTION_INTERNAL_STORAGE_SETTINGS` | 无 |
| System language | `Settings.ACTION_LOCALE_SETTINGS` | **需 PIN**（改系统语言会影响全局） |
| Date & time | `Settings.ACTION_DATE_SETTINGS` | **需 PIN**（改时间可绕过屏幕时间；Device Owner 下另加 `DISALLOW_CONFIG_DATE_TIME`） |
| Apps | `Settings.ACTION_APPLICATION_SETTINGS` | **需 PIN**（可从这里卸载或清数据） |
| All settings | `Settings.ACTION_SETTINGS` | **需 PIN** |

**每行必须显示真实当前值**，不再是硬编码。真实值来自原生桥（见第十章）：Wi-Fi SSID、亮度百分比、音量、电量、剩余存储、系统语言。

**Intent 不可用的兜底**：部分厂商 ROM 会移除或改名某些设置 Activity。跳转前用 `intent.resolveActivity(pm) != null` 判定，不可用则该行置灰并标 `Not available on this device`。

#### 9.5.3 Path A 的风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| Device Owner 必须在产线设置 | **事实不可逆**：抹机后可补设，但已售设备的补救等于清空用户数据 | 与硬件厂商确认产线流程；已售设备走「恢复出厂 + 重新配置」的售后流程。**同时确认 `07` Q74（平台签名 priv-app）——它可随 OTA 补装，是唯一真正可后补的路径** |
| 强制更新可能把设备锁成砖 | C-LingoAIOS 是 Home 且被强制更新拦截，用户无法进系统设置连网 | 强制更新页必须保留 Wi-Fi 设置入口（7.5.5 已规定） |
| C-LingoAIOS 崩溃 = 设备不可用 | Home 崩溃后安卓会反复重启它 | 必须有崩溃兜底页；`06` 的崩溃率指标（< 0.3%）在 Path A 下是**设备可用性指标**，不只是体验指标 |
| 售后与调试困难 | 无法从桌面进开发者选项 | 保留「Exit to Android」的 PIN 入口 |

### 9.6 Path B · C-LingoAIOS 不是 launcher

#### 9.6.1 需求轮廓

| 项 | 需求 |
|---|---|
| `/android/home` | **从 3.0 路由表移除**。按 Home 键就能看到真实桌面，仿真毫无价值 |
| `/android/settings` | 同样**移除**，或降级为一个只含「Open Android settings」单个按钮的中转页 |
| `/apps` 的「Go to Settings」黑条 | 改为直接 `startActivity(Settings.ACTION_SETTINGS)` |
| 家长控制 | **能力大幅缩水**。只能做 App 内 enforcement：应用内屏幕时间、应用内内容分级、应用内路由拦截。**不能**阻止孩子退出去玩别的、不能阻止清除应用数据、不能阻止改系统时间 |
| 家长控制的诚实声明 | `/parental-controls` 顶部常驻：`Limits apply inside C-LingoAIOS only. Your child can still use other apps on this device.` 这句话必须写在 UI 上，不能只写在文档里 |
| 屏幕时间 `scope` | 只允许 `'learning'`；`'device'` 选项不显示（因为拿不到 `PACKAGE_USAGE_STATS` 授权的话就没数据，而拿到了也管不住） |
| APK 静默安装 | 不可用。全部安装走系统确认弹窗 |
| 自动更新 | 不可用（见 GWT-E-71） |
| 内容包存储 | 仍可用应用私有目录（无需 Device Owner） |
| 护眼全局生效 | 需 `WRITE_SETTINGS` 用户授权；系统夜览 API 不可用（`@SystemApi`） |

#### 9.6.2 Path B 的后果

Path B 下，C-LingoAIOS 与 `00-总纲` 声明的「开机即接管整台设备的学习操作系统外壳」**不符**，定位需要同步下调；同时家长控制从「真能管」降为「App 内建议」，儿童隐私承诺的兑现程度也要相应下调，隐私政策文案需重写。

**所以这个决策不只是技术选型，它会改动 `00-总纲` 的产品定位段落和隐私政策文本。**

### 9.7 两条路径对照

| 维度 | Path A（launcher + Device Owner） | Path B（普通应用） |
|---|---|---|
| 与 `00-总纲` 定位一致 | ✅ | ❌ 需下调定位 |
| 家长控制可真正生效 | ✅ | ❌ 仅 App 内 |
| 屏幕时间可管整机 | ✅ | ❌ |
| 抵抗「清数据绕过」 | ✅ | ❌ |
| APK 静默安装 / 自动更新 | ✅ | ❌ |
| 护眼全局生效 | ✅ 无需用户授权 | ⚠️ 需 `WRITE_SETTINGS` |
| 产线流程要求 | ⚠️ 必须在产线设 Device Owner | ✅ 无 |
| 单点故障风险 | ⚠️ Home 崩溃 = 设备不可用 | ✅ 低 |
| 售后可维护性 | ⚠️ 需预留 Exit 通道 | ✅ |
| `/android/home` | 删除 | 删除 |
| `/android/settings` | 改造为真实跳转清单 | 删除或降为单按钮中转 |

**本篇建议 Path A**，理由是家长控制与儿童合规（第四章）在 Path B 下无法兑现产品已经做出的承诺。但这是业务决策，标 `[待确认]`。

### 9.8 GWT · 定位决策（按最终路径取其一）

**GWT-E-72 仿真页已清除（两条路径共同）**
- **Given** 3.0 构建完成
- **When** 测试访问 `/android/home`
- **Then** 该路由不存在（404 处理或重定向到 `/apps`）；应用内**不存在任何伪造 Wi-Fi 名、亮度百分比、电量、剩余存储数字的页面**

**GWT-E-73 Path A · Home 锁定**
- **Given** 走 Path A，设备已在产线配置为 Device Owner，C-LingoAIOS 已注册为持久默认 Home
- **When** 用户在任意应用中按 Home 键
- **Then** 回到 C-LingoAIOS 的 `/Home`；系统**不弹出**「选择桌面应用」的选择器；用户无法在系统设置中把默认桌面改成别的应用

**GWT-E-74 Path A · 设置跳转清单显示真实值**
- **Given** 走 Path A，设备连接的 Wi-Fi 为 `School-Guest`，屏幕亮度 45%，剩余存储 24 GB，家长控制未启用
- **When** 用户进入 `Device Settings`
- **Then** Wi-Fi 行显示 `School-Guest`、Display 行显示 `Brightness 45%`、Storage 行显示 `24 GB free`，全部来自原生桥；点击 Wi-Fi 行跳到**真实的**安卓 Wi-Fi 设置面板；返回后回到 `Device Settings`

**GWT-E-75 Path A · 敏感设置需 PIN**
- **Given** 走 Path A，家长控制已启用，用户处于学习者态
- **When** 用户点击 `Date & time` 行
- **Then** 弹出 PIN 面板；未通过验证不跳转；通过后跳系统日期时间设置；同时 Device Owner 的 `DISALLOW_CONFIG_DATE_TIME` 限制使该面板中的修改操作不可用（双重保护）

**GWT-E-76 Path A · Intent 不可用兜底**
- **Given** 走 Path A，设备 ROM 移除了 `Settings.ACTION_BLUETOOTH_SETTINGS` 对应的 Activity
- **When** 用户进入 `Device Settings`
- **Then** Bluetooth 行置灰并标 `Not available on this device`；点击不触发跳转、不抛异常、不崩溃

**GWT-E-77 Path B · 诚实声明**
- **Given** 走 Path B，家长控制已启用
- **When** 用户进入 `/parental-controls`
- **Then** 页面顶部常驻 `Limits apply inside C-LingoAIOS only. Your child can still use other apps on this device.`；屏幕时间设置中**不出现** `Device` 这个 scope 选项；`Auto-update` 开关置灰

## 十、安卓原生桥接口汇总表

### 10.1 桥的形态与约定

| 项 | 规格 |
|---|---|
| 注入方式（**已按 `07` 第七节评审纠正 5 修订**） | **不用 `addJavascriptInterface`**：它只能传原始类型与字符串、**同步阻塞主线程**，且对页内**任意 origin** 可见，与「只暴露白名单」的目标直接相悖。改用 **`WebViewCompat.addWebMessageListener` 绑定 origin** + `callbackId` 异步协议。注意 **Binder 单次事务约 1 MB 上限**，大 payload（如笔迹、图片）必须走文件句柄而非消息体 |
| 能力探测 | `getCapabilities()` **必须按单项返回**，不能只给一个总布尔——否则「桥可用但 OCR 不可用」这类常见情形无法表达。且**从系统设置页返回时必须重新探测** |
| Web 侧封装 | `src/native/nativeBridge.ts` 统一包 Promise，处理超时（默认 10 秒）、序列化、错误映射 |
| 能力探测 | `nativeBridge.isAvailable()` 与 `nativeBridge.getCapabilities(): Capability[]`。**所有调用方必须先探测**，不得假定桥存在 |
| 版本协商 | 桥自身有 `bridgeVersion`；Web 层声明所需最低版本，不满足时该功能降级并提示 `Update the C-LingoAIOS device app` |
| 返回约定 | 统一 `{ ok: true, data }` 或 `{ ok: false, code, message }`。`code` 为稳定枚举，`message` 仅供日志**不直接展示给用户**（无法 i18n） |
| 大数据传输 | 图标、文件内容等不走桥消息体。桥返回**本地文件 URI** 或 `content://`，Web 层用 `<img src>` / `fetch` 读取 |
| 安全 | 桥只暴露本篇列出的方法；不暴露任意 `startActivity`、任意文件读写、任意 shell 执行 |
| 降级总原则 | 桥不可用时，依赖它的功能**显式禁用并说明原因**，不静默失败、不假装成功 |

### 10.3 权限申请的统一规则

**这一节是本篇对安卓开发的硬性要求。**

1. **不在开机向导里批量索要权限**。安卓用户对「刚装上就要一堆权限」的反应是拒绝。全部权限在**用户第一次真正需要它的那个操作**上申请。
2. **申请前先解释**。每个 runtime / special 权限在跳系统授权页之前，先用产品自己的一页说清三件事：为什么需要、不给会失去什么功能、给了之后我们用它做什么。
3. **被拒不纠缠**。拒绝后功能降级并在对应设置项旁显示一个可点的「Enable」说明，**不在其他页面弹窗骚扰**，不在同一会话内二次请求。
4. **special 权限走 Intent 不走 `requestPermissions`**。`WRITE_SETTINGS`、`SYSTEM_ALERT_WINDOW`、`PACKAGE_USAGE_STATS`、`REQUEST_INSTALL_PACKAGES`、`SCHEDULE_EXACT_ALARM`（13+）均属此类，`requestPermissions()` 对它们无效——必须 `startActivity` 到对应的系统开关页，并在返回时**重新判定**实际状态（用户可能在系统页面里什么都没做就返回了）。
5. **Device Owner 能力不做运行时申请**。Device Owner 是出厂配置的结果。桥的 `getCapabilities()` 要能明确告知 Web 层「本机是否具备 Device Owner 能力」，Web 层据此决定显示哪一套 UI（Path A 或 Path B 的能力集）。
6. **不申请的权限清单（明确拒绝）**：
   - `MANAGE_EXTERNAL_STORAGE`（全盘文件访问）——内容包用私有目录即可，无必要。
   - `READ_PRIVILEGED_PHONE_STATE` / 硬件序列号读取——与「不采集硬件序列号」的隐私原则冲突。
   - `ACCESS_FINE_LOCATION`——仅为显示 Wi-Fi SSID 不值得要定位权限；本篇已把该需求降级（见 10.2.6）。
   - 通讯录、短信、通话记录、麦克风常驻监听——与产品功能无关。麦克风仅在 AI 口语与录音功能中按需申请（属域 D）。

### 10.4 GWT · 原生桥

**GWT-E-78 桥不可用时全域降级**
- **Given** 应用运行在桌面浏览器中（`window.ClingoNative` 不存在）
- **When** 用户依次访问 `/apps`、`/apps-catalog`、`/nsk-app-store`、`/system/content-cache`、`/parental-controls`、`/profile`
- **Then** 每一页都正常渲染不白屏；依赖原生的功能显示禁用态与原因说明；`/apps-catalog` 显示 `App list requires the C-LingoAIOS device runtime` 而不是一份假的应用列表；控制台无未捕获异常

**GWT-E-79 权限先解释后跳转**
- **Given** `canInstallPackages() === false`
- **When** 用户在 `Device Apps` 点击某应用的 `Install`
- **Then** 先弹出产品自有的说明页，写明「为什么需要」「不给会怎样」「会用它做什么」；用户点「Continue」后才跳系统的「安装未知应用」开关页；用户在系统页直接返回（未开启）时，回到 `Device Apps` 并**重新判定**权限状态，横幅仍在，**不再自动弹第二次**

**GWT-E-80 桥版本不匹配**
- **Given** 设备上的原生壳 `bridgeVersion = 2`，而 Web 层的内容包下载功能要求最低 `bridgeVersion = 3`
- **When** 用户进入 `Content & Storage` 并尝试下载
- **Then** 下载按钮禁用；显示 `Update the C-LingoAIOS device app to download content`；页面其他部分（已下载内容浏览、清理）正常工作
