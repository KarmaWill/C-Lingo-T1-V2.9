## 一、概述与本篇范围

### 1.1 本篇职责

域 D 是 C-LingoAIOS 的「非教材、非考试」学习面：学习者在这里**开口说**、**动手写**、**查与玩**。它与域 B（教材主线）的关系是：教材给输入，域 D 给输出与练习；与域 C（HSK 备考）的关系是：HSK 给评级，域 D 给日常能力建设。域 C 已冻结，本篇任何需求**不得**改动 HSK 作答生命周期、`attemptId`、9 种题型与判分快照。

本篇把 14 条路由按能力聚成四组：

| 组 | 路由 | 能力定位 |
|---|---|---|
| AI 口语 | `/ai-chat` | 开口练习 + 结束后统一评分报告 |
| 阅读与识别 | `/reading-buddy`、`/reading-buddy/:docId`、`/camera` | 把学习者自带的文本 / 实体世界的中文变成可学材料 |
| 语音与书写基本功 | `/pinyin-chart`、`/character-writing` 系列 5 条 | 拼音与汉字的底层技能训练 |
| 卡片与小游戏 | `/flashcards`、`/lingo-flash`、`/grammar-puzzle`、`/syntax-snap` | 记忆巩固与轻量游戏化 |

### 1.4 本域设计原则

沿用 `00-总纲.md` 第二节，并在本域具体化：

| 原则 | 本域落法 |
|---|---|
| 游戏化不儿童化 | 分数、连击、解锁可用；禁止 Q 版吉祥物主导画面、禁止夸张音效。评分用中性数值与色带，不用哭脸/笑脸表情 |
| 食指可点 | 本域所有可点元素最小命中区 **≥ 88×88 px @1920×1200 设计稿**（经 `figmaPx` 缩放后实测不小于 48dp）；拖拽把手 ≥ 96×96 |

### 2.4 配置屏与难度生效（A7）

**现状**：Easy / Medium / Hard 三个卡片只改 `difficulty` 状态与说明文案，**不影响任何行为**。

**3.0 需求**：难度必须同时作用于三处，缺一即视为未实现。

| 难度 | 词表上限 | LLM 系统提示约束 | TTS 语速（`rate`） | 单轮期望长度 |
|---|---|---|---|---|
| Easy | HSK1–2 | 只用 HSK1–2 词与基本句式，单句 ≤ 8 字 | 0.65 | 1 句 |
| Medium | HSK1–3 | 日常词汇，允许复句，单句 ≤ 15 字 | 0.9 | 1–2 句 |
| Hard | HSK1–4 | 允许成段表达与追问，单句 ≤ 25 字 | 1.0 | 2–3 句 |

- 难度默认值 **Medium**。
- 「Slow speech」开关与难度**正交**：打开时在当前难度 `rate` 上再乘 0.72（Medium 0.9 → 0.65，与现状数值一致）。
- 难度在会话开始后**锁定**，中途不可改；需要改则结束当前会话重开（避免同一份报告里混着两套口径）。
- HSK3–6 词表在一期无内容，Hard 的词表上限实际落在 HSK4 `[待确认]`。

**Start practice 校验**

| 字段 | 规则 | 不满足时表现 |
|---|---|---|
| User Role | 非空，1–24 字符，去首尾空格 | 按钮置灰 + 该字段红框 |
| AI Role | 同上 | 同上 |
| Scene | 非空，1–120 字符 | 同上 |

`Message` 字段（在现状基础上增删，**粗体**为 3.0 新增或改动）：

| `translation` | string | 否 | 按当前 `locale.id` 生成 |
| `timestamp` | Date | 是 | — |
| ~~`score`~~ | ~~number~~ | — | **3.0 移除**：对话中不再挂分数（A1） |

| 项 | 规则 |
|---|---|
| 默认输入模式 | **voice**（`inputMode` 默认语音，与现状一致） |

## 三、口语评分体系

> 本章是本篇最重头的一章。它同时纠正 A1（评分时机）、A3（评分数据来源），并补齐产品规则要求但当前**完全缺失**的「单句反复练习到满分」与「发音深度剖析」。

### 3.1 现状基线

| 事实 | 位置 | 与规则的关系 |
|---|---|---|
| 语音消息发出后**立即**生成分数 | `AIChatPage.tsx` L605-614、L2433+ | **与产品规则相反**（A1） |
| 分数是随机数 | `mockVoiceScore()` L180-185，一半落 60–98、一半落 20–59 | 仅为演示两种样式（A3） |
| 四维 breakdown 由总分加抖动伪造 | `buildSpeechBreakdown()` L187-195，`completeness` 额外乘 0.75 | 非真实评测（A3） |
| 结束页分数 | 对已有逐条分数取均值 | 口径需重定义 |
| 单句复练 | **不存在** | 规则要求，缺失 |
| 发音深度剖析 | **不存在** | 规则要求，缺失 |

### 3.2 评分时机（核心需求）

**产品规则**：口语评分在最后统一给出，不打断学习。

| 阶段 | 允许出现 | 禁止出现 |
|---|---|---|
| 对话进行中（`CHAT`） | 阶段提示（Listening / Thinking / Speaking）、拼音、翻译、词汇联想、Deep Dive | **任何分数、任何评级色、任何「你说错了」式即时纠错**；不得出现红黄绿等评价性着色 |
| 点击 Finish 之后 | 评分中的过渡态 → 完整报告 | — |

**实现约束**

1. 语音消息在对话中**只记录** `audioRef` + ASR 文本 + `asrConfidence`，不触发任何评分调用。
2. 点击 Finish 后进入 `SCORING` 过渡态：批量把本次会话所有 `isVoiceInput=true` 的消息送评分，并行上限 4 路。
3. 过渡态展示进度（"Scoring your practice… n/m"），预算 P50 ≤ 4 s、P95 ≤ 10 s；超过 15 s 转「部分完成」（见 3.9）。
4. 会话中途退出（非 Finish）：弹确认框，提供两个出口——「Discard」不评分不入历史；「Finish & score」走正常评分流程。
5. 若本次会话语音消息数为 0（全程文字输入），不调用发音评测，报告中发音维度显示 "Not measured"，总分只按语言维度计算（3.3）。

### 3.3 评分维度与口径

保留现有四维命名（`speech` / `fluency` / `accuracy` / `completeness`），但重新定义口径，并区分「单句分」与「会话总分」。

**单句分（每条语音消息一份）**

| 维度 | 口径 | 取值 | 数据来源 |
|---|---|---|---|
| `accuracy` 发音准确度 | 音素级与参考发音的偏离度，含声母、韵母、声调 | 0–100 整数 | 发音评测能力 |
| `fluency` 流利度 | 语速稳定性、停顿次数与时长、拖音 | 0–100 整数 | 发音评测能力 |
| `completeness` 完整度 | 实际说出内容对目标句/预期表达的覆盖率 | 0–100 整数 | 发音评测能力 |
| `speech` 综合口语分 | `round(accuracy×0.5 + fluency×0.25 + completeness×0.25)` | 0–100 整数 | 客户端计算 |

- 权重写在配置里，不硬编码在组件中，便于调参 `[待确认]`（初始值按上表）。
- 声调错误单独计数，在逐句分析中单列（中文学习者的高频问题）。

**会话总分**

| 项 | 规则 |
|---|---|
| 公式 | `总分 = round(口语分均值 × 0.6 + 语言分 × 0.4)` |
| 口语分均值 | 本次会话全部语音消息的 `speech` 算术平均；无语音消息时该项不参与，语言分权重升为 1.0 |
| 语言分 | 由 LLM 侧给出的语法 / 用词评估，0–100；口径 `[待确认]` |
| 阈值 | ≥ 60 为通过态（报告用绿 `#3FB266`），< 60 为待提升（红 `#F34D47`）。与 `PracticeReportView` 现有 `high = score >= 60` 一致 |
| 边界 | 任一来源缺失时，报告显示该维度 "Not measured"，**不用 0 分代替**，也不用随机值填充 |

### 3.4 逐句分析

报告中每条语音消息对应一行，可展开：

| 展示项 | 内容 | 缺省行为 |
|---|---|---|
| 原句 | 学习者实际说出的 ASR 文本 | `asrConfidence < 0.6` 时加「Recognition may be off」标注 |
| 音频回放 | 播放原始录音；受播放代次令牌管辖 | 录音已清理时按钮置灰 |
| 参考音 | 目标句的标准发音（TTS 或预录） | 无参考句时用 ASR 文本合成 |
| 四维条 | `accuracy` / `fluency` / `completeness` / `speech` 横条 + 数值 | 缺失维度显示 "Not measured" |
| 逐字标记 | 每个汉字按发音准确度着色：≥85 正常、60–84 橙、<60 红；声调错误在字上加声调角标 | 无字级数据时退化为整句一个色 |
| 建议 | 1 条针对性建议（≤ 40 字） | 无则隐藏该行 |

### 3.5 发音深度剖析

从逐句分析的任一**红色字**进入，展示：

1. 该字的目标拼音（声母 / 韵母 / 声调分列）与学习者实际被识别的发音。
2. **口型示范视频**：复用第八章 8.6 定义的同一套嘴型视频资源（按音节键索引），避免两套资源。
3. 常见错因提示（如「b/p 送气」「an/ang 前后鼻音」「三声变调」），文案随 `locale.id`。
4. 「Practice this sound」按钮 → 进入 3.6 的单句复练，目标缩小为该字所在的词。

无嘴型视频资源的音节：跳过第 2 项，其余照常展示，不留空块。

### 3.6 单句反复练习到满分（新增）

**产品规则**：支持针对单句反复练习直到满分。

| 项 | 规则 |
|---|---|
| 入口 | 报告逐句分析行的 "Practice" 按钮 → `DRILL` 屏 |
| 目标 | 单句或单词，展示目标文本 + 拼音 + 参考音播放 |
| 循环 | 录音 → 评分 → 显示新分数与逐字着色 → 可继续录 |
| 次数 | 单句不限次；单次会话内 `DRILL` 总调用次数上限 **30** 次 `[待确认]`（成本护栏） |
| 「满分」判定 | `speech ≥ 90` 视为达标，显示达标态与庆祝反馈（轻量，不儿童化） |
| 最佳成绩 | 记录该句历史最佳分；报告中该句的分数**更新为最佳分**，并标注 "improved"，总分随之重算 |
| 退出 | 返回报告，保留本次改进结果 |
| 离线 | 入口置灰，提示需要联网 |
| 失败 | 单次评分失败显示 Retry，不计入 30 次上限 |

### 3.7 `explanation` 字段展示

**现状**：`PracticeReportCorrection.explanation` 在类型定义（`PracticeReportView.tsx` L22-27）与 `chatHistorySlice` 的 mock 数据中都存在，**但 Key Fixes 的 UI 未渲染它**。

**3.0 需求**

1. Key Fixes 每条 correction 在 `original`（删除线）→ `corrected` 之下，**必须**展示 `explanation`。
2. `explanation` 语言随 `locale.id`；长度 ≤ 120 字符，超出折行不截断。
3. `explanation` 缺失时隐藏该行（不显示空白块、不显示占位符）。
4. type 标签沿用现有三类：`grammar`（`#FF6B35`）/ `vocabulary`（`#00B4A0`）/ `fluency`；`chatHistorySlice` 中还出现过 `pronunciation`，3.0 统一为四类并补 `pronunciation` 的标签色 `[待确认]`。

### 3.8 评分能力选型与成本

| 项 | 内容 |
|---|---|
| 能力提供方 | `[待确认]`。必须支持：中文音素级评测、声调评测、字级分数返回、无参考文本（开放式）评测 |
| 关键筛选条件 | 开放式评测（学习者说什么都要能评）是硬性要求——本产品是自由对话，不是跟读 |
| 调用方式 | 经自有后端网关；客户端不持密钥 |
| 单次调用成本 | `[待确认]`。需按「一次练习 ≈ 8 条语音 + 平均 5 次复练 = 13 次评测」折算单会话成本 |
| 音频规格 | 采样率 16 kHz、单声道、PCM 或平台推荐编码 `[待确认]`；单条上限 60 秒 |
| 延迟预算 | 单条 P50 ≤ 1.2 s、P95 ≤ 3 s、硬超时 8 s；批量并行上限 4 路 |
| 配额 | 设备日评测次数上限 `[待确认]`；超限后新会话仍可练习但报告只出语言维度 |
| 隐私 | 录音仅用于评测，评测完成即可删除；不做声纹、不关联身份（匿名 `deviceId` 体系见 `AGENTS.md`） |

### 3.9 离线降级与失败兜底

| 场景 | 表现 |
|---|---|
| 完全离线 | `TOPIC_SELECTION` 即置灰 Start，提示需要联网；不进入对话，避免学习者练完一场却拿不到报告 |
| 对话中途断网 | `llm_fail` 气泡 + Retry；点 Finish 时若评分不可用，报告进入「部分完成」态 |
| 评分部分失败 | 报告正常出，失败的句子标 "Score unavailable"，总分按成功部分计算并在总分旁标注 "based on n of m lines" |
| 评分全部失败 | 报告仍生成，展示时长 / 轮次 / Key Fixes（若语言分可用），总分区显示 "Not scored" + Retry 全量评分按钮 |
| 评分超时 15 s | 自动转「部分完成」，不无限等待 |
| 音频丢失 | 该句不送评测，标 "Audio unavailable"，不阻塞其余句子 |

## 五、AI 对话的引导页与首次体验（A9）

### 5.1 现状基线

产品规则要求「首次进入显示引导页面，后续直接进入对话」。当前 `/ai-chat` **没有任何「首次」判定**，每次进入都从 `HOME` 走完整流程（HOME → TOPIC_SELECTION → CONFIG → ROLE_SELECTION → CHAT），老用户每次都要重复 4 步配置。

3 页横向滑动 + 底部指示点，不强制停留时长：

|---|---|---|
| 1 | How it works | 选模式 → 设定角色 → 开口说 → 结束后拿报告。**明确写出「练习中不打断、评分在最后统一给出」** |

- 指示点与左右滑动均可导航；最后一页按钮文案为 "Start practicing"。

## 七、Camera `/camera`

### 7.1 现状基线（A11）

`local-agent-app/src/pages/CameraPage.tsx`（2115 行）。**四个模式的核心能力全部是 mock**。

| 模式 | 现状 |
|---|---|
| OCR | 模拟 canvas 取景；快门 → `handleScan` **2000 ms 假延迟**（L1926-1931）→ 返回固定 `mockOCRResult`（L106-116：`我爱学中文`）；对焦框可拖拽与四角缩放（L248-341）但纯 UI，不影响识别 |
| Voice | 录音按钮**不申请麦克风、不录音**；1200 ms 后调 `mockTranslate('你好，今天天气很好')`（L695-707） |
| Text | 双栏输入 + Translate → `mockTranslate(input)`（L838），内部只做中文正则判断后返回固定结构，含 1500 ms 假延迟 |
| Fingertap（点读） | 教程页 + mock AR 检测词 |
| History | 筛选 / 删除 / 清空；读写 `localStorage` 键 `camera_translation_history`，上限 **50** 条 |

**结论**：Camera 是本篇中「现状与需求差距最大」的模块。3.0 必须先定清 Web 层与安卓原生层的职责边界，否则无法排期。

### 7.2 分层职责边界

C-LingoAIOS 的业务页面跑在 WebView 中，系统相机、OCR、麦克风必须由安卓原生层提供。

| 能力 | 原生层职责 | Web 层职责 |
|---|---|---|
| 相机预览 | 打开摄像头、输出预览帧到原生 SurfaceView，Web 层以透明区域「开洞」叠加 UI | 绘制取景框、快门、模式切换等全部 UI；上报取景框在屏幕坐标系中的矩形 |
| 拍照 | 按快门时抓帧、按取景框裁剪、压缩 | 发起调用、接收结果、展示 |
| OCR | 执行识别（离线引擎优先），返回文本块 + 每块的坐标 | 渲染识别结果、允许学习者点选某块再翻译 |
| 麦克风与 ASR | 申请权限、录音、语音识别 | 录音 UI、倒计时、结果展示 |
| TTS | 提供中文男/女声 | 选择音色、控制播放与停止 |
| 翻译 | 不负责 | 经后端网关调用翻译能力 |
| 权限 | 系统权限弹窗、跳设置页 | 判断当前权限状态、渲染降级 UI |

**桥接口约定**（命名与签名为建议值，需与安卓开发对齐 `[待确认]`）：

| 方法 | 入参 | 返回 | 失败码 |
|---|---|---|---|
| `camera.open()` | `{ facing: 'back' }` | `{ ok, sessionId }` | `PERMISSION_DENIED` / `DEVICE_BUSY` / `NO_CAMERA` |
| `camera.setViewport()` | `{ x, y, w, h }`（屏幕 px） | `{ ok }` | `NO_SESSION` |
| `camera.capture()` | `{ cropToViewport: true }` | `{ ok, imageRef }` | `NO_SESSION` / `CAPTURE_FAILED` |
| `camera.close()` | — | `{ ok }` | — |
| `ocr.recognize()` | `{ imageRef, lang: 'zh' }` | `{ ok, blocks: [{ text, box, confidence }] }` | `ENGINE_UNAVAILABLE` / `TIMEOUT` |
| `mic.start()` | `{ lang: 'zh-CN', maxMs: 60000 }` | `{ ok, sessionId }` | `PERMISSION_DENIED` / `DEVICE_BUSY` |
| `mic.stop()` | `{ sessionId }` | `{ ok, text, audioRef, confidence }` | `NO_SESSION` |
| `tts.speak()` | `{ text, voice, rate, token }` | `{ ok }` | `VOICE_UNAVAILABLE` |
| `tts.stop()` | — | `{ ok }` | — |
| `permission.request()` | `{ name: 'camera' \| 'microphone' }` | `{ status: 'granted' \| 'denied' \| 'blocked' }` | — |
| `permission.openSettings()` | — | `{ ok }` | — |

**桥不可用时**（在浏览器中调试、或原生版本过旧）：全部模式展示「Camera requires the device app」提示态，Text 模式仍可用（不依赖硬件）。**禁止**回落到当前的 mock 数据假装成功。

### 7.3 模式逐条需求

**OCR（拍照翻译）**

| 项 | 规则 |
|---|---|
| 进入 | 申请相机权限 → `camera.open()` → `camera.setViewport()` |
| 取景框 | 保留可拖拽移动与四角缩放；最小 120×120 px，最大不超出预览区；拖拽规范见第十一章 |
| 快门 | `camera.capture()` → `ocr.recognize()`；处理中显示真实进度而非固定 2 秒 |
| 结果 | 识别文本块列表；点击某块 → 翻译并展示 原文 / 拼音 / 译文 / 分词 |
| 识别为空 | 提示 "No Chinese text found — move closer or improve lighting"，保留重拍 |
| 延迟预算 | 拍照 ≤ 300 ms；OCR P50 ≤ 800 ms、P95 ≤ 2 s、硬超时 5 s；翻译 P50 ≤ 1 s、P95 ≤ 3 s、硬超时 8 s |
| 离线 | OCR 用离线引擎，**可离线**；翻译需联网，离线时展示原文 + 拼音 + 分词，译文区提示需联网 |

**Voice（语音翻译）**

| 项 | 规则 |
|---|---|
| 录音 | 长按或点击开始，`mic.start()`；上限 60 秒，剩余 10 秒倒计时 |
| 权限 | 首次申请；`blocked` 时常驻 "Enable microphone" 入口 → `permission.openSettings()` |
| 结果 | ASR 文本 → 翻译 → 展示原文 / 拼音 / 译文 |
| 空识别 | 提示 "Didn't catch that"，不入历史 |
| 离线 | ASR 若原生离线可用则可用；翻译不可用时同 OCR 处理 |

**Text（文本翻译）**

| 项 | 规则 |
|---|---|
| 输入 | 双栏；输入上限沿用 `MAX` 常量（现状值以代码为准），超出截断并提示 |
| 方向 | 自动判断中↔当前界面语言；提供手动切换 |
| 触发 | 点击 Translate；输入为空时按钮置灰 |
| 离线 | 按钮置灰并提示需要联网 |

**Fingertap（点读）**

| 项 | 规则 |
|---|---|
| 定位 | 3.0 保留为**教程 + 实验能力**，不承诺准确率 |
| 实现 | 基于 OCR 文本块坐标 + 指尖位置匹配最近文本块 |
| 指尖检测 | 依赖原生能力 `[待确认]`；原生不提供时该模式入口隐藏（不做假检测） |
| 优先级 | P2，可整块延后 |

**History**

| 项 | 规则 |
|---|---|
| 存储 | 沿用 `camera_translation_history`，上限 50 条，超出丢弃最旧 |
| 条目 | `type`（ocr/voice/text）、原文、拼音、译文、时间戳、缩略图引用（OCR）|
| 操作 | 按类型筛选、单条删除（二次确认）、清空（二次确认） |
| 隐私 | 只存本机；缩略图随条目删除一并删除 |
| 损坏兜底 | 解析失败时重写为空数组，不白屏 |

### 7.4 权限申请时机

| 权限 | 申请时机 | 拒绝后 | 永久拒绝（blocked）后 |
|---|---|---|---|
| 相机 | 首次进入 OCR 或 Fingertap 模式时，**不在进入 `/camera` 时**统一申请 | 该模式显示说明态 + "Allow camera" 重试按钮；其余模式可用 | 显示 "Enable camera in Settings" → `permission.openSettings()` |
| 麦克风 | 首次按下 Voice 录音键时 | 同上（降级到 Text 模式建议） | 同上 |

**原则**：权限申请必须**由用户动作触发**，且前置一屏说明为什么需要（避免青少年用户直接点拒绝）。

## 八、拼音表 `/pinyin-chart`

> **口径优先级**：本章不得与 [`docs/PINYIN_CHART_ALGORITHM.md`](../../docs/PINYIN_CHART_ALGORITHM.md)（v1.0）冲突。该文档是声母×韵母合法性算法的权威定义，本章只在其之上补产品层需求（嘴型视频、字库覆盖、交互口径）。

### 8.1 现状基线

| 项 | 事实 |
|---|---|
| 左列 | Initial Consonants，数据 `PINYIN_INITIALS`（`PinyinChartPage.tsx` L74；渲染 L289-329），**23 个**声母，含 `zh/ch/sh/y/w` |
| 右列 | Finals，数据 `PINYIN_FINALS`（L75；渲染 L355-403），**31 个**韵母，含 `ü/üe/ün/üan` |
| 底部 | Combine & Tones：公式 chip（L439-490）+ 4 个声调钮 `TONE_OPTIONS`（L47-52；渲染 L500-551） |
| 合法性 | `isValidPair` / `buildValidBaseSyllable`（`src/utils/pinyinChartValidate.ts` → `src/data/pinyinChartMatrix.ts`），bootstrap 自 395 条标准音节表，当前 **424 个合法组合**，支持 `allow` / `deny` 补丁 |
| 拼写 | `combineInitialFinal`（`src/utils/pinyinCombine.ts`）：j/q/x + ü 去两点、y/w 省写规则 |
| 标调 | `applyTone`，优先级 `a > e > ou 的 o > 从后往前 i/u/ü` |
| 发音 | `speakPinyin()` → `speechSynthesis`，`lang='zh-CN'`、`rate=0.85` |
| 字库 | `PINYIN_SYLLABLE_LOOKUP`（L80-171），**约 18 个音节** |
| 无词条态 | Empty State（L796-846）："Valid syllable… lookup not available yet"；算法文档明确要求**不用 fallback 假字「音」** |
| 释义 | `resolvePinyinMeaning(..., locale.id)`，跟随 UI 语言 |
| 缺失 | **全文件无 video / mouth / lip 相关引用**，嘴型示范视频不存在（A12） |

### 8.2 矩阵与合法性（沿用算法文档）

3.0 **不改**算法层，以下为需求层的确认与约束：

| 项 | 规则 |
|---|---|
| 合法性判定 | 唯一来源 `isValidPair(initial, final)`，O(1) 查 `VALID_PAIR_SET` |
| 生效公式 | `VALID_PAIRS = BOOTSTRAP ∪ allow − deny`，补丁写在 `PINYIN_CHART_OVERRIDES` |
| 合法 ≠ 有词条 | 两层独立；合法无词条**必须**走 Empty State，**禁止**回落假字 |
| 零声母音节 | 当前 36 个零声母音节（`a`/`ai`/`an`/`e`/`er`/`o`/`ou` 等）UI 不可达 |
| 3.0 处置 | **新增零声母行**：在声母列首位加 `∅`（显示为 "—"，无障碍标签 "no initial"），使 `a`、`e`、`er`、`ou` 等可达。需同步更新矩阵 bootstrap 与单测 `[待确认]`（是否纳入 3.0 由业务方定） |

### 8.3 对称联动与三态

沿用算法文档第 7 节，需求层复述为可测口径：

| 声母按钮状态 | 条件 | 表现 |
|---|---|---|
| 选中 | `initial === selectedInitial` | 实心橙 |
| 亮起 | 对面已选 final 且 `isValidPair` 为真 | 浅橙底 + 边框 |
| 置灰 | 对面已选 final 且 `isValidPair` 为假 | disabled，不可点 |
| 默认 | 对面未选 | 全可点 |

韵母侧对称（青色系）。**Toggle 语义**：再次点击同一项取消选中；**不 auto-snap**，选到不兼容组合时两边选中都保留，由学习者自行调整。

**Combine 区状态机**

| 声母 | 韵母 | 组合合法 | 表现 | TIP 文案 |
|---|---|---|---|---|
| 无 | 无 | — | `— + —`，四声禁用 | Tap an initial or a final to start. |
| 有 | 无 | — | `b + —` | Tap a matching option on the other side. |
| 无 | 有 | — | `— + a` | Tap a matching option on the other side. |
| 有 | 有 | ✗ | 四声禁用 | This combination is not used in Mandarin. Try another pair. |

### 9.3 笔迹采集（A14）

| 项 | 规则 |
|---|---|
| 渲染层 | `<canvas>` 覆盖田字格，尺寸与格子一致，`devicePixelRatio` 缩放避免模糊 |
| 输入事件 | **Pointer Events**（`pointerdown` / `pointermove` / `pointerup` / `pointercancel`），同时覆盖手指与手写笔；不使用 mouse 事件（当前代码用的是 mouse，安卓平板上不可靠） |
| 手写笔优先 | `pointerType === 'pen'` 时忽略同时发生的 `touch` 事件（掌托误触） |
| 掌托抑制 | 接触面积（`width`/`height`）超过阈值 `[待确认]` 的 pointer 视为手掌，丢弃 |
| 笔迹样式 | 圆头圆角，线宽随 `pressure` 在 6–14 px（设计稿）区间变化；无压感设备用固定 10 px |
| 采样 | 记录 `{x, y, t, pressure}` 点序列；相邻点距离 < 1.5 px 时抽稀 |
| 一笔定义 | `pointerdown` 到 `pointerup` 之间为一笔；`pointercancel` 视为该笔作废并清除 |
| 撤销 | "Undo" 按钮撤销上一笔，可连续撤销到空 |
| Reset | **清空 canvas 全部笔迹并回到当前步骤的第 1 笔**；`handleResetToStart` 现有的「回 Step 1」行为改为二次确认后才跨步骤重来 |
| 性能 | 落笔到出墨延迟 ≤ 50 ms `[待确认]`；1024×768 与 2000×1200 下均需达标 |
| 离线 | 采集与渲染**完全本地**，无网络依赖 |

### 9.4 笔顺校验与书写评分

| 项 | 规则 |
|---|---|
| 参考数据 | 每个字的标准笔画路径（中点序列 + 起止点），来自 9.5 的笔画数据源 |
| 单笔判定 | 三项：**起笔位置**（落点与标准起点距离 / 格宽 ≤ 阈值）、**方向**（首尾向量夹角 ≤ 阈值）、**形状**（采样点到标准路径的平均距离 / 格宽 ≤ 阈值）。阈值初值 `[待确认]` |
| 顺序 | 必须按标准笔顺；写错顺序时该笔判失败 |
| 失败反馈 | 该笔笔迹淡出消失 + 轻微震动（安卓 `HapticFeedback`）+ 重新高亮当前应写笔画（Step 1）或仅提示 "Try that stroke again"（Step 2/3）；**不弹窗、不打断** |
| 连续失败 | 同一笔连续失败 3 次后，即使在 Step 2/3 也临时显示一次方向提示（保底不卡死） |
| 进度角标 | 显示 `{已完成笔数 + 1}/{总笔数}`，随笔画**实时步进**（A17 修正）；完成时显示 `{总笔数}/{总笔数}` |
| 单字评分 | `笔顺分`（顺序正确笔数 / 总笔数）、`形状分`（各笔形状分均值）、`整体分`（加权，权重 `[待确认]`）；0–100 |
| 评分位置 | **本地计算**，不调用云端能力——书写是离线核心功能 |
| 完成态展示 | 三步各自的整体分 + 最弱的一笔提示 |

### 9.6 田字格规范（A16）

**硬约束**（`AGENTS.md` 已知易错点，本篇复述并细化）：

| 规则 | 说明 |
|---|---|
| 必须正方形 | 容器样式必须写 `aspect-ratio: 1 / 1`，宽高由同一维度推导 |
| 禁止 `flex: 1` | 不得用 `flex: 1` 让格子吃剩余空间——这会在不同分辨率下把格子拉成竖长或横长矩形 |
| 禁止固定双写宽高 | 现状的 `width: 350, height: 350` 虽然此刻相等，但两个数字各自被改动时不会同步；3.0 改为 `width: <计算值>; aspect-ratio: 1 / 1`（A16 修正） |
| 尺寸推导 | 取「可用宽度」与「可用高度」的较小值作为边长，再按 `figmaPx` 缩放；中间互动区用 flex 吃满剩余高度，格子在其中居中 |
| 辅助线 | 外框 `3px solid #C9C9C9`；横中线、竖中线、两条对角线均为 `2px dashed #D0D0D0` |
| canvas 对齐 | canvas 的 CSS 尺寸与格子完全一致，内部像素尺寸 = CSS 尺寸 × `devicePixelRatio` |
| 分辨率 | 1024×768 / 960×540 / 1920×1125 / 2000×1200 四档下均须实测为正方形（像素级宽高差 ≤ 1） |
| 适用范围 | Hub 预览格（现已合规）、Module 列表缩略格、Practice 主格、拼字功能的目标格，**一律遵守** |

## 十一、拖拽与手势交互规范（安卓平板）

### 11.1 为什么要单列一节

域 D 有四处彼此独立实现的拖拽：闪卡三向滑动（`LingoFlashPage` 阈值 90 px）、拖词成句（`/grammar-puzzle`、拼字）、相机对焦框移动与缩放（`CameraPage` `FrameDragMode`）、汉字书写的笔迹采集（本质是绘制，不是拖拽，但共享同一套触摸事件冲突问题）。当前四处的阈值、事件类型、误触处理各写各的，在安卓平板上表现不一致。

本节定义**统一口径**，四处实现必须对齐。

### 11.2 输入模型

| 项 | 规则 |
|---|---|
| 事件 | 一律用 **Pointer Events**；禁止用 mouse-only 事件（`CharacterWritingPage` 现状的 `onMouseDown/Up/Leave` 在触摸设备上不可靠） |
| 多指 | 拖拽只响应**第一个**落下的 pointer；第二指落下时忽略，不中断当前拖拽 |
| pointerType | `pen` 优先于 `touch`；书写场景下 `pen` 存在时丢弃同时发生的 `touch` |
| 捕获 | 拖拽开始后调用 `setPointerCapture`，保证手指滑出元素范围仍能跟随 |
| 取消 | `pointercancel`（系统手势抢占、来电等）一律视为**放弃**，元素回到拖拽前状态，不产生判定 |

### 11.3 阈值与参数

| 参数 | 值 | 说明 |
|---|---|---|
| 长按起拖延时 | **120 ms** | 拖词成句、拼字用长按起拖，防止与列表滚动冲突 |
| 直接起拖 | 0 ms | 闪卡滑动、相机对焦框不需要长按，落手即拖 |
| 移动判定阈值 | **12 px** | 位移小于此值视为「点击」而非「拖拽」 |
| 闪卡判定阈值 | **90 px** | 沿用现状；三向（左 / 右 / 上）同阈值 |
| 吸附距离 | **32 px** | 拖词 / 拼字的部件距槽位中心小于此值时吸附 |
| 回弹时长 | **180 ms** | 未达阈值或错放时回到原位的动画时长 |
| 惯性 | 闪卡判定成功后按松手速度飞出，最长 250 ms；拖词与对焦框**无惯性**（需要精确落点） |
| 拖拽把手最小尺寸 | **96×96**（设计稿） | 相机对焦框的四角把手 |
| 可拖元素最小尺寸 | **88×88**（设计稿） | 拖词 token、拼字部件 |

### 11.4 与滚动的冲突消解

| 场景 | 规则 |
|---|---|
| 可滚动容器内的可拖元素 | 落手后先判方向：首次位移的主轴为**容器滚动轴**时交给滚动；主轴为**垂直于滚动轴**时接管为拖拽 |
| 长按起拖 | 长按 120 ms 达成后，立即 `preventDefault` 并接管，滚动不再响应本次手势 |
| 闪卡 | 卡片区域内禁用页面滚动（`touch-action: none`），页面本身在会话中不滚动 |
| 相机对焦框 | 预览区整体 `touch-action: none` |
| 书写 canvas | `touch-action: none`，防止书写时页面被拖动 |

### 11.5 误触撤销与反馈

| 项 | 规则 |
|---|---|
| 滑动取消 | 长按录音（2.7）与拖拽起始后，把元素拖回起点区域并松手视为取消，不产生判定 |
| 闪卡误判 | 会话中提供 "Undo last card"，可撤销最近一次 know/unknown/uncertain 判定并把卡片放回 |
| 拖词错放 | 部件回弹到候选区 + 轻微震动，不扣分、不判负 |
| 触觉反馈 | 起拖、吸附成功、判定成功三个时机各给一次轻震（安卓 `HapticFeedback`）；失败只在错放时震一次 |
| 视觉反馈 | 起拖时元素抬起（阴影 + 缩放 1.04）；吸附时槽位高亮；判定方向在闪卡上用方向遮罩透明度渐变表达（沿用现状 `useTransform` 口径） |
| 无障碍 | 每个拖拽交互必须有**非拖拽的等价操作**：拖词可「点词 → 点槽位」完成；闪卡可用三个按钮替代三向滑动；对焦框提供「重置取景框」按钮 |

## 十二、音频独占控制在本域的适用规则

| 历史条目朗读 | `/camera` History | TTS |
| 嘴型示范视频 | `/pinyin-chart`、发音深度剖析 | **静音轨**，不参与音频互斥 |

### 12.3 独占规则

| 规则 | 说明 |
|---|---|
| 单路 | 任意时刻**全应用只允许一路音频在响**（嘴型视频因静音不计） |
| 代次令牌 | 全局单调递增的 `playbackToken`；每次发起播放前 `token = ++global`；异步回调（`onstart`、`onend`、`play()` 的 Promise）执行前必须校验 `token === global`，不等则直接丢弃并停音 |
| 抢占 | 新播放请求先 `stopAllAudio()`（取消 `speechSynthesis`、暂停并释放音频元素、通知原生 `tts.stop()`），再自增令牌并播放 |
| 串行 | `/ai-chat` 沿用 `AiConversationPipeline` 的 `workTail` 串行链，手动朗读也进同一条链，避免与管线播放争抢 |
| 离场 | 路由切换、屏状态切换（`ScreenState` 变化）、应用进入后台、页面 `visibilitychange` 转 hidden，**一律**执行 `stopAllAudio()` 并自增令牌 |
| 卸载 | 组件 `unmount` 时同上；`useEffect` 清理函数必须实现，不得遗漏 |
| 音色切换 | 切换 TTS 音色（2.9）立即停音并自增令牌 |
| 系统打断 | 安卓音频焦点丢失（来电、其他应用播放）时停音并自增令牌；焦点恢复**不自动续播** |
| 录音互斥 | 录音期间禁止任何播放；播放期间按下录音键先停播放再录 |

### 12.4 GWT 验收标准 · 音频独占
