## 一、概述与本篇范围

### 1.1 本篇要解决什么

教材域是 C-LingoAIOS 的**主线**。开机向导结束后，用户落到 `/Home`；除非他主动去考 HSK，否则此后所有学习行为都发生在本篇覆盖的 23 条路由里。

`00-总纲.md` 第九节把日常学习主流程描述为一条线：

```text
/Home → 选书 → 单元 → 课程（视频 → 学习 → 练习）→ 报告 → 回 Hub → 完成度达阈值 → 解锁 bonus
```

**这条线在 3.0 之前是断的。** 现状基线实测出 7 处断点（本篇编号 C1–C7），它们的共同特征不是「样式不好看」，而是**用户以为自己在做的事和系统实际做的事不一致**：

- 点着「HSK Chinese」的卡，进的是快乐中文 Hub（C1）
- 选了 Level 3 / Unit 7，开始学的还是 lesson 1（C2）
- 下载完一本书，刷新浏览器又变成没下载（C3）
- 学完两课，刷新一下进度归零（C4）
- 在书架上选了 HSK2，打开阅读器读到的是快乐中文第 1 课（C5）

本篇的产出目标：**把这条主线补成一条真的能走通、且走完有痕迹的线**，并为每一段给出可直接转测试用例的 GWT。

### 1.4 本篇通用设计约束

以下约束对本篇**全部 23 条路由**生效，各章不再重复，只在有额外要求时补充。

| # | 约束 | 判定标准 |
|---:|---|---|
| G1 | **游戏化，不儿童化** | 不用 Q 版卡通形象、不用夸张音效、不用彩带撒花类庆祝动画。进度与解锁用克制的徽章、进度条、XP 数值表达。目标审美是 12 岁以上、主力 13–19 岁 |
| G2 | **食指可点** | 任何可点元素的**触控热区**不小于 `figmaPx(88)`（Figma 1920 画布下 88×88，约合 11 mm 物理尺寸）。视觉尺寸可以更小，但热区必须补足。相邻可点元素**热区间距** ≥ `figmaPx(16)`。`[待确认]` 88 与 16 两个数值需业务方核定 |
| G3 | **首页一屏占满不滚动** | `/Home` 与 `/AI` 在 4 种目标分辨率（1024×768 / 960×540 / 1920×1125 / 2000×1200）下，主内容区 `scrollHeight <= clientHeight`，不出现纵向滚动条 |
| G4 | **英文为第一语言** | 全部界面文案默认英文，走 i18n 键；**中文只出现在教学内容本身**（课文、生词、例句）。不得硬编码中文 UI 文案。现状基线里 `敬请期待...`（`FunChineseHubPage.tsx:818`）是违例，必须改为 i18n 键 |
| G5 | **音频独占** | 任一时刻全局只有一个音频在响。切课、切句、切模式、离开页面、进入后台都必须停当前音频，并**递增播放代次令牌**，使旧 `play()` 的异步回调回来后直接作废、不得重新启动播放。复用 `src/hsk/exclusiveAudioPlayer.ts` 的同一机制 |
| G6 | **田字格必须正方形** | 凡渲染田字格处，格子容器 `aspect-ratio: 1 / 1`，宽高相等。**禁止用 `flex: 1` 把格子拉成竖长或横长矩形**。本篇第七章写字链跳转到域 D 的 `/character-writing/practice/:character`，该约束在两侧都生效 |
| G7 | **锁定即真锁定** | 「锁定」的定义沿用 `07-附录.md`：不可点击、**不请求数据**、**不能通过 URL 绕过**。只做 UI 灰置而路由可直达的，不算锁定（见 C7） |
| G8 | **无裸空页** | 任何路由被打开时，必须落在「内容 / 加载中 / 空态 / 错误态 / 锁定态」五种之一。不允许出现只有标题没有内容的白屏 |
| G9 | **离线优先** | 教材内容一旦下载到本地，**断网后必须可完整学习**（阅读、点读音频、练习、进度记录）。仅联网才能用的能力（AI 对话、云端同步）必须在断网时显式降级并提示 |

## 二、`/Home` 教材 Hub

### 2.1 页面定位

`/Home` 是开机向导完成后的**默认落地页**，也是底栏 Home Tab 的目的地。它回答用户三个问题：

1. **我现在在读哪本书？**（当前教材卡：封面、体系徽章、进度页码）
2. **我该从哪继续？**（Start 按钮 + 当前单元）
3. **我想换本书 / 用配套工具怎么办？**（Choose a Book + 伴学卡）

它**不是**书架，也**不是**课程目录。信息密度必须克制：一屏之内、不滚动（G3）。

### 2.3 需求 B2-1 · 入口命名与目的地必须一致（解 C1）

#### 2.3.1 问题陈述

默认安装状态下（用户从未选过书），`activeBook` 是 `hsk1`，`isHappyChineseBook` 返回 `false`，于是 `/Home` 底部渲染那张橙色大卡，**标题写「HSK Chinese」，点击后 `navigate('/library/hub/fun-chinese')`**。

也就是说：**快乐中文不仅在一期「可达」，而且是新设备上的默认入口，只是挂了一个 HSK 的名字。** 这比「不该展示却展示了」更糟——它是一次明确的导航欺骗：用户按标题预期进入 HSK 相关内容，实际落在另一个教材体系的 Hub 里。

`00-总纲.md` 第四节已决定按代码现状把快乐中文纳入 3.0 正式范围。因此本篇不讨论「要不要有快乐中文」，只解决**命名与信息架构的欺骗性**。

#### 2.3.2 需求：伴学卡按教材体系派生，不写死

`/Home` 底部的伴学卡区**不得**出现与 `activeBook` 所属体系无关的入口。卡片配置由 `activeBook.seriesId` 查表派生：

| `seriesId` | 卡位 1 | 卡位 2 | 说明 |
|---|---|---|---|
| `hsk` | **HSK Practice** → `/hsk-test` | *(空)* | 单卡占满宽度。目的地是 HSK 域入口，与标题一致 |
| `happy-chinese` | **Fun Chinese** → `/library/hub/fun-chinese` | **Culture** → `/library/hub/culture` | 双卡等宽 |
| `culture` | **Culture** → `/library/hub/culture` | *(空)* | 单卡占满宽度 |
| `practice` | **Practice Hub** → `/favorites` | *(空)* | `[待确认]` 练习册体系的配套入口目的地未定，暂指向收藏；业务方需明确 |

**硬性规则**：

- **R1 · 文案—目的地一致性**：卡片主标题必须与目的地页面的主标题（H1）文本一致或为其明确前缀。构建期（CI）加一条校验：伴学卡配置表中每条记录的 `label` 必须出现在目的地页面的 `pageTitle` 常量中，不一致则构建失败。
- **R2 · 快乐中文必须显式命名**：进入快乐中文 Hub 的任何入口，可见文案必须包含 `Fun Chinese`（i18n 键 `library.series.happyChinese.name`）。**禁止**用 `HSK Chinese`、`Games & Activities`、`Chinese Textbooks` 等不含体系名的文案作为其唯一标识。
- **R3 · 体系归属显式化**：`activeBook` 数据结构新增 `seriesId` 字段（见 2.4），**废弃**用 `id.startsWith('hc-')` 或 `badge[0] === 'Happy Chinese'` 做体系推断的写法。字符串前缀推断是 C1 的根因之一——它把「体系」这个业务概念编码进了 id 的书写约定里，任何一本命名不符约定的新书都会掉进错误分支。
- **R4 · 快乐中文的独立入口**：用户在读 HSK 教材时，若想进快乐中文，路径是 `/Home → Choose a Book → 选一本 Happy Chinese 教材 → 伴学卡出现 Fun Chinese`。**不在 HSK 体系的 `/Home` 上提供快乐中文快捷入口**。`[待确认]` 业务方若希望保留一个常驻的跨体系快乐中文入口，应放在书架页的体系分类 Tab，而不是 `/Home` 伴学卡位。

| 字段 | 类型 | 必填 | 校验 | 默认 / 缺失行为 |
|---|---|---|---|---|
| `id` | `string` | 是 | 非空，`^[a-z0-9-]{1,64}$` | 缺失 → 整体回落默认教材 |
| `title` | `string` | 是 | 非空，长度 ≤ 120 | 缺失 → 整体回落默认教材 |

### 2.6 需求 B2-4 · Start 按钮

| 场景 | 按钮文案 | 行为 |
|---|---|---|
| 当前单元 `available`，且 `currentPage === 0` | `Start` | `navigate('/library/read/' + activeBook.id, { state: { from: '/Home', unitId } })` |
| 当前单元 `in-progress` 或 `currentPage > 0` | `Continue` | 同上，并由阅读器定位到 `currentPage` |
| 当前单元 `completed` | `Review` | 同上 |
| 当前单元 `locked` | `Locked` | **不可点**：不带 `onClick`、`aria-disabled="true"`、不发起任何数据请求。点击区域给 120 ms 的轻微横向抖动反馈（`translateX(±4px)`），并在下方显示解锁条件文案 `Finish Unit N to unlock` |
| 内容包未下载 | `Download` | 触发内容包下载流程（见第四章 4.6），下载中按钮变进度态，完成后自动变 `Start` |

### 2.7 需求 B2-5 · 状态态补全（loading / error / 空 / 离线）

现状 `/Home` 三种状态全缺（G8 违例）。3.0 要求：

| 状态 | 触发条件 | 表现 |
|---|---|---|
| **Loading** | 内容包元数据、封面、单元列表任一未就绪 | 当前教材卡、Hero 文案区、伴学卡区各自显示骨架屏；顶栏与底栏正常渲染。骨架屏最短展示 300 ms（避免闪烁），最长 8 秒后转 Error |
| **Error** | 元数据读取失败、`localStorage` 解析抛错、内容包校验失败 | 主区显示错误卡：图标 + `Couldn't load your book.` + 主按钮 `Retry` + 次按钮 `Choose a Book`。**不白屏、不崩溃** |
| **封面加载失败** | `coverUrl` 图片 `onError` | 显示占位封面：`#F4F4F4` 底 + 书名首字母 + 体系徽章。**不显示破图图标** |
| **空态** | `activeBook` 指向的书已被用户从书架删除 | 主区显示 `Your last book is no longer on this device.` + 主按钮 `Choose a Book`；同时清除 `clingo.library.activeBook.v1` 并回落默认教材 |
| **离线** | `navigator.onLine === false` 或内容请求超时 | 见 2.8 |

### 2.8 需求 B2-6 · OFFLINE 徽章改为真实网络状态指示

#### 2.8.1 问题

现状顶栏的 OFFLINE 胶囊是**静态装饰**，联网时也显示 OFFLINE。这是比没有指示更坏的情况：它训练用户忽略这个位置，等到真正离线时指示就失效了。

#### 2.8.2 需求

顶栏该位置改为**网络与内容可用性指示器**，三态：

| 态 | 触发 | 视觉 | 文案 |
|---|---|---|---|
| `online` | `navigator.onLine === true` 且最近一次后端探测成功 | 圆点 `#00B4A0` + 边框 `#00B4A0` + 底 `rgba(0,180,160,0.1)` | `ONLINE` |
| `offline-ready` | 网络不可用，**但当前教材内容包已完整下载** | 圆点 `#FDB24F` + 边框 `#FDB24F` + 底 `rgba(253,178,79,0.1)` | `OFFLINE READY` |
| `offline-limited` | 网络不可用，**且当前教材内容包缺失或不完整** | 圆点 `#E5484D` + 边框 `#E5484D` + 底 `rgba(229,72,77,0.1)` | `OFFLINE` |

- 指示器**可点**，点击弹出气泡说明当前可用与不可用的能力（例：AI 对话不可用、教材与练习可用）。
- 状态变化监听 `online` / `offline` 事件，并每 `[待确认] 60` 秒做一次轻量探测（`HEAD` 请求，超时 3 秒）。探测频率需与 `06-非功能需求.md` 的功耗要求对齐。
- 三态颜色对比度需满足 WCAG AA（文字对背景 ≥ 4.5:1）；**不得只用颜色区分**，文案必须同时变化。

### 2.9 需求 B2-7 · 一屏不滚动的版式约束

`/Home` 采用固定画布布局（Figma 1920×1200 出数经 `figmaPx` 缩放），需满足：

- 顶栏高度固定 `figmaPx(160)`；底栏预留 `getBottomNavReserve()`；中间 `HubContainBoard` 区域 `1800 × 774` 等比缩放后必须完整落在剩余高度内。
- 按**宽**缩放后 1920×1200 稿的总高会超过 2000×1200 与 1920×1125 的设备高度（见根 `AGENTS.md`「UI 适配记录」）。因此：固定块（顶栏、底栏）用 `figmaPx`；**中间互动区用 flex 吃满剩余高度**，不得把稿上的绝对高度全部相加。
- 验收：4 种分辨率下 `document.scrollingElement.scrollHeight <= clientHeight`，且当前教材卡、Start 按钮、Choose a Book、伴学卡全部**完整可见**（不被裁切、不需滚动）。

### 3.3 需求 B3-1 · 消除假控件（解 C2）

#### 3.3.1 问题陈述

Level 与 Unit 是两个**完整实现了交互反馈、但不产生任何结果**的下拉框。用户选择 `Level 3 / Unit 7: Opinions & Advice`，下拉的 label 正确更新，然后点 Start Session——进入的是 lesson 1。

这类缺陷比缺失功能更有害：用户无法通过界面反馈察觉自己被忽略了，只会认为课程内容有问题。

#### 3.3.2 决策：接真实课程数据，不移除

任务给的两个选项是「接真实课程数据」或「移除控件」。**3.0 选择接真实数据**，理由：

1. Studio 的产品定位就是「分级课程体系」，Level 与 Unit 是它区别于 `/Home`（按书组织）的**唯一结构特征**。移除后 `/AI` 退化为一个只有 Start Session 按钮的落地页，与 `00-总纲.md` 把它列为 P0 双入口之一的定位矛盾。
2. 课程数据已部分存在（`src/data/lessonCatalog.ts` 的 `getLessonById`），缺的是「Level/Unit → lessonId」的映射与真实目录，不是从零建设。

**但需要分级落地**：见 3.3.4 的降级方案。

#### 3.3.3 需求：Studio 课程目录模型

新增课程目录数据源（来源优先级：后端接口 > 本地内容包 > 内置兜底），结构：

### 3.7 GWT 验收标准 · `/AI`

**GWT-B3-01｜Level 选择影响 Unit 列表**
- **Given** 用户在 `/AI`，当前为 Level 1，Unit 下拉列出 Level 1 的单元
- **When** 用户把 Level 切到 Level 2
- **Then** Unit 下拉的选项集合变为 Level 2 的单元；当前选中 Unit 自动重置为 Level 2 的第一个 `available` 单元；Hero 区的课题、mastery、生词数、句型数同步更新为该单元的数据

**GWT-B3-02｜Unit 选择影响 Start Session 的目标（C2 回归）**
- **Given** 用户在 `/AI` 选择 `Level 1 / Unit 1`，记录点击 Start Session 后的落地 URL 为 U1
- **When** 用户返回 `/AI`，改选 `Level 2 / Unit 3`，再点 Start Session，记录落地 URL 为 U2
- **Then** U1 ≠ U2；两者均形如 `/lesson/:id`；U2 对应的 lesson 属于 `Level 2 / Unit 3`；**不得两次都落在 `/lesson/1`**

**GWT-B3-03｜Start Session 携带来源上下文**
- **Given** 用户在 `/AI` 选定任一可用单元
- **When** 点击 Start Session
- **Then** 导航 `state` 中包含 `from: '/AI'`、`trackId`、`levelId`、`unitId` 四个字段；在 `/lesson/:id` 内点返回，回到 `/AI` 且**选择状态保持为刚才选的 Level/Unit**

**GWT-B3-04｜锁定 Level 不可选且不请求数据**
- **Given** 用户尚未完成 Level 1（完成度低于解锁阈值），DevTools Network 面板已清空
- **When** 用户展开 Level 下拉并点击 Level 3
- **Then** 下拉保持当前选择不变；Level 3 项显示锁图标与解锁条件文案；Network 面板无任何课程数据请求；下拉关闭后 Hero 区内容未改变

**GWT-B3-05｜Mastery 不显示伪造数值**
- **Given** 一台全新设备，用户从未在 Studio 完成过任何课程
- **When** 用户落地 `/AI`
- **Then** Hero 区**不显示 `65%` 或任何非零 mastery 百分比**，而显示 `Not started`；生词数与句型数取自真实单元数据（若无数据则不显示该指标，不显示 `3`）

**GWT-B3-06｜空单元的处理**
- **Given** 课程目录中存在一个 `lessonIds` 为空数组的单元
- **When** 用户选中该单元
- **Then** Start Session 按钮不可点（`aria-disabled="true"`）；Hero 区显示 `No lessons in this unit yet.`；点击按钮不发生导航、无未捕获异常

**GWT-B3-07｜课程目录加载失败的降级**
- **Given** 课程目录接口返回 500
- **When** 用户落地 `/AI`
- **Then** 页面不白屏；Hero 区显示错误卡与 `Retry` 按钮；Level/Unit 下拉呈禁用态；点 `Retry` 重新发起请求；AI Tutor 与 Pinyin Chart 两张卡**仍可点击并正常导航**（它们不依赖课程目录）

**GWT-B3-08｜`/AI` 一屏不滚动**
- **Given** 应用分别以 4 种 `VITE_SCREEN_SIZE` 启动
- **When** 用户落地 `/AI` 并依次展开课轨、Level、Unit 三个下拉
- **Then** 页面始终无纵向滚动条；下拉菜单若超高则菜单内部滚动；Hero 区与右侧两张卡完整可见

### 4.5 需求 B4-3 · 长按手势规范（安卓平板）

现状只有本页用长按，且阈值与仓库工具函数不一致。3.0 把长按定为**全站统一手势**，规范如下：

| 项 | 规范值 | 理由 |
|---|---|---|
| 触发阈值 | **500 ms** | 与安卓平台 `ViewConfiguration.getLongPressTimeout()` 默认值一致，符合安卓平板用户既有肌肉记忆。**统一 `src/utils/useLongPress.ts` 的默认值为 500 ms**，删除页面内自写的计时器 |
| 移动容差 | 指尖在按下后移动超过 **10 dp** 即取消长按 | 防止滚动列表时误触发。现状 `useLongPress` 只在 `pointerleave` / `pointercancel` 取消，**未做位移判定，需补** |
| 触觉反馈 | 达到阈值瞬间 `navigator.vibrate(50)` | 50 ms 短震，对应安卓 `HapticFeedbackConstants.LONG_PRESS`。设备不支持 `vibrate` 时静默跳过，不报错 |
| 视觉反馈 | 按下后 500 ms 内，被按元素以 `scale(0.97)` + 逐渐加深的遮罩表达「蓄力中」，达到阈值时遮罩消失并弹出 overlay | 让用户知道「还需再按一会儿」，而不是以为没反应 |
| 与点击互斥 | 长按触发后，后续的 `click` / `pointerup` 必须被吞掉，**不得同时触发打开书籍** | 现状 `useLongPress` 已有 `consumeLongPress()`，页面自写的那套没有，需补 |
| 适用范围 | Grid 视图的书卡（非编辑模式）。List 视图与编辑模式**不启用长按** | 编辑模式已有显式复选框，长按会语义重复 |
| 可发现性 | 长按不得是唯一路径。书卡右上角必须同时提供一个**显式的 `⋮` 更多按钮**（热区 `figmaPx(88)`），点击打开同一个管理 overlay | 手势是加速器，不是唯一入口。这是 G2 与无障碍的共同要求 |
| 无障碍 | 屏幕阅读器下长按不可用；`⋮` 按钮 `aria-label="More options for ${title}"` | |

**单书管理 overlay 内容**：书名 + 封面缩略 + 内容包体积 + 三个动作：`Open`（已下载时）/ `Download`（未下载时）、`Delete download`（已下载时）、`Cancel`。

### 4.6 需求 B4-4 · 内容包下载模型（解 C3）

#### 4.6.1 问题陈述

现状的下载是一个 `setInterval` 动画：1.3 秒跑满，不传输任何字节，状态只在内存，刷新后全部回退。用户在这里做的一切（下载、删除、批量清理）**都不产生任何真实效果**，包括「Delete All」——它不释放一个字节的存储。

这在演示里看不出问题，在真机上是彻底不可用的：教材内容包是本产品的核心资产，离线学习（G9）完全依赖它。

#### 4.6.2 下载状态机

```text
                    ┌──────────────── 用户点 Download ────────────────┐
                    ▼                                                 │
 not-downloaded ──► queued ──► downloading ──► verifying ──► downloaded
                      │            │  ▲            │              │
                      │            │  │            │ 校验失败      │ 远端版本更高
                      │       用户暂停 │恢复         ▼              ▼
                      │            ▼  │         failed      update-available
                      │          paused                           │
                      │            │                              │ 用户点 Update
                      └────────────┴──── 用户取消 ──► not-downloaded
                                                          ▲
                                   用户点 Delete download ─┘（仅从 downloaded）
```

#### 4.6.3 各状态的 UI 规格

| 状态 | CTA 文案 | 辅助显示 | 可用动作 |
|---|---|---|---|
| `not-downloaded` | `Download` | 内容包体积（如 `42 MB`） | 点击开始下载 |
| `queued` | `Queued` | 队列位次（如 `2 of 3`） | 取消 |
| `downloading` | 环形进度 + 百分比 | `12.4 / 42 MB · 1.2 MB/s` | 暂停、取消 |
| `paused` | `Resume` | `12.4 / 42 MB · Paused` | 恢复、取消 |
| `verifying` | `Verifying…` | 不确定进度条 | 无（不可取消） |
| `downloaded` | `Open` | `42 MB on device` | 打开、删除 |
| `failed` | `Retry` | 失败原因短句（见 4.6.6） | 重试、取消 |
| `update-available` | `Update` | `New version v1.3 · 8 MB` | 更新、直接打开旧版 |
| `accessState === 'locked'` | `Locked` | 锁定原因（如 `HSK 3 coming soon`） | **无**。不可点、不请求数据、不可 URL 绕过（G7） |

#### 4.6.4 功能要求

| # | 要求 |
|---:|---|
| D1 | **真实传输**。内容包为单一归档文件，分块请求（推荐分块 `[待确认] 4 MB`），支持 HTTP Range |
| D2 | **断点续传**。中断（关页、断网、杀进程）后再次进入书架，`downloadState` 恢复为 `paused`，`downloadedBytes` 保留；点 `Resume` 从断点继续，不重头下载 |
| D3 | **状态持久化**。下载状态与游标写入本地持久层（`localStorage` 存元数据 + 文件系统 / IndexedDB 存分块）。**刷新页面、重启应用后状态不变** |
| D4 | **完整性校验**。下载完成后计算 SHA-256 与 `packageChecksum` 比对；不一致则置 `failed`，错误码 `CHECKSUM_MISMATCH`，并删除已下载的残片 |
| D5 | **并发上限**。同时进行的下载不超过 `[待确认] 2` 个，其余进入 `queued` |
| D6 | **存储配额**。开始下载前检查可用空间：`可用空间 < packageSizeBytes × [待确认] 1.2` 时拒绝开始，弹出对话框 `Not enough space` + 需要 / 可用体积 + 按钮 `Manage storage` → `/system/content-cache` |
| D7 | **与内容缓存页打通**。`/system/content-cache`（域 E）必须能列出全部已下载内容包、各自体积、总占用，并提供删除。书架的删除与该页的删除**操作同一份数据**，任一侧变更后另一侧立即反映 |
| D8 | **真实删除**。`Delete download` 必须删除本地文件并释放空间，同时把 `downloadState` 置 `not-downloaded`、`downloadedBytes` 置 `0`。删除前弹确认对话框，文案含将释放的体积 |
| D9 | **删除不丢进度**。删除内容包**不删除学习进度**（`currentPage`、单元完成记录）。重新下载后进度仍在。确认对话框需明示这一点：`Your progress will be kept.` |
| D10 | **当前教材保护**。若被删除的是 `activeBook` 指向的书，删除后 `/Home` 按 2.7 的空态处理 |
| D11 | **后台继续**。下载在用户离开书架页后继续；底栏 Library 图标上显示小进度环；全部完成后出现一次性 Snackbar |
| D12 | **计量网络**。`[待确认]` 是否在移动数据下默认暂停下载并提示。安卓平板可能插 SIM，建议提供开关，需业务方确认 |

#### 4.6.5 内容包构成

| 子资源 | 必需 | 说明 |
|---|---|---|
| `manifest.json` | 是 | 版本、校验和、单元与课目录、各子资源清单 |
| 正文与版式数据 | 是 | 课文、生词、句型、拼音标注 |
| 页面图片 | 是 | 教材跨页图 |
| **原声音频** | 是 | 逐句音频，见第六章 6.5。**这是内容包体积的主要来源** |
| 练习数据 | 是 | 匹配 / 填空 / 判断 / 角色扮演 / 写字 各子题数据 |
| 笔画数据 | 否 | 写字练习用；缺失时写字入口锁定 |
| 文化素材 | 否 | 见第八章 |

`[待确认]` 单本内容包的预估体积区间（影响 D6 的配额策略、首包下载时长、设备出厂预装策略）。粗估 HSK1 一册含逐句音频约 `[待确认] 30–80 MB`，需内容团队按真实素材核定。

### 4.9 GWT 验收标准 · 书架

**GWT-B4-01｜下载状态跨刷新保持（C3 回归）**
- **Given** 用户在 `/library/select-books` 对一本 40 MB 的教材点击 `Download`，等待进度到约 50% 后刷新浏览器
- **When** 页面重新加载并回到书架
- **Then** 该书的 `downloadState` 为 `paused`，进度显示约 50%（已下载字节数与刷新前一致，误差不超过一个分块）；CTA 文案为 `Resume`；**不得回到 `Download` 初始态**

**GWT-B4-02｜断点续传不重头下载**
- **Given** 一本教材处于 `paused` 状态，已下载 20 MB / 共 40 MB
- **When** 用户点击 `Resume`，并在 DevTools Network 面板观察请求
- **Then** 后续请求携带 `Range` 头且起始偏移约为 20 MB；总下载流量增量约为 20 MB 而非 40 MB；完成后状态经 `verifying` 转 `downloaded`

**GWT-B4-03｜校验失败不产生可用的坏包**
- **Given** 服务端返回的内容包字节被人为篡改一位，`packageChecksum` 不变
- **When** 下载完成并进入 `verifying`
- **Then** 状态转为 `failed`，错误文案为 `Download was corrupted. Tap to download again.`；本地残片被清除（`downloadedBytes` 归零）；该书**不可被打开**，点击书卡不进入阅读器

**GWT-B4-04｜删除释放真实空间且保留进度**
- **Given** 一本已下载教材，用户已读到第 37 页，`/system/content-cache` 显示总占用为 X
- **When** 用户在书架长按该书 → `Delete download` → 确认
- **Then** 确认对话框中出现 `Your progress will be kept.` 与将释放的体积；删除后 `/system/content-cache` 的总占用减少约等于该包体积；重新下载该书后打开，阅读器仍定位到第 37 页

**GWT-B4-05｜存储不足时拒绝开始下载**
- **Given** 设备可用空间小于目标内容包体积的 1.2 倍
- **When** 用户点击 `Download`
- **Then** 不开始任何传输；弹出 `Not enough space` 对话框，显示所需与可用体积；提供 `Manage storage` 按钮，点击后进入 `/system/content-cache`

**GWT-B4-06｜长按阈值与触觉反馈**
- **Given** 用户在 Grid 视图、非编辑模式下
- **When** 用户按住一张书卡并保持 500 ms 不松手、指尖位移不超过 10 dp
- **Then** 在 500 ms 达到时触发一次 50 ms 震动，弹出单书管理 overlay；松手后**不额外触发打开书籍**；overlay 内含 `Open` / `Delete download` / `Cancel`

**GWT-B4-07｜长按在位移超限时取消**
- **Given** 用户在 Grid 视图按住一张书卡
- **When** 用户在 500 ms 内把指尖移动超过 10 dp（如开始滚动列表）
- **Then** 不触发长按、不震动、不弹 overlay；列表正常滚动；松手后也不触发打开书籍

**GWT-B4-08｜长按不是唯一入口**
- **Given** 用户在 Grid 视图
- **When** 用户点击书卡右上角的 `⋮` 按钮
- **Then** 弹出与长按完全相同的单书管理 overlay；该按钮触控热区不小于 `figmaPx(88)` 见方；`aria-label` 包含书名

**GWT-B4-09｜List 视图与编辑模式不响应长按**
- **Given** 用户切到 List 视图，或在 Grid 视图下进入 Manage 编辑模式
- **When** 用户按住一本书超过 1 秒
- **Then** 不震动、不弹 overlay；List 视图下松手按普通点击处理（打开书籍），编辑模式下按勾选处理

**GWT-B4-10｜搜索与分类求交集**
- **Given** 书库中 Happy Chinese 分类下有 2 本书，其中 1 本标题含 `Volume 2`
- **When** 用户选中 `Happy Chinese` Tab 并在搜索框输入 `volume 2`
- **Then** 结果只显示那 1 本；清空搜索后恢复为 2 本；输入一个无匹配关键词时显示 `No books found` 空态与 `Clear search` 按钮

**GWT-B4-11｜离线时已下载书籍仍完整可见可用**
- **Given** 用户已下载 3 本教材，随后断开网络
- **When** 用户进入 `/library/select-books`
- **Then** 页面不白屏、不显示空列表；3 本已下载教材正常列出且可打开；顶部出现非阻断提示条 `Showing downloaded books only.`；未下载的书可以不显示，但不得显示为可下载并在点击后无反馈

**GWT-B4-12｜批量删除只作用于当前筛选结果**
- **Given** 书库共 8 本已下载教材，用户筛选到 `HSK` 分类（3 本）
- **When** 用户进入 Manage，点击 `Select all`，再点 `Delete` 并确认
- **Then** 顶栏显示 `3 selected`（不是 8）；删除后仅这 3 本回到 `not-downloaded`，其余 5 本保持已下载；Snackbar 显示删除数量与释放体积

**GWT-B4-13｜打开书籍写入当前教材指针并携带来源**
- **Given** 用户当前 `activeBook` 为 `hsk1`
- **When** 用户在书架点开一本 `seriesId` 为 `happy-chinese` 的教材
- **Then** `clingo.library.activeBook.v1` 被更新为该书（含 `seriesId: 'happy-chinese'` 与新的 `lastOpenedAt`）；导航到 `/library/read/${bookId}` 且 `state.from` 为 `/library/select-books`；在阅读器内点返回回到书架而非 `/Home`

**GWT-B4-14｜锁定教材不可点且不请求数据**
- **Given** 书库中存在一本 `accessState` 为 `locked` 的 HSK3 教材，DevTools Network 面板已清空
- **When** 用户点击该书卡与其 CTA 各一次
- **Then** 不发生导航；无任何内容包或书目详情请求；CTA 显示 `Locked` 与锁定原因；直接在地址栏访问 `/library/read/<该 bookId>` 时，阅读器显示锁定态而非内容

## 五、学习主线：单元选择 → 课程 → 练习 → 报告

### 5.1 主线定位

`/lesson/:id` 是 3.0 学习主线的**唯一容器**。用户产品规则要求的主线是：

```text
进入课程 → 观看视频（可跳过）→ 练习 → 学习报告 → 回 Hub 显示进度 → 完成度达阈值解锁 bonus
```

本章把这条线落成可排期的 stage 机、进度模型与解锁规则。

### 5.2 现状基线

> 对 `local-agent-app/src/pages/LessonPage.tsx`（136 行）与 `components/Lesson/UnitSelectionStage.tsx` 的实测记录。

| 项 | 现状 |
|---|---|
| stage 机 | `VIDEO` → `UNIT_SELECTION` → `UNIT_LEARNING` / `EXERCISE` → `CULTURE_VIDEO` / `HSK_UPSELL`（+ 三个 premium 子 stage） |
| 首次进课 | `useEffect` 读 `localStorage` 的 `lesson_${id}_seen_video`；无该键 → 进 `VIDEO` 并**立即写入** `'true'`；有则直接进 `UNIT_SELECTION`（`LessonPage.tsx:33-42`） |
| 未知 id | `getLessonById(id)` 回落到 `CURRENT_LESSON` 兜底数据，**不报错、不提示** |
| 返回 | `UnitSelectionStage` 用 `resolveBackPath(location, { defaultPath: '/AI' })`，默认回 `/AI` |
| 课列表 | `UnitSelectionStage` 内部把 `firstUnit.questions` 按每 3 题切成最多 3 课（`lesson-1/2/3`），标题写死 `Lesson 1: Rice` / `Lesson 2: Dumplings` / `Lesson 3: Eat Baozi` |
| 课锁定 | Lesson 2 / 3 需前序完成（`disabled`） |
| Bonus 解锁 | `cultureUnlocked = completedLessons / totalLessons >= 2/3`（`UnitSelectionStage.tsx:136`），`totalLessons` 写死 `3`，即**需完成 2 课 ≈ 66.7%** |
| 单元进度条 | `unitProgressPercent = 10` **写死**（`UnitSelectionStage.tsx:137`） |
| 其他入口 | Study Report → `/study-report`；Mistakes → `/mistakes-review`；Bonus Enter → `/culture-content`；AI Tutor 大卡 → `/ai-chat` |
| **进度持久化** | `completedUnits` 是 `useState<string[]>([])`，**仅 session state**。`useEffect([lesson])` 还会把它重置为 `[]`。刷新页面即归零。**只有 `seen_video` 落盘** |

### 5.3 需求 B5-1 · 学习进度模型（解 C4）

#### 5.3.1 问题陈述

用户在一课里完成了 2 个小节，Bonus 解锁了，进度条动了——然后刷新页面，全部消失，Bonus 重新锁上。这条主线的**每一次学习都没有留下痕迹**，`00-总纲.md` 描述的「回 Hub 显示进度」在现状下不成立。

同时 `07-附录.md` E3 指出 `lesson_<id>_seen_video` 这类**按 id 分键**的写法会导致键数无界增长。3.0 的进度模型必须一次性解决「不持久化」和「持久化方式不可扩展」两个问题。

#### 5.3.2 进度数据结构

单一索引键：`clingo.study.progress.v1`（命名遵循 `07-附录.md` E2 的统一规范）。

```text
StudyProgress {
  version: 1
  updatedAt: string            // ISO 8601
  courses: {
    [courseId: string]: CourseProgress
  }
}

CourseProgress {
  courseId: string             // 对应 /lesson/:id 的 :id，或教材的 bookId
  seenIntroVideo: boolean      // 取代 lesson_<id>_seen_video
  units: {
    [unitId: string]: UnitProgress
  }
  completedUnitCount: number   // 派生缓存，用于快速渲染
  totalUnitCount: number
  lastStudiedAt: string
}

UnitProgress {
  unitId: string
  status: 'locked' | 'available' | 'in-progress' | 'completed'
  lessons: {
    [lessonKey: string]: LessonProgress
  }
  bonusUnlocked: boolean
}

LessonProgress {
  lessonKey: string
  status: 'locked' | 'available' | 'in-progress' | 'completed'
  learningDone: boolean        // UNIT_LEARNING 阶段完成
  exerciseDone: boolean        // EXERCISE 阶段完成
  exerciseScore: number | null // 0-100
  masteryPercent: number       // 0-100
  attempts: number
  firstCompletedAt: string | null
  lastAttemptAt: string | null
}
```

#### 5.3.3 字段校验与默认值

| 字段 | 校验 | 非法 / 缺失时 |
|---|---|---|
| `version` | 整数，当前为 `1` | 不等于 `1` → 走迁移；无法迁移 → 丢弃并重建空进度，**不崩溃** |
| `status` | 枚举内 | 非枚举值 → `'available'` |
| `exerciseScore` | `null` 或 `0 ≤ v ≤ 100` | 越界 → 钳制；非数字 → `null` |
| `masteryPercent` | `0 ≤ v ≤ 100` 整数 | 越界 → 钳制；非数字 → `0` |
| `attempts` | 整数 ≥ 0 | 非法 → `0` |
| 时间字段 | 可解析 ISO 8601 | 非法 → `null`，不显示相关时间信息 |
| 整体 JSON | 可解析 | 解析抛错 → 重建空进度并**保留一份损坏数据副本**到 `clingo.study.progress.corrupt.v1` 供排查，仅保留最近 1 份 |

#### 5.3.4 写入时机

| 事件 | 写入内容 |
|---|---|
| 首次进入课程并开始播放导入视频 | `seenIntroVideo = true`（**变更点**：现状在进入 VIDEO 时立即写，导致用户刚进页面就被标记为看过；3.0 改为**视频播放完成或用户显式跳过时**才写） |
| 进入某小节的 `UNIT_LEARNING` | 该 `lessonKey.status = 'in-progress'`，`lastAttemptAt` 更新 |
| 完成 `UNIT_LEARNING` | `learningDone = true` |
| 完成 `EXERCISE` | `exerciseDone = true`、写 `exerciseScore`、`attempts += 1`；`learningDone && exerciseDone` → `status = 'completed'`、首次时写 `firstCompletedAt` |
| 单元内全部小节 completed | `UnitProgress.status = 'completed'`，`CourseProgress.completedUnitCount` 重算 |
| 达到 bonus 阈值 | `bonusUnlocked = true`（**单向**，一旦解锁不再回落，见 5.4） |

**写入必须是原子的**：读 → 改 → 整体序列化 → 一次 `setItem`。捕获 `QuotaExceededError`，触发 `07-附录.md` E5 的配额处理路径（提示 + 引导清理），**不静默吞掉**。

#### 5.3.5 老键迁移

升级到 3.0 后首次启动，扫描全部 `lesson_<id>_seen_video` 键：写入 `courses[<id>].seenIntroVideo = true`，然后**删除原键**。迁移一次性执行，用 `clingo.study.progress.migratedFrom.v1 = 'lesson-seen-video'` 标记，避免重复扫描。

### 5.4 需求 B5-2 · Bonus 解锁阈值的定夺

#### 5.4.1 冲突

| 来源 | 阈值 |
|---|---|
| 产品规则（用户规则 `learning-flow-structure`）、`00-总纲.md` 第九节与 sprint S8 出口条件、`07-附录.md` 术语表 | **60%** |
| 代码实现 `UnitSelectionStage.tsx:136` | `completedLessons / 3 >= 2/3` ≈ **66.7%** |

在 `totalLessons = 3` 的当前结构下，两者的实际效果**恰好相同**（60% 需完成 1.8 课 → 向上取整 2 课；66.7% 需完成 2 课）。所以现状没暴露问题。**但一旦单元的课数变成 4 或 5，两者就分叉了**：5 课时 60% 要求完成 3 课，2/3 要求完成 4 课。

#### 5.4.2 决策

**3.0 统一采用 60%**，判定公式：

```text
bonusUnlocked = completedLessonCount >= ceil(totalLessonCount × 0.60)
```

| `totalLessonCount` | 阈值课数 |
|---:|---:|
| 1 | 1 |
| 2 | 2 |
| 3 | 2 |
| 4 | 3 |
| 5 | 3 |
| 6 | 4 |
| 8 | 5 |

**实现要求**：

- 阈值系数 `0.60` 必须是**唯一的常量定义**（如 `src/study/progressRules.ts` 的 `BONUS_UNLOCK_RATIO`），全站引用同一个符号。**禁止**在任何页面内写 `2/3`、`0.66` 或硬编码课数。
- `totalLessonCount` 取自课程目录的真实课数，**不得写死 `3`**。
- 解锁是**单向**的：已解锁的 bonus 不因内容包更新导致课数变多而重新锁上（否则用户会觉得功能被收回）。实现上以 `bonusUnlocked` 持久化标志为准，不每次重算。
- 单元进度条 `unitProgressPercent` 必须取真实值 `round(completedLessonCount / totalLessonCount × 100)`，**不得写死 `10`**。

> `[待确认]` 60% 系数需业务方最终签字。若业务方希望不同教材体系用不同阈值，需改为按 `seriesId` 配置，当前按全局单值设计。

### 5.5 需求 B5-3 · Stage 机与各阶段规格

#### 5.5.1 Stage 定义

| `HSK_UPSELL` | Hub 的深度学习入口 | 返回 → Hub；选 AI → `/ai-chat` | 否 |

#### 5.5.2 导入视频（VIDEO）

| 项 | 要求 |
|---|---|
| 可跳过 | 必须提供显式 `Skip` 按钮，**从第 0 秒即可点**。产品规则明确「可跳过」，不设强制观看时长 |

#### 5.5.3 课程 Hub（UNIT_SELECTION）

Hub 是主线的枢纽，元素与去向：

| 元素 | 状态规则 | 去向 |
|---|---|---|
| 单元目标卡 | 展示 `objectives` | — |
| 单元进度条 | 真实值（见 5.4.2） | — |

#### 5.5.4 未知课程 id 的处理

现状 `getLessonById(id)` 对任意未知 id 静默回落到兜底课程。这会让 `/lesson/99999` 看起来像一门真课。

**3.0 要求**：未知 id 渲染**课程未找到**页：图标 + `We couldn't find this lesson.` + 主按钮 `Back to Studio`（→ `/AI`）+ 次按钮 `Go to Home`（→ `/Home`）。不渲染兜底课程内容，不写任何进度。

#### 5.5.5 练习阶段（EXERCISE）

本章只定义与主线衔接的部分，题型细节属内容与域 D 范畴。

| 项 | 要求 |
|---|---|
| 颗粒度 | 练习按小节拆分，单次练习题量 `[待确认] 5–8` 题，目标单次时长 ≤ 5 分钟（产品规则「练习颗粒度化，拆分成小单元」） |
| 中途退出 | 弹确认：`Leave practice? Your answers in this round won't be saved.`；确认后回 Hub，**不写** `exerciseDone` |
| 完成 | 显示本轮结果（正确数 / 总题数 / 用时），主按钮 `Back to lesson hub`；同时写入进度（5.3.4） |
| 错题 | 每道错题写入错题记录，供 `/mistakes-review` 消费。存储收敛为单索引键（`07-附录.md` E3），**不再按题 id 分键** |
| 音频题 | 受 G5 约束：切题必须停当前音频并递增令牌 |
| 写字题 | 田字格严格 `aspect-ratio: 1 / 1`（G6） |

### 5.7 GWT 验收标准 · 学习主线

**GWT-B5-01｜完成进度跨刷新保持（C4 回归）**
- **Given** 用户进入 `/lesson/1`，完整完成 Lesson 1（学习 + 练习），Hub 上 Lesson 1 显示已完成、进度条非零
- **When** 用户刷新浏览器并重新进入 `/lesson/1`
- **Then** Lesson 1 仍显示已完成、显示上次得分；Lesson 2 处于 `available`；进度条数值与刷新前一致；**不得回到全部未完成的初始态**

**GWT-B5-02｜进度落在单一索引键**
- **Given** 用户在 3 门不同课程中各完成若干小节
- **When** 检查 `localStorage`
- **Then** 学习进度全部落在 `clingo.study.progress.v1` 一个键内；**不存在任何 `lesson_<id>_seen_video` 形式的键**；键内 `courses` 下有 3 个条目

**GWT-B5-03｜老键迁移**
- **Given** 升级前的设备 `localStorage` 中存在 `lesson_1_seen_video` 与 `lesson_7_seen_video` 两个键
- **When** 应用升级到 3.0 后首次启动
- **Then** `clingo.study.progress.v1` 中 `courses['1'].seenIntroVideo` 与 `courses['7'].seenIntroVideo` 均为 `true`；两个旧键已被删除；进入 `/lesson/1` 时**不再播放导入视频**

**GWT-B5-04｜导入视频可从第 0 秒跳过**
- **Given** 用户首次进入 `/lesson/2`，导入视频开始播放
- **When** 用户在视频播放 1 秒内点击 `Skip`
- **Then** 立即进入课程 Hub；`seenIntroVideo` 被写为 `true`；再次进入 `/lesson/2` 时直接落在 Hub

**GWT-B5-05｜中途退出不误标视频已看**
- **Given** 用户首次进入 `/lesson/3`，导入视频正在播放
- **When** 用户在视频播完前按系统返回键离开课程
- **Then** `courses['3'].seenIntroVideo` 仍为 `false`；再次进入 `/lesson/3` 时视频重新播放；离开瞬间视频音频立即停止，返回后**不出现残留音轨**

**GWT-B5-06｜Bonus 解锁按 60% 阈值（3 课单元）**
- **Given** 一个含 3 课的单元，用户已完成 1 课
- **When** 用户查看课程 Hub 的 Bonus Class 入口
- **Then** 入口为锁定态，提示 `Complete 2 lessons to unlock`；完成第 2 课后（2 ≥ ceil(3×0.6)=2）入口变为 `Enter`，点击进入 `/culture-content`

**GWT-B5-07｜Bonus 解锁按 60% 阈值（5 课单元）**
- **Given** 一个含 5 课的单元，用户已完成 2 课
- **When** 用户查看 Bonus 入口，随后完成第 3 课
- **Then** 完成 2 课时仍锁定（2 < ceil(5×0.6)=3）；完成第 3 课后解锁；**不得要求完成 4 课**（即不得沿用 2/3 判定）

**GWT-B5-08｜Bonus 解锁不可回落**
- **Given** 用户在含 3 课的单元中完成 2 课，Bonus 已解锁
- **When** 内容包更新，该单元课数增加到 6 课（新阈值 4 课）
- **Then** Bonus 入口**仍保持解锁**；进度条按新的 2/6 显示；不出现「功能被收回」

**GWT-B5-09｜单元进度条显示真实值**
- **Given** 一个含 4 课的单元，用户完成 1 课
- **When** 用户查看课程 Hub
- **Then** 进度条显示 `25%`；**不显示写死的 `10%`**；完成第 2 课后变为 `50%`

**GWT-B5-10｜Lesson 逐级解锁**
- **Given** 用户首次进入一个含 3 课的单元
- **When** 用户依次尝试点击 Lesson 1、Lesson 2、Lesson 3
- **Then** 只有 Lesson 1 可进入；Lesson 2、3 为锁定容器（无 `onClick`），点击不导航、不发起数据请求、给 120 ms 抖动反馈；完成 Lesson 1 后 Lesson 2 转为可点、Lesson 3 仍锁定

**GWT-B5-11｜未知课程 id 显示未找到页**
- **Given** 课程目录中不存在 id 为 `99999` 的课程
- **When** 用户直接访问 `/lesson/99999`
- **Then** 页面显示 `We couldn't find this lesson.` 与 `Back to Studio` / `Go to Home` 两个按钮；**不渲染任何兜底课程内容**；`clingo.study.progress.v1` 中不新增 `courses['99999']` 条目

**GWT-B5-12｜练习中途退出不记完成**
- **Given** 用户在某小节的练习阶段已答完 3 / 6 题
- **When** 用户点返回并在确认对话框中确认离开
- **Then** 对话框文案提示本轮答案不会保存；回到课程 Hub；该小节 `exerciseDone` 仍为 `false`、`status` 为 `in-progress`；`attempts` 未增加

**GWT-B5-13｜练习完成写入得分与错题**
- **Given** 用户完成一轮 6 题练习，答对 4 题
- **When** 练习结果页出现
- **Then** 显示 `4 / 6`；`clingo.study.progress.v1` 中该 `lessonKey` 的 `exerciseDone` 为 `true`、`exerciseScore` 约为 `67`、`attempts` 增加 1、`firstCompletedAt` 已写入；2 道错题出现在 `/mistakes-review` 中

**GWT-B5-14｜学习报告使用真实数据**
- **Given** 用户在某课程完成 2 个小节，得分分别为 80 和 60
- **When** 用户从课程 Hub 点 Study Report
- **Then** 报告中的完成小节数为 2、平均分约 70，与进度模型一致；报告页返回按钮回到该课程 Hub（不是首页）；从未学习的课程进入报告时显示空态而非假数据

**GWT-B5-15｜存储配额超限不崩溃**
- **Given** `localStorage` 已接近浏览器配额上限
- **When** 用户完成一轮练习触发进度写入并抛出 `QuotaExceededError`
- **Then** 应用不崩溃、不白屏；出现提示 `Storage is full. Clear learning records to continue.` 与跳转清理的入口；已完成的本轮结果在界面上仍可见（即便未持久化）

### 6.3 需求 B6-1 · 按 `bookId` 加载内容（解 C5）

#### 6.3.1 问题陈述

用户在书架上选了「HSK 2 Standard Course」，地址栏是 `/library/read/hsk2`，`activeBook` 也已经写成 hsk2——**打开后读到的是快乐中文第 1 课「你好」**。因为渲染内容的组件根本没看 URL，它只认识自己文件里那份常量。

这是本篇最直接的功能错误：书架、当前教材指针、URL 三者都正确，只有渲染层没接上。

#### 6.3.2 需求

| # | 要求 |
|---:|---|
| R1 | 阅读器**必须**从路由读取 `bookId`（`useParams<{ bookId: string }>()`），并据此加载对应教材的内容包 |
| R2 | 内容加载顺序：本地已下载内容包 → （联网时）后端内容接口 → 失败则错误态。**不得回落到任何硬编码课程内容** |
| R3 | `bookId` 缺失（路由未匹配到参数）→ 回落到 `activeBook.id`；`activeBook` 也无效 → 跳 `/library/select-books` |
| R4 | `bookId` 在书目中不存在 → 显示 `We couldn't find this book.` + `Choose a Book` 按钮 |
| R5 | `bookId` 存在但内容包未下载 → 显示下载引导态：封面 + 体积 + `Download` 按钮，点击走第四章 4.6 的下载流程，完成后自动进入阅读 |

### 6.4 需求 B6-2 · 内容源与后端化（解 C6 · 内容侧）

#### 6.4.1 问题陈述

全部教材内容是编译进前端 bundle 的常量。后果：改一个错别字要发一次前端版本；内容量增长直接撑大首包；内容团队（`NSK-BackEnd` 配置人员）**无法配置任何教材内容**，只能配 HSK 题库。这与工作区 `AGENTS.md` 描述的内容流转（运营在 `NSK-BackEnd` 配置 → 后端提供接口 → 推送到 C-LingoAIOS）完全脱节。

#### 6.4.2 需求

| # | 要求 |
|---:|---|
| S1 | 教材内容**从前端代码中移出**，改由内容包提供。前端 bundle 内**不保留任何整课教学内容常量** |
| S2 | 内容由运营在 `NSK-BackEnd` 配置，经后端接口分发。`[待确认]` 教材内容的后台配置能力是否已在 `NSK-BackEnd` 规划中，需与后台产品对齐；当前后台 PRD（v2.4）只覆盖 HSK 题库 |
| S3 | 内容包支持增量更新：`packageVersion` 变化时书架显示 `update-available`，用户可选择更新或继续用旧版 |
| S4 | 过渡期允许把现有 `LESSONS_DATA` **导出为一份内置内容包**（随应用出厂预装），走与远端内容包完全相同的加载路径。**过渡的底线是加载路径统一**，不得保留「组件直接 import 常量」的分支 |
| S5 | 内容缺失的降级：某课资源不完整时，该课在目录中标为不可点并显示 `Content not available`，**不显示半截内容** |

### 6.5 需求 B6-3 · 教材原声音频与 TTS 降级（解 C6 · 音频侧）

#### 6.5.1 问题陈述

点读用 `window.speechSynthesis` 合成。对中文学习产品这是硬伤：

- 合成音的**声调准确度不可控**，而声调是 HSK1 学习者最需要模仿的对象
- 不同安卓设备的中文 TTS 引擎差异极大，部分设备甚至没有中文语音包，表现为点了没声音
- 无法与教材配套的真人朗读保持一致，跟读评测失去参照基准

#### 6.5.2 需求

| # | 要求 |
|---:|---|
| A1 | 点读、跟读、逐句播放**优先使用内容包中的教材原声音频**（`sentence.audioUrl`） |
| A2 | 原声音频随内容包离线下载，**断网时点读必须可用**（G9） |
| A3 | `audioUrl` 为 `null`（内容尚未配音）时降级到 TTS，并在该句的播放按钮上显示一个小标记（如 `AI voice`），让用户知道这不是标准发音 |
| A4 | 设备无可用中文 TTS 语音时，播放按钮置为不可用并提示 `Audio not available for this sentence.`，**不得点了毫无反应** |
| A5 | 语速调节对原声音频通过 `playbackRate` 实现，档位 `[待确认] 0.75 / 1.0 / 1.25`；变速时保持音高（`preservesPitch = true`） |
| A6 | **音频独占（G5）**：切句、切模式、切课、打开目录、打开设置、离开页面、应用进入后台，**全部必须停止当前音频并递增播放代次令牌**；旧 `play()` 的 Promise 回调回来后检查令牌，不一致则立即 `pause()` 并作废，**不得重新启动播放** |
| A7 | 跟读录音期间必须先停止朗读音频，避免录进设备自身的外放声 |
| A8 | 音频加载失败（404 / 网络）时，该句播放按钮显示重试图标；连续 3 次失败后提示内容包可能损坏并引导重新下载 |

#### 6.5.3 播放代次令牌的实现约束

沿用 HSK 域 `src/hsk/exclusiveAudioPlayer.ts` 的同一机制，不另起一套：

```text
generation += 1                       // 任何「该停」的事件发生时先递增
const myGen = generation
audio.play().then(() => {
  if (myGen !== generation) {         // 回调回来时代次已变 → 这次播放已作废
    audio.pause()
    return
  }
  // 正常继续
})
```

**测试必须覆盖的竞态**：快速连续点击相邻两句（间隔 < 300 ms）、点句后立刻切模式、点句后立刻按返回键。三种情况下都不得出现两个音频同时发声或返回后仍有声音。

### 6.6 需求 B6-4 · 翻页手势（安卓平板缺失项）

#### 6.6.1 问题陈述

现状阅读器**没有左右滑动翻页**。在安卓平板上，一个占满全屏、视觉上就是一本书的界面却只能靠按钮翻页，违反用户对「书」的基本操作预期，也和产品规则第 2 条（符合平板交互习惯）冲突。

#### 6.6.2 需求

| 项 | 规范 |
|---|---|
| 手势 | 在跨页内容区水平滑动翻页。**从右往左滑 = 下一跨页**，从左往右滑 = 上一跨页（LTR 语言下） |
| RTL | 界面语言为阿拉伯语时**方向镜像**（从左往右滑 = 下一跨页），与 `01-开机向导与壳层.md` 的 RTL 规范一致 |
| 触发阈值 | 水平位移 ≥ `[待确认] 60` dp 且水平位移 > 垂直位移 × 1.5；或快速轻扫（速度 ≥ `[待确认] 0.5` dp/ms）时阈值降至 30 dp |
| 跟手 | 拖动过程中内容跟手位移，松手后按阈值决定「翻过去」或「弹回」。动画 `[待确认] 240` ms，缓动 `cubic-bezier(0.2, 0, 0, 1)` |
| 边界 | 首跨页继续右滑 / 末跨页继续左滑时，给橡皮筋阻尼（位移衰减到 1/3）并回弹；末跨页再次左扫时提示 `Last page of this lesson` 并给出 `Next lesson` 按钮 |
| 与点读互斥 | 手指按下到抬起的位移小于 `[待确认] 10` dp 视为点击（触发点读），否则视为滑动，**不触发点读** |
| 与模式互斥 | `shadow` 模式（多选句子）与 `exercise` 模式下**禁用翻页手势**，避免与选择/拖拽冲突；这两种模式仍保留翻页按钮 |
| 按钮保留 | 左右翻页按钮必须保留（手势是加速器，不是唯一入口）。热区 `figmaPx(88)` |
| 跨课 | 在一课的末跨页继续翻，**不自动跳下一课**，需用户显式点 `Next lesson`。避免误滑导致跨课 |
| 音频 | 翻页时停止当前句子音频并递增代次令牌（G5） |

### 6.7 需求 B6-5 · 模式、设置与 Focus mode

#### 6.7.1 四种模式

| 模式 | 用途 | 点句行为 | 翻页手势 |
|---|---|---|---|
| `read`（Tap to Read） | 点读 | 播放该句原声，高亮该句 | 启用 |
| `repeat`（Repeat Range） | 循环跟读 | 播放该句；可设起止句循环 | 启用 |
| `shadow`（Shadow Reading） | 影子跟读 | 选入 / 移出跟读范围（多选） | **禁用** |
| `exercise`（Practice） | 页内练习 | 不点读 | **禁用** |

**切换模式时**：停止当前音频并递增令牌；清空 `shadow` 的选择；练习中途切模式先弹确认。

#### 6.7.2 设置项

| 设置 | 取值 | 默认 | 持久化 |
|---|---|---|---|
| 语速 | `0.75` / `1.0` / `1.25` | `1.0` | `clingo.reader.settings.v1` |
| 拼音显示 | `on` / `off` | `on` | 同上 |
| 译文显示 | `on` / `off` | `[待确认] on` | 同上 |
| 句子高亮 | `on` / `off` | `on` | 同上 |
| AI assist | `on` / `off` | `off` | 同上。离线时强制 `off` 并说明原因 |

设置为**全局**（跨书生效），不按 `bookId` 分别保存。`[待确认]` 若业务方希望按书保存，需改为 map 结构。

#### 6.7.3 Focus mode

| 项 | 要求 |
|---|---|
| 进入 | 连续 `[待确认] 5` 秒无交互后自动隐藏 chrome（顶栏、模式 Tab、底栏） |
| 退出 | 点击内容区空白、任意滑动、任意按键 → 立即恢复 chrome，并重置计时 |
| 例外 | 音频播放中**不进入** Focus mode（用户正在跟读，需要看到控制条）；`exercise` 模式下**不进入** |
| 动效 | chrome 淡入淡出 `[待确认] 200` ms，不使用位移动画（避免内容跳动） |
| 提示 | 首次进入 Focus mode 时显示一次性提示 `Tap anywhere to show controls`，3 秒后消失，之后不再显示 |

#### 6.7.4 跟读录音与评分

| 项 | 要求 |
|---|---|
| 录音前 | 停止全部朗读音频；检查麦克风权限，未授权时引导授权，拒绝后显示 `Microphone access is needed for shadow reading.` |
| 评分时机 | **整段跟读结束后统一给分**，不逐句打断（产品规则 `speech-evaluation-timing`） |
| 结果 | 写入口语评分记录。现状写 `hsk-speaking-latest-score`（单值覆盖）；3.0 应并入统一存储命名空间并保留按句记录，见 `07-附录.md` E2/E3 |
| 离线 | 评分若依赖云端能力，离线时录音仍可回放，但评分显示 `Scoring needs a connection.`，**不显示假分数** |
| 田字格 | 若跟读流程内嵌写字环节，田字格严格 `aspect-ratio: 1 / 1`（G6） |

### 6.8 GWT 验收标准 · 阅读器

**GWT-B6-01｜阅读器按 `bookId` 加载对应教材（C5 回归）**
- **Given** 用户在书架选中并打开「HSK 2 Standard Course」，其内容包已下载，URL 为 `/library/read/hsk2`
- **When** 阅读器完成加载
- **Then** 显示的书名为 `HSK 2 Standard Course`，目录中列出的是该教材的课，正文内容属于 HSK2；**不出现快乐中文的课文（如「你好」）**

**GWT-B6-02｜不同 `bookId` 渲染不同内容**
- **Given** `hsk1` 与 `hc-1` 两本教材的内容包均已下载
- **When** 测试依次访问 `/library/read/hsk1` 与 `/library/read/hc-1`
- **Then** 两次的书名、目录、首跨页内容互不相同；两次页面上的课文文本集合无交集（除通用问候语外）

**GWT-B6-03｜未知 `bookId` 显示未找到页**
- **Given** 书目中不存在 `bookId` 为 `not-a-book` 的教材
- **When** 用户直接访问 `/library/read/not-a-book`
- **Then** 页面显示 `We couldn't find this book.` 与 `Choose a Book` 按钮；**不渲染任何兜底课程内容**；点击按钮进入 `/library/select-books`

**GWT-B6-04｜未下载的书显示下载引导而非内容**
- **Given** `bookId` 为 `hsk2` 的教材存在于书目但内容包未下载
- **When** 用户访问 `/library/read/hsk2`
- **Then** 显示封面 + 内容包体积 + `Download` 按钮；**不显示任何正文内容**；点 `Download` 走标准下载流程，完成后自动进入该书的阅读界面

**GWT-B6-05｜锁定教材不可通过 URL 直达内容**
- **Given** 存在一本 `accessState` 为 `locked` 的教材，DevTools Network 面板已清空
- **When** 用户直接访问该书的 `/library/read/:bookId`
- **Then** 显示锁定态与锁定原因；Network 面板无任何内容包或内容接口请求；无正文渲染

**GWT-B6-06｜阅读进度写回并在下次打开时恢复**
- **Given** 用户在 `/library/read/hsk1` 翻到第 5 跨页
- **When** 用户返回 `/Home` 后再次点 `Continue`
- **Then** 阅读器直接定位到第 5 跨页；`clingo.library.activeBook.v1` 的 `currentPage` 与该跨页的页码一致；`/Home` 的进度显示同步更新

**GWT-B6-07｜点读播放教材原声**
- **Given** 当前课的句子 `audioUrl` 指向内容包中的原声音频文件
- **When** 用户在 `read` 模式下点击该句
- **Then** 播放的是该音频文件（可通过 Network / 媒体元素来源验证）；**不调用 `window.speechSynthesis`**；句子高亮同步

**GWT-B6-08｜无原声时降级 TTS 并明示**
- **Given** 某句的 `audioUrl` 为 `null`
- **When** 用户点击该句
- **Then** 使用 TTS 朗读，且该句播放控件上显示 `AI voice` 标记；若设备无可用中文 TTS 语音，则播放控件置为不可用并提示 `Audio not available for this sentence.`，**不出现点了无反应**

**GWT-B6-09｜离线可完整点读**
- **Given** 当前教材内容包（含原声音频）已完整下载，设备随后断网
- **When** 用户打开该书并在 `read` 模式下依次点击一页内的全部句子
- **Then** 每句都能正常播放原声；不出现加载失败提示；顶栏网络指示器为 `OFFLINE READY`

**GWT-B6-10｜音频独占：快速连点相邻两句**
- **Given** 用户在 `read` 模式，页面上有句 A 与句 B
- **When** 用户点击 A 后在 300 ms 内点击 B
- **Then** 任一时刻只有一个音频在响；最终播放的是 B；A 的播放被立即停止且**不会在其 `play()` Promise 回调后重新开始**；高亮只在 B 上

**GWT-B6-11｜音频独占：离页即停**
- **Given** 用户在 `read` 模式下点句开始播放
- **When** 用户在音频播放中立即按返回键离开阅读器
- **Then** 音频在离开的同一帧停止；返回后的页面（如 `/Home`）**不存在任何残留音频**；再次进入阅读器时不自动续播

**GWT-B6-12｜音频独占：切模式即停**
- **Given** 用户在 `read` 模式下正在播放某句
- **When** 用户切换到 `shadow` 模式
- **Then** 音频立即停止；`shadow` 的选择集合为空；再切回 `read` 时不自动续播

**GWT-B6-13｜左右滑动翻页**
- **Given** 用户在 `read` 模式，当前为第 2 跨页
- **When** 用户在内容区从右往左水平滑动 80 dp 后松手
- **Then** 翻到第 3 跨页，动画跟手且在 240 ms 内完成；从左往右滑同样距离则回到第 2 跨页；页码指示与 `currentPage` 同步更新

**GWT-B6-14｜滑动不误触发点读**
- **Given** 用户在 `read` 模式，手指落点正好在一个可点读句子的热区内
- **When** 用户从该点水平滑动 80 dp 后松手
- **Then** 执行翻页；**不播放该句音频**、不出现点读高亮

**GWT-B6-15｜点击不误触发翻页**
- **Given** 用户在 `read` 模式，手指落在句子热区内
- **When** 用户按下并在 10 dp 位移内抬起
- **Then** 播放该句音频并高亮；**不翻页**

**GWT-B6-16｜边界回弹与不自动跨课**
- **Given** 用户在某课的最后一个跨页
- **When** 用户继续从右往左滑动
- **Then** 内容以衰减位移跟随并回弹；出现提示 `Last page of this lesson` 与 `Next lesson` 按钮；**不自动进入下一课**；点 `Next lesson` 才切课，切课时停止当前音频

**GWT-B6-17｜shadow 与 exercise 模式禁用翻页手势**
- **Given** 用户切到 `shadow` 模式并已选中 2 个句子
- **When** 用户在内容区水平滑动 100 dp
- **Then** 不翻页、已选中的句子保持选中；翻页按钮仍可用且点击可正常翻页

**GWT-B6-18｜Focus mode 在播放中不触发**
- **Given** 用户在 `read` 模式下播放一段时长超过 8 秒的音频且期间不做任何操作
- **When** 播放持续超过 5 秒
- **Then** chrome **不隐藏**；音频播放结束后再静置 5 秒，chrome 才淡出；点击空白立即恢复

**GWT-B6-19｜跟读评分在整段结束后统一给出**
- **Given** 用户在 `shadow` 模式选中 4 个句子并开始跟读
- **When** 用户逐句朗读完成
- **Then** 每句读完后**不弹出任何评分**、不打断流程；4 句全部完成后一次性展示整段评分与逐句分析；点击某句可展开该句的发音细节

**GWT-B6-20｜设置持久化且跨书生效**

### 7.3 需求 B7-1 · 解锁条件必须在页面层再校验（解 C7）

#### 7.3.1 问题陈述

Hub 用 `unitComplete` 做了完整的门禁 UI：锁层、Snackbar、禁用按钮。但这套判断**只存在于 Hub 这一个组件里**。目标页面本身对「用户是否有资格看到我」一无所知。

在浏览器地址栏可见的产品里（C-LingoAIOS 是 H5 壳），这等于门禁不存在。更现实的风险不是用户主动作弊，而是**分享链接、历史记录、书签、返回栈**——用户上次解锁后访问过 `…/intensive`，清除学习数据后从历史记录点回去，就绕过了。

#### 7.3.2 需求：三层防护

| 层 | 位置 | 要求 |
|---|---|---|
| **UI 层** | Hub | 未解锁项渲染为锁定态：不带 `onClick` 的容器、锁图标、解锁条件文案。**不是 `disabled` 按钮**（G7） |
| **页面层** | 每个受限页面自身 | 页面挂载时**独立**读取进度并校验解锁条件。不满足 → 渲染锁定态页面，**不渲染任何受限内容、不请求受限数据** |
| **数据层** | 内容加载函数 | 受限内容的加载函数在返回数据前再校验一次；不满足则返回 `locked` 而非内容 |

**页面层锁定态的统一规格**：

| 元素 | 内容 |
|---|---|
| 图标 | 锁 |
| 主文案 | `This is locked for now.` |
| 条件文案 | 具体条件，如 `Finish all 3 lessons in Unit 1 to unlock the Knowledge Toolbox.` |
| 进度提示 | `2 of 3 lessons completed` |
| 主按钮 | `Continue learning` → 跳到该单元下一个可学的课 |
| 次按钮 | `Back to Fun Chinese` → `/library/hub/fun-chinese` |

#### 7.3.3 各路由的解锁条件表

| 路由 | 解锁条件 | 不满足时 |
|---|---|---|
| `/library/hub/fun-chinese` | 无（Hub 本身始终可达，但要求 `activeBook.seriesId === 'happy-chinese'`；否则显示「切换到快乐中文教材」引导） | 引导态 |
| `…/lesson/:lessonId` | 第 1 课无条件；第 k 课需第 k−1 课 `completed` | 锁定态 |
| `…/lesson/:lessonId?period=N` | 该课已解锁，且 `period` ∈ 该课的课时集合 | 锁定态 / 参数无效则回落 `period=1` |
| `…/intensive` | 本单元全部课完成（`unitComplete`） | 锁定态 |
| `…/card-collection` | 本单元全部课完成（`unitComplete`） | 锁定态 |
| `…/teacher-guide` | 见 7.7（3.0 收口为锁定占位） | 锁定态 |

`[待确认]` `card-collection` 是否真的需要单元门禁。它展示的是用户**自己收藏的卡片**，用门禁挡住自己的收藏在体验上说不通。**建议**：`card-collection` 取消门禁、始终可达（无收藏时显示空态），门禁只保留在 `intensive` 与 `unit_test`。需业务方裁决；在裁决前按现状代码的口径（有门禁）实现，并把本条列入第十三章清单。

#### 7.3.4 非法 / 越界参数

| 参数 | 校验 | 不合法时 |
|---|---|---|
| `lessonId` | 整数，存在于本单元课目录 | 显示 `We couldn't find this lesson.` + 返回 Hub |
| `period` | 整数，∈ 该课的课时集合（当前为 `1 \| 2`） | 回落 `period=1`，不报错 |
| `phase` | ∈ `warmup \| learn \| cards \| practice \| complete` | 回落 `warmup` |
| `card` | 整数，∈ 该课卡片索引范围 | 回落卡片列表首项 |
| `from` | ∈ 已知来源白名单 | 忽略，返回按钮回落 Hub |

**深链跳阶段的额外约束**：`?phase=complete` 不得被用来直接触发完成写入。完成状态**只能**由真实走完 Practice 阶段写入；带 `phase=complete` 直达时渲染为「查看完成页」只读态，不调用 `markLessonCompleted`。

## 八、文化内容与解锁机制

### 8.1 域定位

产品规则对文化内容有三条硬约束：

1. **不直接暴露，通过学习解锁**
2. **两类内容**：带视频的文化 + 书籍后的文化知识
3. 文化视频考虑用 AI 生成以保持风格统一

本章把这三条落成可实现的解锁模型与页面规格，覆盖路由 `/library/hub/culture`、`/culture-content`、`/culture-video`、`/audio-reading`。

### 8.2 现状基线

| 路由 | 现状 |
|---|---|
| `/library/hub/culture`（`CultureMapPage`） | 三张卡：**AI Culture Podcast** → `/audio-reading`；**Culture Mindmap** → 无 `route`，点击只弹 Snackbar `Culture Mindmap is being prepared for this hub.`（L403-412）；**Culture Videos** → `/culture-video`。返回用 `navigate(-1)` |
| 入口可达性 | 该 Hub 的入口只在 `isHappyChineseBook(activeBook)` 为真时出现在 `/Home`。**默认 HSK1 教材下无任何入口，但 URL 可直达** |
| `/culture-content` | 在 `MainLayout` **之外**全屏渲染；三态 `selection` / `video` / `audiobook`；入口仅在 `/lesson/:id` 的 Bonus 解锁后出现，**URL 可直达，无 guard** |
| `/culture-video` | 全屏包裹 `CultureVideoStage`，内容为 mock |
| `/audio-reading` | 全屏包裹 `AudiobookPage`，内容为 mock |

### 8.3 需求 B8-1 · 文化内容的两类划分与解锁模型

#### 8.3.1 两类内容

| 类型 | 定义 | 归属 | 解锁条件 | 承载路由 |
|---|---|---|---|---|
| **课后文化（Lesson Culture）** | 与某一课的语言点绑定的文化知识，学完课才有意义 | 课 | 所属单元的完成度 ≥ 60%（与第五章 5.4 同一常量 `BONUS_UNLOCK_RATIO`） | `/culture-content` |
| **体系文化（Series Culture）** | 与整套教材配套的文化专题（视频、播客、读物），相对独立 | 教材体系 | `[待确认]` 建议：所属教材**任一单元**达到 60% 完成度即整体解锁 | `/library/hub/culture` → `/culture-video` / `/audio-reading` |

#### 8.3.2 解锁的两条硬规则

| # | 规则 |
|---:|---|
| K1 | **不直接暴露**：未解锁的文化内容，其入口**不在信息架构中显示为可用功能**。入口可以可见（让用户知道有这个东西并产生动力），但必须是锁定态 + 明确解锁条件。**不可见地存在但 URL 可达**是最差的形态，必须消除 |
| K2 | **页面层 guard**：与第七章 7.3 同一要求。`/culture-content`、`/culture-video`、`/audio-reading` 三个页面在挂载时**独立校验**解锁条件，不满足则渲染锁定态，不渲染内容、不请求内容、不播放音频 |

#### 8.3.3 `/library/hub/culture` 的入口可达性

现状：该 Hub 只在快乐中文教材下有入口，HSK 教材下无入口但 URL 可达。这是 K1 描述的最差形态。

**3.0 要求**：

| `activeBook.seriesId` | Hub 入口 | Hub 内容 |

| `culture` | `/Home` 伴学卡（单卡）`Culture` | 同上 |
| `hsk` | **无伴学卡入口** | URL 直达时显示引导态：`Culture content comes with your Fun Chinese textbook.` + `Choose a Book` 按钮。**不渲染任何文化内容** |
| `practice` | 无入口 | 同上 |

### 8.4 需求 B8-2 · Culture Mindmap 的占位收口

#### 8.4.1 问题

Culture Mindmap 是一张**做得和另外两张一样精致**的卡（含专属插图 `MindmapIllustration`、CTA `Explore Map`、渐变按钮），点下去只有一条 Snackbar。视觉上它承诺了一个完整功能，交互上它什么都没有。

#### 8.4.2 决策：收口为锁定占位，不删除

理由：它在信息架构上是有位置的（文化内容的三种形态：听 / 看 / 结构化浏览），删掉会让 Hub 变成两张卡的空旷布局。但必须**停止用完整功能的视觉语言承诺一个不存在的功能**。

| # | 要求 |
|---:|---|
| M1 | 卡片渲染为**锁定占位样式**：插图降饱和度至 `[待确认] 40%`、右上角锁角标、CTA 文案改为 `Coming soon`、按钮改为不可点的中性灰 |
| M2 | 整卡**不带 `onClick`**（G7），点击无任何反应，**不再弹 Snackbar**。转瞬即逝的提示是在用户已经点错之后才解释，锁定态在点之前就说明了 |
| M3 | 卡片下方常驻一行说明：`Visual knowledge map is on the way.` |
| M4 | 不为该卡注册任何路由。用户无法通过 URL 到达一个不存在的 Mindmap 页 |
| M5 | 列入第十一章处置结论表 |

- **When** 用户从课程 Hub 点 Bonus Class 的 `Enter`
- **Then** 全屏进入 `/culture-content` 的 selection 态；两个入口（video / audiobook）均可用；返回按钮回到该课程 Hub

**GWT-B8-04｜Culture Mindmap 为锁定占位且不可点**

- **When** 用户点击 Culture Mindmap 卡片及其 CTA 各一次
- **Then** 无导航、无 Snackbar、无任何状态变化；卡片呈降饱和 + 锁角标样式，CTA 文案为 `Coming soon` 且不可点；卡片下方有常驻说明 `Visual knowledge map is on the way.`

**GWT-B8-05｜体系文化未解锁时视频页被拦**
- **Given** 用户的快乐中文教材中没有任何单元达到 60% 完成度
- **When** 用户直接访问 `/culture-video`
- **Then** 渲染锁定态；不加载任何视频资源；播放器不出现；提供 `Continue learning` 与 `Back to Culture` 两个按钮

**GWT-B8-06｜文化媒体独占控制**
- **Given** 用户在 `/culture-video` 播放一段视频
- **When** 用户按返回键回到 `/library/hub/culture`，随后进入 `/audio-reading` 播放一段音频
- **Then** 离开视频页的同一帧视频音轨停止；文化 Hub 上无残留声音；音频播放期间无第二个音源；快速在两页间来回切换 3 次后仍只有一个音源在响

**GWT-B8-07｜文化素材未下载时不显示黑屏播放器**
- **Given** 当前教材的内容包未包含文化视频素材（或该部分未下载）
- **When** 用户进入 `/culture-video`
- **Then** 显示下载引导或空态 `No culture videos in this book yet.`；**不出现无法播放的黑屏播放器**；无控制台报错

**GWT-B8-08｜AI 生成内容有可见标识**
- **Given** 某文化视频的素材标记为 AI 生成
- **When** 用户播放该视频
- **Then** 播放器上持续可见 `AI-generated` 角标；英文字幕默认开启且可关闭
